# Smartup Hub - правила для Claude Code

Источник требований: docs/TZ.md. При противоречии между кодом и ТЗ остановись и спроси.

## Порядок работы
- Одна веха - одна ветка и один запрос на слияние.
- Перед кодом вехи напиши план в docs/plans/M<n>.md и дождись подтверждения.
- Для каждой задачи сначала тест, потом код.
- Перед завершением шага запусти: pnpm check (типы, линтер, переводы) и pnpm test.
- Документация Next.js: читай версию из AGENTS.md проекта, а не из памяти.
- Перед использованием API сторонней библиотеки сверься с её документацией для версии из docs/versions.md.

## Нельзя без отдельного согласования
- Ослаблять или удалять политики RLS и тесты из tests/integration/isolation.
- Обращаться к базе в обход withActor.
- Брать идентификатор организации или пользователя из запроса вместо актора.
- Кешировать данные клиентов (use cache, unstable_cache).
- Добавлять внешние сервисы и зависимости с сетевым доступом.
- Отправлять в AI что-либо сверх перечня из раздела 14.3 ТЗ.
- Писать строки интерфейса в коде компонентов мимо messages/*.json.
- Коммитить секреты и файлы .env.
- Давать AI-помощнику инструменты, доступ к базе или право менять обращение в обход правил в коде.
- Показывать клиенту шаги, написанные моделью, а не взятые из опубликованного решения.
- Добавлять серверу MCP инструменты, которые что-либо показывают клиенту или меняют состояние обращения.
- Хранить в портале исходный код Smartup или давать клиентской части доступ к знаниям из кода.
- Задавать в компоненте цвет, размер или радиус числом, мимо токенов (раздел 8.11 ТЗ).
- Читать сессию или использовать актора, отличного от public, в группе маршрутов (public).
- Отдавать клиенту или посетителю текст статьи из любой таблицы, кроме kb_published.
- Давать каналу связи собственную логику ответов, сроков или прав в обход общих модулей.
- Рисовать или менять Теза и логотип. Только файлы из docs/brand/ через компонент TezMark (раздел 8.13 ТЗ).

## Всегда
- Каждая точка входа: проверка сессии, прав и данных схемой Zod.
- Каждая новая таблица предметной области: миграция с RLS и строка в тесте изоляции.
- Каждое изменение статуса и прав: запись в журнал аудита в той же транзакции.
- Внешний сервис: интерфейс, настоящая реализация и заглушка.
- Принятое решение, которого нет в ТЗ: короткая запись в docs/decisions/.
- Значения оформления берутся из docs/design/smartup-tokens.scss через слой 1 tokens.css.
- Тексты интерфейса и Теза: правила голоса из раздела 8.13 ТЗ. Линтер не пропускает "dala", "Smartup ERP" и длинное тире.

## Оформление
- Не использовать длинное тире (U+2014) и среднее тире (U+2013) в документах, комментариях, сообщениях коммитов и текстах интерфейса. Вместо них дефис.
- pnpm check падает, если находит эти символы в репозитории.
