## 3. Как работать (обязательно)

Правила проекта: `CLAUDE.md` (совпадает с разделом 16.1 ТЗ, менять только вместе с ТЗ). Коротко:

1. Одна веха: одна ветка и один запрос на слияние.
2. Перед кодом вехи план в `docs/plans/M<n>.md` по образцу `docs/plans/M4b.md`, затем подтверждение владельца. Без подтверждения код не пишется.
3. Для каждой задачи сначала тест, который падает, потом код.
4. Перед каждым коммитом: `pnpm check`, `pnpm test`, `pnpm test:integration`. Перед слиянием ещё `pnpm build` и `pnpm test:e2e --trace off`.
5. В конце вехи: независимая проверка всей ветки свежим проверяющим, исправление важных замечаний с тестами, отчёт `docs/plans/M<n>-report.md`, решение в `docs/decisions/`, строки состояния в `README.md` и `docs/plans/README.md`.
6. Длинное и среднее тире (U+2014, U+2013) запрещены везде, `pnpm check` их ловит. Тексты интерфейса только в `messages/ru.json`, `uz.json`, `en.json`.
7. Секреты и `.env` не коммитятся.

С Claude Code: открыть репозиторий, `CLAUDE.md` подхватится сам. Первое сообщение, например: "Прочитай docs/HANDOFF.md и docs/plans/README.md. Напиши план вехи M5 в docs/plans/M5.md и дождись моего подтверждения".

## 4. Окружение на новом компьютере

Внешние ключи для разработки не нужны: портал работает на заглушках. Полное описание: `README.md`, разделы "Что нужно", "Запуск одной командой" и "Команды".

- Node.js 26 (точная версия в `.node-version`), pnpm 12, Docker с Compose (на Windows и Mac: Docker Desktop).
- Запуск:

```bash
pnpm install
pnpm dev:up        # создаёт .env, поднимает базу, роли, миграции, приложение и фоновый процесс
pnpm dev:oidc      # в соседнем окне: ложные серверы Smartup для входа клиента
pnpm dev:telegram  # по желанию: ложный бот Telegram
pnpm hub staff:create --email you@smartup.example --name "Имя" --role admin   # первый администратор
```

- Кабинет клиента: `http://localhost:3000/ru`, вход "Войти через Smartup", на форме ложного сервера любой пользователь. Рабочее место: `http://localhost:3000/ru/agent`, пароль по ссылке из команды выше и второй фактор в приложении-аутентификаторе.
- Вместо настоящих сервисов: письма печатаются в окне приложения, файлы лежат в папке на диске, антивирус заглушкой (строка EICAR считается вирусом), Telegram ложный.
- Письмо "от клиента" на адрес поддержки локально само не придёт: нужен Resend или ручная имитация вебхука (так делают тесты, `tests/e2e/helpers/inbound.ts`).
- Тесты с базой и браузерные тесты поднимают PostgreSQL в Docker. Если Docker Hub отвечает 429, задать `PG_IMAGE=mirror.gcr.io/pgvector/pgvector:pg18` (раздел README "Если Docker Hub недоступен"). В контейнерах без Ryuk: `TESTCONTAINERS_RYUK_DISABLED=true`.
- Браузерные тесты: сначала `pnpm build`, затем `pnpm test:e2e --trace off`.
