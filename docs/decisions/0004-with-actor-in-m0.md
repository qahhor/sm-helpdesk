# 0004. withActor появляется в вехе M0

Дата: 20.11.2026. Веха: M0. Статус: принято.

## Контекст

По ТЗ функция `withActor` (раздел 11.1) строится в вехе M1 вместе с аутентификацией. Но уже в M0 есть две таблицы с политиками RLS: справочник модулей `hdr_product_modules` и настройки `hdc_settings`. Проверить политику без актора нельзя.

## Решение

`src/db/with-actor.ts` создаётся в M0 по тексту раздела 11.1:

- типы `ClientActor`, `StaffActor`, `SystemActor`, `AgentActor`, `Actor` в точности как в ТЗ;
- `createWithActor(db)` возвращает функцию для заданного подключения, `withActor` работает с подключением приложения;
- значения актора записываются в переменные транзакции и исчезают с её концом. Тест проверяет, что следующая транзакция того же соединения их не видит, в том числе после ошибки.

Веха M1 добавляет построение актора из проверенной сессии (`requireClientActor`, `requireStaffActor`). До этого актора создают только тесты.

## Отличия от наброска ТЗ

| Набросок | Сделано | Почему |
|---|---|---|
| Пул создаётся при импорте модуля | Пул создаётся при первом запросе (`getAppPool`, `getAppDb`) | Сборка приложения не должна требовать адреса базы |
| Окружение разбирается при импорте | Разбор при первом чтении, проверка при запуске сервера | Та же причина. Сервер с неверным окружением завершается с кодом 1 |
| Ошибка Drizzle уходит в сервис как есть | Сервис получает исходную ошибку базы | См. решение 0003 |

## Что осталось на следующие вехи

- Журнал аудита для изменений `hdc_settings` (ТЗ 10.5: каждое изменение настройки записывается). Таблица `hdc_audit_log` появляется в M1.
- Политики для актора `agent` (AI-сотрудник). Сейчас он читает только справочник модулей.
