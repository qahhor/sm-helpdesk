# 0005. Тексты интерфейса: языки, пространства имён, проверки

Дата: 20.11.2026. Веха: M0. Статус: принято. Дополнено 21.11.2026 по проверке main (docs/plans/M1-hardening.md).

## Языки

Языки перечислены в одном файле: `src/i18n/locales.ts`. Новый язык добавляется так:

1. код в `LOCALES` и по строке в `FALLBACKS` и `FORMAT_LOCALES`;
2. файл `messages/<код>.json`;
3. `pnpm check` показывает недостающие ключи.

Русский язык эталонный: состав ключей остальных языков сверяется с ним. Если ключа в языке нет, посетитель видит текст запасного языка, а не имя ключа: узбекский берёт из русского, затем из английского, русский из английского, английский из русского.

Название языка в переключателе берётся из его же файла (ключ `common.language.self`).

## Выбор языка

Порядок (FR-I18N-06): выбор пользователя, язык в Smartup, язык браузера, русский. В вехе M0 выбор пользователя хранит кука `hub_locale` на год, язык Smartup появится вместе со входом в M1.

Язык всегда стоит первым в адресе: `/ru/...`. Адрес без языка перенаправляется на язык посетителя с сохранением пути. Неподдерживаемый язык в адресе (`/de/tickets`) заменяется языком посетителя. Короткое имя раздела (`/kb`) за язык не принимается: первый отрезок считается языком, только если это известный код языка.

Библиотека next-intl отвечает за сообщения и ссылки. Определение языка и кука библиотеки выключены: язык выбирает `resolveLocale`, одна функция для всех точек входа.

## Пространства имён

| Пространство | Что в нём |
|---|---|
| `common` | Общие подписи, язык, тема, состояния |
| `client` | Кабинет клиента |
| `agent` | Рабочее место сотрудника |
| `auth` | Вход клиента и сотрудника, ссылки из писем, выбор организации, шаг первого входа (M1) |
| `mail` | Тексты писем: тема и текст с параметрами (M1, решение 0016) |
| `bot` | Сообщения клиентского бота Telegram (M1, решение 0018) |
| `dev` | Витрина компонентов для разработчиков, `/{язык}/dev/ui` (дополнение 21.11.2026, проверка main, Q14) |

Для клиента и сотрудника разные правила слов, поэтому тексты разделены. Клиент читает не только кабинет: страницы входа, письма и сообщения бота подчиняются тем же правилам слов, что и кабинет (дополнение 21.11.2026, проверка main, Q14).

## Проверка слов

Файл `scripts/checks/messages.mjs`, входит в `pnpm check`. Слова ищутся с начала слова, без учёта регистра.

| Где | Что запрещено |
|---|---|
| Все языки, все пространства | "Smartup ERP", длинное и среднее тире |
| Русский, все пространства | "тикет", "заявк", "кейс", "инцидент", "фича" в любом падеже, "гарантированн"; слова целиком: FAQ, L1, L2, "точно" |
| Узбекский, все пространства | "dala" и "дала" в любой форме |
| `common`, `client`, `auth`, `mail`, `bot`, русский | SLA, "эскалац", "очеред" |
| `common`, `client`, `auth`, `mail`, `bot`, английский | SLA, ticket, escalat, queue |
| `common`, `client`, `auth`, `mail`, `bot`, узбекский | SLA, tiket, eskalatsiya |

Слова "запрос", "документ", "страница" проверка не ловит: "Запрос на обслуживание" это название типа обращения (FR-TK-01).

Слово "точно" запрещено только целиком: "точность расчёта" проходит.

## Проверка строк

- Полнота: в каждом языке те же ключи, что в русском. Пустая строка считается пропуском.
- ICU: строка разбирается, подстановки те же, что в русской строке.

## Вычитка

Узбекские и английские тексты вехи M0 написаны как черновик и ждут вычитки человеком. Состояние вычитки ведётся в `docs/i18n-review.md`. Словарь терминов: `glossary.csv`, тоже черновик до сверки с доской 4.02 пакета бренда.
