# 0011. GitHub Actions выключен до готовности проекта

Дата: 20.11.2026. Веха: M0. Статус: отменено решением владельца продукта от 24.11.2026 (решение 0041, пункт 6): проверки включены.

## Решение

Автоматические проверки в GitHub Actions не запускаются, пока проект не готов. Включить их решает владелец продукта.

## Как сделано

- Файл настройки перенесён из `.github/workflows/ci.yml` в `.github/workflows-disabled/ci.yml`. GitHub запускает только файлы из `.github/workflows`, поэтому ни отправка в ветку, ни запрос на слияние ничего не запускают.
- Настройка остаётся рабочей: до выключения все пять задач прошли на коммите `89251dd`. Тест `tests/unit/ci-workflow.test.ts` по-прежнему проверяет её состав и следит, чтобы папка `.github/workflows` оставалась пустой.
- `.github/dependabot.yml` не тронут: Dependabot читает настройку только из основной ветки и начнёт работать после слияния в неё.

## Чем заменены проверки

Те же проверки запускаются вручную перед каждым коммитом и в конце каждой вехи:

```bash
pnpm check && pnpm test && pnpm test:integration
pnpm build && pnpm test:e2e && pnpm budget && pnpm lighthouse
```

Результаты с числами записываются в отчёт вехи.

## Как включить

1. Перенести файл обратно: `git mv .github/workflows-disabled/ci.yml .github/workflows/ci.yml`.
2. В `tests/unit/ci-workflow.test.ts` поправить путь и убрать тест о пустой папке.
3. Убрать первые строки файла с пометкой "ВЫКЛЮЧЕНО".

## Что это стоит

Пока проверки не запускаются сами, ошибку, пропущенную при ручном прогоне, никто не поймает до включения. Образ контейнера и поиск секретов проверяются только вручную.
