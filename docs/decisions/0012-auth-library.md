# 0012. Библиотека входа Better Auth: как она подключена

Дата: 20.11.2026. Веха: M1. Статус: принято.

ТЗ (раздел 11.2) задаёт библиотеку Better Auth и даёт набросок настроек с пометкой "имена опций сверить с установленной версией". Версию 1.7.22 проверили запуском на Node.js 26.13.1 и PostgreSQL 18. Ниже то, что по итогам проверки сделано иначе, чем в наброске, и почему.

## Версии

| Пакет | Версия | Зачем |
|---|---|---|
| `better-auth` | 1.7.22 | Вход по паролю, второй фактор, вход по ссылке, сессии |
| `@better-auth/sso` | 1.7.22 | Вход через сервер OIDC (серверы Smartup) |
| `kysely` | 0.29.9 | Нужен как прямая зависимость: из него берётся подключение к PostgreSQL для библиотеки |
| `uqr` | 0.1.3 | Рисунок QR для подключения второго фактора, строится на сервере |
| `oauth2-mock-server` | 9.3.0 | Ложный сервер OIDC для разработки и тестов |
| `rolldown` | 1.2.19 | Сборка команды консоли `hub` в один файл. Версия уже была в lock-файле как зависимость Vitest |

Сценариев установки нет ни у одного из пакетов. Аудит зависимостей чистый.

## Решения

1. **Подключение к базе.** Встроенный адаптер библиотеки (Kysely) с параметром `schemaName: 'auth'`, а не адаптер Drizzle из наброска. Этот путь проверен запуском целиком, включая транзакции, без которых не работает личность "сервер и идентификатор пользователя". Второго описания тех же таблиц для адаптера не нужно. Свои запросы к таблицам `auth` модуль `hdu` пишет через Drizzle.
2. **Идентификаторы** типа `uuid`, значение задаёт база (`uuidv7()`), как у остальных таблиц портала. Библиотека при вставке идентификатор не передаёт.
3. **Один открытый адрес.** Библиотека открывает 55 адресов под `/api/auth`. Порталу снаружи нужен один: возврат с сервера Smartup `/api/auth/sso/callback/{код сервера}`. Обработчик маршрута пропускает только его, остальное отвечает 404. Вход по паролю, код второго фактора, ссылки и сессии вызываются серверными действиями как функции. Так у портала нет открытой регистрации, смены адреса, SAML и других точек, которыми он не пользуется.
4. **Серверы Smartup из реестра портала.** Библиотека умеет хранить серверы в своей таблице, но секрет клиента OAuth кладёт туда открытым текстом и шифровать не умеет. Поэтому серверы передаются ей настройкой (`defaultSSO`) из таблицы `hdu_servers`, где секрет лежит зашифрованным ключом `ENCRYPTION_KEY`. Таблица библиотеки `ssoProvider` остаётся пустой. Когда реестр меняется, экземпляр библиотеки создаётся заново.
5. **Вход без email.** Библиотека требует поле email от сервера OIDC, а Smartup его чаще не передаёт. Обход: поле email сопоставлено с `sub`, а пользователя создаёт функция портала со служебным адресом (решение 0013).
6. **Свой способ входа.** Сессию по одноразовой ссылке самого портала (приглашение, ссылка из бота Telegram) выдаёт собственная закрытая точка входа библиотеки `/sign-in/trusted`. Вход по ссылке библиотеки для этого не годится: он ищет человека по email, а у неподтверждённого адреса удаляет все способы входа.
7. **Ограничение частоты библиотеки выключено.** Оно не действует на вызовы функций, а портал вызывает библиотеку именно так. Считает портал, счётчики в таблице `hdc_rate_limits` (раздел 14.5 ТЗ).
8. **Кеш сессии в куке выключен.** Отзыв сессии и блокировка сотрудника действуют на следующем запросе.
9. **Резервные коды и "доверенное устройство" выключены.** Оба обходят обязательный второй фактор (FR-ID-09). Восстановление доступа: сброс администратором или командой `hub staff:reset`.
10. **Куки переносит портал.** Вызовы библиотеки возвращают строки `Set-Cookie`, портал сам записывает их в ответ. Плагин библиотеки для Next.js не используется: внутри Next.js 16 он не проверялся.

## Что нужно помнить при обновлении библиотеки

- При первом вызове библиотека сверяет таблицы с ожидаемыми и бросает ошибку на каждом вызове, если не хватает таблицы или колонки. Тест `auth-instance` проверяет это заранее: миграции портала должны совпадать с тем, что ждёт установленная версия.
- Обязательность второго фактора библиотека не обеспечивает: это делают перехватчики портала и проверка при входе в рабочее место.
- Вход по ссылке пользователя с неподтверждённым адресом удаляет его способы входа. Портал отправляет ссылку только на подтверждённый адрес.
- Адрес каждого сервера OIDC должен входить в список доверенных адресов библиотеки.

Полный перечень проверенных свойств записан в плане вехи: `docs/plans/M1.md`, раздел "Проверенные свойства Better Auth 1.7.22".
