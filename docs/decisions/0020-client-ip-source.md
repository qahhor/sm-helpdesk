# 0020. Источник адреса посетителя

Дата: 20.11.2026. Веха: M1 (итоговая проверка). Статус: принято исполнителем, подтверждается владельцем вместе с отчётом вехи.

Адрес посетителя нужен счётчикам частоты (вход через Smartup, ссылки для входа, поиск сервера) и журналу аудита. До итоговой проверки портал брал первое значение заголовка `x-forwarded-for`. При развёртывании по разделу 13.4 ТЗ (Cloudflare, затем Caddy, затем портал) это даёт одно из двух:

- Caddy не доверяет Cloudflare: в заголовке адрес узла Cloudflare. Все посетители за одним узлом делят счётчики, и в утренний час вход через Smartup отказывает людям, не связанным друг с другом.
- Caddy доверяет Cloudflare: первым идёт значение, которое прислал сам посетитель. Счётчики обходятся подстановкой адреса, в журнал попадает выдуманный адрес.

Решение:

- Переменная `CLIENT_IP_HEADER` выбирает заголовок: `cf-connecting-ip` (за Cloudflare), `x-real-ip` (Caddy с `trusted_proxies` и `header_up X-Real-IP {client_ip}`) или `x-forwarded-for`.
- В production на настоящем адресе переменная обязательна: портал не запустится с непродуманным источником. На localhost она не нужна (`x-forwarded-for`, так работают тесты).
- Тот же источник у библиотеки входа (`ipAddressHeaders`) и у проверки "не робот" (`remoteip`).
- `cf-connecting-ip` честен, только если до портала доходят лишь запросы через Cloudflare: сетевой экран сервера пропускает на 443 только адреса Cloudflare (раздел 13.4).
