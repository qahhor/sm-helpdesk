# 0022. Правило ошибок

Дата: 21.11.2026. Основание: проверка `main`, пункт Q5 плана `docs/plans/M1-hardening.md`. Статус: принято исполнителем, подтверждается владельцем вместе с отчётом доработки.

До проверки в модулях было три способа сообщить об отказе: исключение с кодом, объект `{ ok: false, code }` и ответ HTTP с кодом. Правило, когда какой, нигде не было записано, и отказ "последний администратор" приходил кодом `forbidden`, то есть страница показывала человеку не ту причину.

Решение:

1. Ожидаемый отказ (нет прав, не найдено, неверный ввод, предел частоты, бизнес-правило) это код из списка в `error.ts` модуля: `HduError`, `HdcError`. Текста в коде нет, текст на языке человека берёт страница из `messages/*.json`.
2. Одна причина, один код. Нельзя подменять причину общим кодом: `forbidden` значит "у вас нет права на это действие", а не "так нельзя по правилу". Для правила свой код (`last_admin`).
3. Функция слоя `api` по умолчанию бросает исключение модуля. Объект `{ ok: false, code }` возвращают только шаги входа и ссылок (`signInStaff`, `verifyStaffCode`, `requestLoginLink`, `confirmEmail`, принятие приглашения): их результат и есть следующий экран, и отказ там обычный исход, а не сбой.
4. Обработчик маршрута (`route.ts`) отвечает `problemResponse(статус, код)` из `hdc/util.ts`: тело `application/problem+json` с кодом, без подробностей.
5. Серверное действие страницы ловит только исключения своего модуля и переводит код в адрес страницы (`?error=код`). Список кодов, у которых есть текст, лежит рядом со страницей (например, `agent/settings/staff/errors.ts`), неизвестный код показывается как `invalid_input`.
6. Неожиданная ошибка (база недоступна, ошибка программы) не ловится: Next.js показывает страницу ошибки, в журнал процесса попадает имя ошибки без личных данных.
