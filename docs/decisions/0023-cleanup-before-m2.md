# 0023. Очистка служебных таблиц до фоновых задач

Дата: 21.11.2026. Основание: проверка `main`, пункт Q8 плана `docs/plans/M1-hardening.md`. Статус: принято, подтверждено владельцем 21.11.2026.

Ночная задача очистки (раздел 14.6 ТЗ, решение 78) появится вместе с фоновым процессом в M2. До этого служебные таблицы только растут: каждый запрос ссылки, каждое начало входа и каждое событие Telegram оставляют строку.

Решение:

- Команда `node hub.mjs maintenance:cleanup` удаляет то, что уже ничего не значит: счётчики частоты старше самого длинного окна с запасом в сутки, номера событий Telegram старше двух суток (Telegram повторяет событие не дольше суток), сессии и одноразовые значения библиотеки входа, срок которых вышел больше суток назад. Печатает, сколько строк удалено. Повторный запуск безопасен.
- До M2 команду запускает расписание сервера раз в сутки (памятка `docs/runbooks/staging-after-m1.md`). В M2 тот же код вызывает ночная задача.
- Строки портала с хешами ссылок (`hdu_email_tokens`, `hdu_link_codes`, `hdu_login_codes`) команда не удаляет: роли `hub_auth` удалять строки идентичности запрещено (раздел 10.3, набор изоляции), а ослаблять это правило без согласования нельзя (CLAUDE.md). Их рост ограничен пределами частоты (не больше пяти в час на человека), строка занимает около 200 байт. Узкое право удаления просроченных строк для ночной задачи предлагается владельцу в плане M2.
- Журнал аудита не чистится: он хранится 3 года (решение 78), удаление по сроку тоже в M2.

## Дополнение M2 (21.11.2026)

Решение 13 плана M2 подтверждено владельцем 21.11.2026.

- Очистку выполняет ночная задача `maintenance.cleanup` фонового процесса в 03:00 по Ташкенту (решение 0028). Команда `hub maintenance:cleanup` остаётся для ручного запуска и печатает те же числа.
- Роль `hub_auth` получила право удалять строки `hdu_email_tokens`, `hdu_link_codes` и `hdu_login_codes` только от актора `system` и только когда срок строки вышел больше суток назад (миграция `0015_cleanup_rights.sql`). Политики ограничивающие (`AS RESTRICTIVE`): прежние политики системы `FOR ALL` сами по себе удаления не дают, клиент и сотрудник не удаляют ничего. Набор изоляции получил строки `auth: IUD` и прямую проверку `identity-direct.test.ts`.
- Журнал аудита по-прежнему не чистится: удаление по сроку 3 года появится, когда первым записям будет 3 года.
