# 0024. Dependabot, пока CI выключен

Дата: 21.11.2026. Основание: проверка `main`, пункт C7 плана `docs/plans/M1-hardening.md`. Статус: принято, подтверждено владельцем 21.11.2026.

После слияния вех M0 и M1 в `main` файл `.github/dependabot.yml` начал действовать (решение 0011 это предвидело). Запросы на слияние от Dependabot будут приходить, а проверки GitHub Actions на них не запустятся: CI выключен до решения владельца. Зелёной отметки у таких запросов не будет, и это не значит, что обновление безопасно.

Решение:

- Dependabot остаётся включённым: исправления безопасности нужно видеть сразу.
- Запрос Dependabot сливается только после ручного прогона из решения 0011 на его ветке: `pnpm check`, `pnpm test`, `pnpm test:integration`, `pnpm build`, `pnpm test:e2e`. Итог прогона пишется в запрос комментарием.
- Обновление базового образа Node.js приходит как новый digest в `Dockerfile`, обновления Caddy и PostgreSQL как новый digest в `compose.prod.yaml` (добавлено отслеживание `docker-compose`). Перед слиянием образ собирается и запускается локально.
- Действия GitHub в `.github/workflows-disabled/ci.yml` Dependabot не видит: он смотрит только `.github/workflows`. При включении CI закреплённые хеши действий обновляются вручную.
