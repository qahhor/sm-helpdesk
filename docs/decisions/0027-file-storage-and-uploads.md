# 0027. Хранилище вложений и загрузка файлов

Дата: 21.11.2026. Веха: M2 (`docs/plans/M2.md`, таблица решений, пункты 7-10). Статус: принято, план и подключение Cloudflare R2 подтверждены владельцем 21.11.2026.

1. Хранилище спрятано за интерфейсом `Storage` (`src/modules/hdc/storage/`): настоящая реализация Cloudflare R2, локальная заглушка и хранилище в памяти для тестов (CLAUDE.md, раздел 11.11 ТЗ).
2. R2 подписывается библиотекой `aws4fetch` 1.0.20 по SigV4 (регион `auto`, служба `s3`, адреса вида `{R2_ENDPOINT}/{R2_BUCKET}/{ключ}`). Ссылка на загрузку методом PUT живёт 300 секунд и подписывает `Content-Type` и `Content-Length`: другой тип или размер R2 не примет. Ссылка на скачивание подписывает `response-content-disposition`. Подпись сверена в тесте с независимым расчётом по алгоритму SigV4.
3. Браузер кладёт файл в R2 напрямую, портал файлы через себя не пропускает. Бакету нужна настройка CORS: метод PUT, заголовок `Content-Type`, источник равен адресу портала. Адрес `R2_ENDPOINT` попадает в `connect-src` и `img-src` политики CSP только при `FILE_STORAGE=r2`.
4. Строка вложения создаётся при запросе ссылки, до обращения: без `ticket_id`, со статусом `pending`, видна только загрузившему. Ключи хранилища: `quarantine/{attachment_id}` до проверки и `files/{org_id}/{attachment_id}` после чистой проверки.
5. Тип файла определяется по расширению из списка FR-TK-13. Заявленный браузером тип должен совпасть с ним; пустой тип, `application/octet-stream` и известные варианты тех же файлов (`application/vnd.ms-excel` для `.csv`, `text/xml` для `.xml`, `application/x-zip-compressed` для `.zip` и другие из `MIME_ALIASES`) принимаются, но в строку и подпись идёт тип из списка. SVG и HTML не принимаются никогда. Предел 25 МБ, видео MP4 до 50 МБ. Ссылок на загрузку не больше 30 в час на пользователя.
6. После загрузки браузер вызывает "загрузка завершена". Нет файла или размер не совпал с заявленным: файл удаляется, загрузка получает `rejected`. Состояние проверки клиент менять не может (триггер `t_hdt_attachments_client_guard`), поэтому строку меняет фоновая роль (`system`, задача `uploads.complete`), и только свою загрузку этого человека в `pending`. Размер совпал: ставится задача `attachment.scan`. Повторный вызов безопасен.
7. Отклонённую и заражённую загрузку нельзя прикрепить к обращению или ответу.
8. Обработчики `/api/uploads/presign` и `/api/uploads/complete` принимают только JSON со страницы портала (`Origin` равен `HUB_URL`, `Sec-Fetch-Site` не чужой) от вошедшего клиента с организацией, тело до 4 КБ, ошибки в виде `application/problem+json` с кодом.
9. Локальная заглушка (`FILE_STORAGE=local`, каталог `FILE_STORAGE_DIR`, по умолчанию `.storage/`) работает только с адресом портала на localhost: ссылки подписаны HMAC ключом, выведенным из `BETTER_AUTH_SECRET`, и ведут на обработчик `/api/uploads/local`, который сверяет тип и размер, как R2. На настоящем адресе в production портал без `FILE_STORAGE=r2` и четырёх переменных `R2_*` не запускается.
10. Смена состояния проверки вложения в журнал аудита не пишется: это не статус обращения и не права. Заражённые файлы журнал получит вместе с проверкой (задача 6).
