# 0032. Сроки SLA и рабочий календарь

Дата: 21.11.2026. Веха: M3 (`docs/plans/M3.md`, задачи 1-3 и 13). Статус: принято, план подтверждён владельцем 21.11.2026.

1. Расчёт сроков: чистые функции `addWorkingMinutes`, `addWorkingDays`, `workingMinutesBetween` в `src/modules/hdt/sla.ts` (раздел 11.7). Местное время считается через `Intl` в часовом поясе календаря, результат не зависит от часового пояса процесса. Праздник нерабочий целиком.
2. Срок в рабочих днях: от первого рабочего момента не раньше создания (создано вне графика: с начала следующего рабочего интервала), то же время суток через N рабочих дней. Если это время вне графика найденного дня, до его начала или после конца, срок переносится на конец рабочего дня: раздел 7.4 говорит "сдвигается к концу рабочего дня" без исключений.
3. Значения по умолчанию (раздел 7.4) заданы в коде, `src/modules/hdr/pref.ts`. Строка `hdr_sla_policies` или `hdr_business_calendars` появляется, когда администратор меняет значение, и действует вместо значения по умолчанию. Так у значений по умолчанию один источник, а пустая база не ломает расчёт. Удалять строки не может никто из ролей приложения.
4. Менять сроки, график и праздники может только администратор: роль проверяет модуль, база повторяет проверку политикой. Каждое изменение пишется в журнал аудита (`sla.policy_changed`, `sla.calendar_changed`, `sla.holidays_changed`).
5. Новые значения действуют на новые расчёты. Сроки открытого обращения меняются только его следующим событием (решение 7 плана M3): одно сохранение настроек не сдвигает молча обещанные клиентам сроки. Экран настроек это говорит.
6. Праздники вводятся по годам. В декабре экран настроек показывает, что праздники следующего года не заполнены (FR-SLA-12); уведомление администратору отправит M4.
