# 0043. Предустановленные правила вместо встроенных уведомлений

Дата: 24.11.2026. План: `docs/plans/M8.md`, задача 10, решения 1 и 2. Статус: принято исполнителем, владелец подтверждает при приёмке вехи.

1. **Три правила поставляет миграция 0067.** `p1_oncall` (дежурным о P1), `sla_breach_lead` (руководителю линии о нарушении срока), `csat_low_manager` (сотрудникам `care` об оценке 1 или 2; раньше такого уведомления не было). Включены, момент включения пуст, стоят первыми по порядку: правило администратора с флагом "остановить" не должно молча отменить сообщение дежурным. Порядок администратор меняет сам. Поставочный вид лежит в `src/modules/hdw/builtin.ts`; тест сверяет его с командой вставки из миграции.
2. **Уведомления остались прежними, изменился запуск.** Действия `notify_oncall_p1`, `notify_sla_breach`, `notify_csat_low` вызывают прежний код модуля обращений: те же получатели, шаблоны и однократность (`oncall_notified_on`). Обычное действие "уведомить" не использовано: у него другие шаблоны и получатели. Прямые вызовы из создания обращения, смены приоритета и задачи раз в минуту убраны. Действие предустановленного правила принимает только само это правило (`builtin_only`).
3. **Одно правило о P1 на два события.** Сообщение дежурным нужно и при создании обращения, и при поднятии приоритета. Правило хранит одно событие (`ticket_created`), второе (`priority_changed`) добавляет приложение (`extraEvents`). Поэтому событие предустановленного правила не меняется (`builtin_event`), редактор показывает его закрытым с пояснением. Цена, если неверно: четвёртое правило и перенос второго события в базу.
4. **Событие, порождённое правилом или макросом.** Правила администратора на него по-прежнему не срабатывают (FR-AUTO-07). Уведомления предустановленных правил срабатывают: раньше макрос или правило, поднявшие приоритет до P1, извещали дежурных, и это сохранено. На таком событии у предустановленного правила выполняются только его собственные уведомления, добавленные администратором действия не выполняются: цепочку они породить не могут.
5. **Защита от зацикливания считает срабатывания, которые что-то сделали.** Срабатывание, где менять было нечего (дежурные уже извещены, тег уже стоит), в счёт десяти за час не идёт. Иначе приоритет, который за час одиннадцать раз подняли до P1, выключил бы сообщение дежурным для всех обращений. Нарушений срока у обращения не больше двух (отметки не снимаются), оценка одна: в обычной работе предустановленное правило защита не выключает. Если администратор добавит правилу действие, которое зацикливается, защита выключит правило, как любое другое, с уведомлением администраторам.
6. **История обращения прежняя.** Срабатывание предустановленного правила, в котором выполнялись только его уведомления, записи "Правило ..." в историю обращения не добавляет: эти уведомления её не пополняли и раньше. След есть в журнале срабатываний правила и в журнале аудита (`rule.applied`). Если администратор добавил правилу другое действие, запись в истории появляется. Это отступление от FR-AUTO-09 для трёх правил; цена, если неверно: одна строка в `applyRuleTx`.
7. **Задержка сообщения о P1.** Раньше строка очереди исходящих появлялась в транзакции создания обращения. Теперь её ставит задача `automation.process`, которую будит каждое создание обращения и смена приоритета (портал, сотрудник, письмо, макрос, массовое действие). В тестах с настоящим фоновым процессом строка появляется через 1,9-2,0 секунды после фиксации: это один цикл опроса очереди задач (2 секунды). Если сигнал потерян, задача идёт по расписанию раз в минуту.
8. **Потерянное событие.** Событие, разбор которого упал пять раз, снимается с очереди (поведение задачи 2). Теперь это сигнал дежурным `automation_dropped` через `ops.watch`: проверка будится в момент снятия события, а не ждёт своих пяти минут. Сигнал один в час, в нём только число.
9. **Миграция данных и FORCE RLS.** У таблицы правил нет политик для владельца базы, поэтому миграция 0067 на время вставки снимает принуждение RLS и возвращает его в той же транзакции. `ALTER TABLE` держит исключительную блокировку до фиксации: другие подключения таблицу без принуждения не видят. Политики не менялись.
