Запас для уменьшения: расширение ссылки тянет `linkifyjs` при выключенном автораспознавании, его можно заменить своей отметкой ссылки.

## Решения пробы, которых нет в ТЗ

1. **Формат хранения.** Документ хранится как `{ version: 1, blocks }` из раздела 18.10, а `blocks` это узлы ProseMirror в формате JSON Tiptap (`type`, `attrs`, `content`, `marks`, `text`). Переход между документом и редактором это смена обёртки (`src/ui/doc/editor/convert.ts`). Цена ошибки: если этап 2 захочет свой формат блоков, понадобится преобразование при чтении, документы этапа 1 останутся читаемыми.
2. **Идентификатор у каждого узла-блока, а не только у верхнего уровня.** Абзацы внутри шагов, списков, предупреждений и ячеек таблицы тоже несут `attrs.id`: перевод по абзацам и замечания к абзацу (UX-W-06, UX-W-14) нужны и внутри шагов. Повтор идентификатора в документе отклоняет схема. Части блоков (`listItem`, строки и ячейки таблицы) идентификатора не несут.
3. **Свои устойчивые идентификаторы вместо расширения UniqueID** (оно тоже под MIT): правило "копия получает новый, оригинал сохраняет, даже если копия вставлена перед ним" здесь своё и проверяется на модели без браузера.
4. **Отметки текста:** жирный, курсив, код в строке, ссылка. В ТЗ перечня отметок нет; подчёркивание, зачёркивание, цвет и шрифт не входят, оформление задаёт портал. Внутри текста допускается перенос строки (`hardBreak`): Word и Google Docs дают его в абзацах.
5. **Чего нет в списке блоков этапа 1 и не добавлено:** блок кода (`codeBlock` есть в списке этапа 2, в плане M5 для этапа 1 его нет; код ошибки пишется отметкой "код"). Заголовки только второго и третьего уровня: первый это заголовок решения.
6. **Шаг** это блок верхнего уровня `step` с содержимым "абзац, затем абзацы и изображения"; соседние шаги нумеруются по порядку, номер не хранится. Нумерованный список Word становится `orderedList`, а не шагами: автор превращает его в шаги сам, если это шаги.
7. **Адрес изображения** в схеме только внутренний путь портала. Задача 2 заменит его ссылкой на файл `hdk_article_files` (решение 16).
8. **Вставка из Word** чистится до разбора ProseMirror (`word-paste.ts`, только для HTML с приметами Word): списки `MsoListParagraph`, заголовки, пустые абзацы, служебные элементы, рисунки с адресами вне портала. Остальное отсекает закрытая схема. Google Docs отдельно не проверялся (UX-W-11 упоминает его, это задача 3).
9. **Стили ProseMirror** подключены файлом `editor.css`, встроенный блок стилей Tiptap выключен (`injectCSS: false`): политика CSP пропускает стили только с одноразовым кодом. Таблица рисуется без `colgroup` и атрибутов `style`. Проверено браузерным тестом: с включённым `injectCSS` тест "1. шаг с изображением" падает на нарушении CSP.
10. **Страница пробы под `(dev)`, а не под `/agent`:** так она закрыта тем же флагом, что витрина, и не требует входа в браузерных тестах. Оболочка та же, что у рабочего места.

## Что не проверено

- Вставка из настоящего буфера Word на Windows и macOS: проверены образцы, написанные вручную по разметке Word. Первые настоящие вставки сотрудников стоит сверить в задаче 3.
- Перетаскивание на сенсорном экране: перетаскивание ProseMirror работает на событиях HTML5 drag and drop, на планшете их нет. Замена с клавиатуры и кнопками есть.
- Firefox и Safari: браузерные тесты портала идут только в Chromium.
