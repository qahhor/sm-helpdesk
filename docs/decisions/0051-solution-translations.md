## Решения, которых нет в ТЗ

1. **Перевод держится на идентификаторах блоков.** Черновик перевода это копия опубликованного оригинала с теми же идентификаторами, где заменён только текст. Модель получает куски текста (`<блок>.<номер узла>` и заголовок) внутри `<solution>` и возвращает их по идентификаторам; адреса ссылок, изображения, разметку, порядок и число блоков переносит код. Модель не видит адресов ссылок и не может их изменить или добавить ссылку отметкой. Ответ без хотя бы одного куска не принимается (`failed`, сотрудник переводит сам или повторяет).
2. **Переводится только опубликованный оригинал**, и перевод публикуется только при опубликованном оригинале действующего решения (`no_original`): перевод с черновика сверять не с чем. После возврата из архива переводы публикуются заново.
3. **Сверка перед публикацией (поправка 101):** те же адреса ссылок (отметки и адреса в тексте), тот же набор чисел (по цифрам: "1 250 000" и "1,250,000" совпадают), столько же фрагментов в кавычках и столько же шагов. Текст в кавычках сравнивается числом, а не содержимым: названия экранов и кнопок на другом языке пишутся по-другому. Машинный текст без расхождений публикуется без отметки "Перевод проверен" и с пометкой для клиента (FR-SOL-06). С расхождением публикация закрыта, пока сотрудник не нажмёт "Перевод проверен"; после этого расхождения остаются видны, а решает человек. Проверка FR-SOL-04 работает для перевода так же, как для оригинала: ссылка вне списка не публикуется никогда, телефон только с подтверждением.
4. **Состояние перевода при публикации:** машинный текст `machine` (пометка клиенту), подтверждённый `reviewed`, машинный текст, сделанный со старой версии оригинала, `outdated`. Подтверждённый перевод получает версией основы действующий оригинал: сотрудник сверял его с ним. Публикация оригинала по-прежнему делает переводы `outdated` (задача 4).
5. **"По абзацам рядом с оригиналом":** слева блоки опубликованного оригинала по одному, изменившиеся с версии перевода подсвечены и подписаны; справа тот же редактор с автосохранением, что у оригинала. Строки слева и справа не выравниваются по высоте: редактор один на весь документ. Цена ошибки: на длинном решении сотрудник ищет абзац глазами; выравнивание по строкам потребует отдельного редактора на каждый блок.
6. **"Перевести с AI" заменяет текущий черновик перевода** (кнопка подписана). Задача выполняется, только если язык ждёт её (`ai_status = pending`): повтор задачи и устаревшая задача модель не вызывают. Очередь `standard`, три повтора с растущей паузой; сбой: `failed` на странице, предел: `limited`, нет ключа: `unavailable`. Страница с задачей в работе обновляется сама раз в 3 секунды до 3 минут.
7. **Модуль и видимость на экране перевода не меняются:** это свойства решения, их меняют на языке оригинала.
8. **Клиент без своего языка** видит решение по цепочке узбекский, русский, английский с пометкой "пока не переведено" (задача 4, проверено интеграционным тестом на опубликованном переводе).

## Проверки

`tests/integration/hdk-translations.test.ts`: машинный перевод с пометкой и публикация для клиента; перевод с дописанной ссылкой, с телефоном и с другим числом шагов не публикуется; изменение оригинала делает перевод устаревшим и подсвечивает блок; перевод самому; без опубликованного оригинала перевод не начинается; сбой и предел видны на странице.

## Не проверено

- Качество машинного перевода и сверка на настоящих ответах модели: настоящий API не вызывался (решение 0050).
- Перевод решения с таблицей и предупреждением на живых данных: куски текста ячеек и предупреждений собираются тем же обходом, проверено юнит-тестом только на абзацах и шагах.
