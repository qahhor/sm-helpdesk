# 0059. Виджет: загрузчик, страницы "Сообщить", "Мои обращения" и страница для приложения

Дата: 25.11.2026. Веха: M6, задачи 4-7. План: `docs/plans/M6.md` (решения 1-17 подтверждены владельцем 25.11.2026). Статус: принято исполнителем. Здесь только то, чего нет ни в ТЗ, ни в решениях плана.

## Загрузчик (задача 4)

- Интерфейс: `SmartupHub.init({ hubUrl, embedKey, locale, theme, button, getContextToken, getHints, onTicketCreated })`, `open({ mode: 'report' | 'tickets' })`, `reportError({ code, message })`. `theme` строка или функция (UX-S-09), `button: false` убирает плавающую кнопку, если у Smartup Web есть пункт "Помощь". `onTicketCreated` получает только номер.
- Неверный `hubUrl` (не https, кроме `localhost` и `127.0.0.1`) или `embedKey` (не 32 шестнадцатеричных знака): виджет не включается, в консоль одна строка.
- Адрес `iframe`: `{портал}/{язык}/embed/{report|tickets}?key=<embed_key>&origin=<адрес хозяина>`. Параметр `origin` нужен браузерам без `location.ancestorOrigins` (Firefox). Если браузер назвал родителя сам, параметр его не подменяет: при расхождении страница не отвечает никому. У `iframe` `referrerPolicy = no-referrer`: путь страницы Smartup Web не попадает в журнал портала.
- Стили: закрытый Shadow DOM и `adoptedStyleSheets`. Элемент `style` создаётся только в браузере без таблиц стилей CSSOM. Атрибут `style` не ставится нигде, поэтому политике CSP Smartup Web не нужен `unsafe-inline`. Нужны только `script-src` и `frame-src` с адресом портала (раздел 17).
- Цвета, шрифт, скругления и высота кнопки подставляются сборкой из `src/ui/tokens.css`, ширина панели 400 px из ТЗ, панель на весь экран уже `--breakpoint-tablet`.
- Сборка без сжатия имён: результат около 4,5 КБ в сжатом виде при пределе 15 КБ. Комментарии исходника в файл не попадают.
- Режим B по ошибке `getContextToken` включается только при первом токене (`ready`). Ошибка продления (`need-token`) режим B не открывает: страница виджета показывает своё состояние, иначе посреди заполнения формы открылась бы новая вкладка.
- Формат адреса режима B: `{портал}/{язык}/tickets/new#widget=1&hints=<JSON подсказок>`. Страницу, которая его разбирает, строит задача 8.
- Уведомление `reportError` скрывается само через 20 секунд или по "Скрыть". Текст ошибки в нём не длиннее 200 знаков и только текстом.

## Проверка протокола

- Пакета jsdom в проекте нет, а новые пакеты без согласования не ставятся. Модульные тесты протокола идут в Node: собранный файл загрузчика выполняется в `node:vm` с простыми окном, документом и элементами (`tests/unit/widget-loader.test.ts`), сторона страницы проверяется чистыми функциями `src/ui/widget/protocol.ts` (`tests/unit/widget-protocol.test.ts`). Настоящий браузер: браузерные тесты задачи 5.
- Сторона страницы проверяет сообщения схемой, записанной проверками без библиотеки (точный набор полей каждого типа, типы, пределы). Решение 8 плана говорит "схема Zod с обеих сторон", но даже `zod/mini` в браузере занимал 17 КБ, и страница виджета выходила за бюджет 170 КБ (175 КБ). Без него 157 КБ. Сервер проверяет те же данные схемами Zod.

## Страница "Сообщить" (задача 5)

- Раскладка `(embed)/embed/layout.tsx` берёт ключ встраивания из адреса (заголовок `x-hub-path` от прокси) и отдаёт странице адреса встраивания этого сервера: только им страница отвечает. Поставщик `EmbedSession` живёт в раскладке: переходы между `/embed/report`, `/embed/tickets` и `/embed/tickets/{номер}` не пересоздают его, токен виджета не теряется. Ключ и адрес хозяина остаются в адресе при каждом переходе.
- Линтер запрещает группе `(embed)` модуль `hdu` (сессия, актор), как группе `(public)`.
- Точки входа сверх списка плана: `GET /api/embed/form` (модули для поля "Модуль" с кодом для подсказки) и `GET, POST /api/embed/solutions/{номер-slug}` (решение в панели, "Помогло" и "Не помогло"). `POST /api/suggest` принимает и исход `{ outcome: 'not_helped', sessionId }`. Все только с токеном виджета через общий `withEmbedRequest` (`hdu/api/embed.ts`): JSON до 64 КБ, без кеша, без кук.
- `uploads/presign` и `uploads/complete` с заголовком `Authorization: Bearer` строят актора по токену виджета и сессию портала не читают совсем: неверный токен даёт 401, а не вход по куке. `attachments/{id}` с токеном отдаёт ссылку хранилища в JSON (`{ url }`), а не перенаправлением: переход по ссылке с заголовком браузер сделать не может.
- Форма виджета короче формы портала, как на экране 8.3: описание, модуль, скриншот. Тип "ошибка", влияние "серьёзно мешает", видимость "организация" по умолчанию, тема из описания. Поле "Модуль" простым списком без поиска и недавних (бюджет скриптов). Модуль из подсказки выбирается, если код есть в справочнике.
- Подсказка в виджете ищет и без описания: точное совпадение по сигнатуре кода и текста ошибки из Smartup, а для поиска словами берётся текст ошибки, пока клиент не написал своё. Исход с зоной `widget`.
- Число клиентов у точного совпадения строкой "Встречалось у клиентов: N": формы множественного числа на странице без библиотеки сообщений не собрать.
- Изображения решения в панели не показываются (заглушка с подписью DocView): файл решения отдаётся по сессии портала, а тег `img` не несёт заголовок с токеном. Пересматривается, если в решениях для виджета нужны картинки.
- Отрисовка решения (DocView) грузится отдельно при открытии решения: её нет на первом экране.
- "Нет связи" (8.13): отправка без сети оставляет текст в форме и в черновике и повторяется сама по событию `online`.
- Черновик на устройстве по ключу "пользователь и организация" из полезной части токена виджета (без проверки подписи: ключ черновика, не права).
- Карточка обращения сотрудника показывает контекст из Smartup (модуль, экран, версия, платформа, код и текст ошибки) строками текста. Раньше контекст нигде не показывался, и проверить пункт 7 раздела "На что смотреть" было не на чем. В письмах контекста нет.
- Ложный выпуск принимает `persona=custom` с полями `claim_*`, как вход OAuth: браузерные тесты берут нового человека на тест, пределы частоты считаются по пользователю.
- Страницу хозяина в браузерных тестах отдаёт перехват Playwright на адресе `http://localhost:3190` (начало `base_url` ложного сервера mock, его можно встраивать всегда). Отдельный порт не занят. Chromium считает такую страницу публичной и закрыл бы загрузку с localhost проверкой Local Network Access, поэтому тесты виджета запускают его с выключенной проверкой. Демонстрационная страница на своём порту остаётся задачей 9.

## "Мои обращения" (задача 6)

- Список: обращения, которые пользователь создал в организации токена (`scope: mine`), как "Мои" на портале, по 20 с курсором. Обращения коллег остаются в портале.
- Ответ `GET /api/embed/tickets/{номер}` строится отдельной проекцией `embedTicketView` из клиентской страницы обращения `getTicket`: без событий, приоритета, влияния, видимости и наблюдателей. Ответ сотрудника подписан "Поддержка Smartup", имя есть только у людей клиента. `POST` принимает только `reply` и `confirm` (решение 13), остальное по ссылке "Открыть в портале".
- Файл в виджете открывается по ссылке хранилища на 60 секунд в новой вкладке (окно без `opener`). Непроверенный и отклонённый файл показан названием с причиной, без ссылки.

## Страница для мобильного приложения (задача 7)

- `/{язык}/m/report` в той же группе `(embed)`: те же экраны "Сообщить", "Мои обращения" и обращение, переходы сменой экрана без перезагрузки (адрес остаётся `/m/report`). Кнопки "Закрыть" нет: страницу закрывает приложение.
- Фрагмент `#ctx=` разбирается и убирается `history.replaceState` в первом эффекте страницы, до первого запроса к API. Смена фрагмента без перезагрузки (`hashchange`) тоже принимается: приложение может открыть ту же страницу с новым токеном.
- Продлевать токен некому: через 15 минут, после перезагрузки, при ответе 401 и при отклонённом токене страница просит открыть её заново из приложения. Подсказок (модуль, ошибка) у страницы приложения пока нет: ТЗ 11.9 передаёт только токен.
- `Referrer-Policy: no-referrer` у `/{язык}/m/*` и `/{язык}/embed/*` правилом `next.config.ts` (задача 4).
- Памятка разработчикам приложения: `docs/integrations/mobile-report.md`.
