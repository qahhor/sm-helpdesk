# 0061. Исправления по проверке вехи M6

Дата: 25.11.2026. План: `docs/plans/M6.md`. Решения: 0058-0060. Статус: принято исполнителем. Каждое замечание проверено по коду; для каждого сначала тест, который воспроизводит замечание и падает, затем исправление. Все замечания подтвердились.

## Важное

**I1. Миграция 0078 снимала FORCE ROW LEVEL SECURITY.** Подтвердилось: снятие согласовано владельцем только для 0067. Заполнение `context_issuer` у уже заведённых серверов теперь делается перезаписью таблицы `ALTER TABLE hdu_servers ALTER COLUMN context_issuer TYPE text USING issuer`: перезапись идёт мимо RLS (выражение USING ссылается на другую колонку, поэтому база переписывает таблицу, а не меняет только описание), принуждение не снимается ни на миг. Затем `SET NOT NULL`, как раньше. Триггеров перезапись не вызывает. Миграция не слита в main и ни в одной общей базе не применялась; файл исправлен, а не дополнен новой миграцией. Локальная база браузерных тестов `hub_e2e` (контейнер `smartup-hub-postgres-1`) уже записала 0078 со старой контрольной суммой, поэтому она удалена (`DROP DATABASE hub_e2e`), подготовка браузерных тестов создаёт её и применяет все миграции заново. База разработки `hub` 0078 не записала (в ней миграции до 0013) и не тронута. Тесты: `tests/unit/migrations-force-rls.test.ts` (ни одна миграция, кроме 0067, не содержит `NO FORCE ROW LEVEL SECURITY`), `tests/integration/m6-review-migration.test.ts` (0078 на базе с серверами: издатель заполнен, `relforcerowsecurity` истинно). Общая проверка FORCE у всех таблиц после миграций уже есть: `tests/integration/rls-base.test.ts`, первый тест.

**I2. Режим B открывал окно без нажатия.** Подтвердилось: при ошибке `getContextToken` после `ready` окно открывалось из обработчика сообщения. Теперь загрузчик закрывает панель и показывает уведомление в своём Shadow DOM: "Не получилось открыть форму здесь. Откройте её в портале." и кнопка "Открыть портал" (три языка, `widget.loader.portalTitle`, `widget.loader.openPortal`). `window.open` вызывается только из нажатия кнопки, передача подсказок через фрагмент прежняя. Без `getContextToken` вызов `open()` по-прежнему сразу открывает портал: он идёт из нажатия кнопки виджета или меню хозяина. Тесты: `tests/unit/widget-loader.test.ts` (окно только после нажатия, тексты трёх языков), `tests/e2e/widget-host.spec.ts` (тест режима B при ошибке нажимает кнопку). В закрытый Shadow DOM локаторы Playwright не заходят, поэтому этот тест открывает его через `addInitScript`; нажатие настоящее.

## Мелкое

**M1. Счётчик неудач адреса и недоступные ключи.** Подтвердилось. Неудачей адреса считаются только `malformed`, `unknown_issuer`, `algorithm`, `key_in_token` (заголовок ключа в токене, то же что подделка) и `signature` (`ADDRESS_FAULTS` в `context-token.ts`). Повтор, срок и неполные сведения (подпись верная, ошибка сервера Smartup) адрес не закрывают. Ключи сервера не загрузились: причина `keys_unavailable`, ответ 503 `context_keys_unavailable` с `Retry-After: 30` (страница виджета показывает "недоступно"), неудача адреса не считается. Неудачная загрузка JWKS запоминается на 30 секунд по адресу ключей: обмены в это время отвечают 503 без похода в сеть. Класс `ContextKeysUnavailableError` перенесён в `context-token.ts` (без сети и `server-only`), `context-keys.ts` его вывозит. Тесты: `tests/unit/hdu-context-token.test.ts`, два новых теста в `tests/integration/embed-session.test.ts`.

**M2. `hub server:widget` стирал адреса встраивания.** Подтвердилось. Поле `embedOrigins` настроек виджета необязательное: нет поля, прежний список остаётся; пустое значение флага `--embed-origins ""` очищает список явно. Форма настроек по-прежнему присылает весь список. Тест: `tests/integration/cli.test.ts` (дополнен существующий тест `server:widget`).

**M3. Выключенный виджет не отзывал токены.** Подтвердилось. `embedMembership` требует `context_key_mode IS NOT NULL`. Существующие тесты `tests/integration/embed-widget.test.ts` и `tests/integration/embed-tickets.test.ts` подписывают токены виджета для сервера набора изоляции, у которого виджет не настроен: в их `beforeEach` добавлено включение режима jwks этому серверу. Новый тест в `tests/integration/embed-session.test.ts`.

**M4. Адрес виджета с расширением файла без frame-ancestors.** Подтвердилось для `/embed`: такой адрес прокси не обрабатывает (`matcher` в `src/proxy.ts`), а статическое правило снимало с него запрет. Правило без запрета теперь только для адресов `/embed` без точки (у страниц виджета точек нет), остальные получают `frame-ancestors 'none'`. Страницы виджета по-прежнему получают один заголовок без frame-ancestors, его ставит прокси. Адреса `/m` с расширением запрет уже сохраняли; тест теперь проверяет и их. Тест: `tests/unit/csp.test.ts`.

**M5. Запрос с истёкшим токеном после сна.** Подтвердилось. Запрос страницы виджета с ответом 401 просит у хозяина новый токен контекста, ждёт обмена до 20 секунд и повторяется один раз (`requestWithRenewal` в `src/ui/widget/session.tsx`, ожидание в `EmbedSession`). Ответ 401 сервер даёт до выполнения запроса, поэтому повтор не создаёт обращение дважды. Несколько запросов с 401 сразу просят хозяина один раз. Страница `/m/report` не меняется: у неё нет хозяина, она по-прежнему предлагает открыть её заново из приложения. Тесты: `tests/unit/widget-session-renewal.test.ts`, `tests/e2e/widget-host.spec.ts` (первый ответ API 401 подставлен перехватом: часы сервера тест не двигает).

**M6. Ссылка режима B с любого сайта.** Риск принят, строка добавлена в решение 0060.

## Токен доступа вместо токена контекста

Отдельного `typ` план M6 не задаёт, поэтому `typ` не требуется: Smartup ещё не выпускает токены контекста, требование `typ` сломало бы совместимость без согласования. Признак токена контекста уже есть: обязательные поля `platform` (только web, android, ios) и `app_version`, которых у токена доступа Smartup ID нет. Код не менялся; добавлен тест, что токен доступа тем же ключом, издателем и получателем отклоняется (`tests/unit/hdu-context-token.test.ts`). Цена ошибки: если Smartup ID однажды положит в токен доступа поля `platform` и `app_version` с тем же получателем `smartup-hub`, различить их будет нечем; тогда нужен `typ`.
