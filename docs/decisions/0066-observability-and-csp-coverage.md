# 0066. Наблюдение без внешних сервисов и полнота проверки CSP

Дата: 26.11.2026. План: `docs/plans/M9-prep.md`, задачи 2 и 3, решения 2, 5 и 6 (подтверждены владельцем). Статус: принято исполнителем. Здесь только то, чего нет в плане.

## Полнота CSP (задача 2)

1. **Список обхода в файле теста, сверка в `pnpm check`.** `tests/e2e/helpers/csp-pages.ts` перечисляет каждую страницу (`page.tsx`) и каждый обработчик (`route.ts`) каталога `src/app` путём каталога с группой маршрутов. Проверка `scripts/checks/csp-pages.mjs` читает файл как текст (без импорта TypeScript) и сверяет с каталогом. Цена: строку с маршрутом нужно писать полем `route: '...'` или шаблоном с `${A}`, иначе проверка её не увидит (тест `csp-pages.test.ts` сверяет прочитанное с импортом).
2. **Браузер обходит страницы с отметкой `walk`, не все.** По одной и больше на группу маршрутов (тест требует каждую группу), в светлой и тёмной теме, плюс виджет во фрейме страницы хозяина. Заголовок проверяется у всех страниц и обработчиков. Цена: нарушение на странице без `walk` найдёт только ручная проверка или отчёт `/api/csp-report`.
3. **Страница "не найдено" идёт без темы.** Next.js отдаёт её документом `__next_error__` без корневой раскладки `[locale]/layout.tsx`, поэтому класс `dark` не ставится. Нарушения политики нет, тема на 404 светлая. Обход проверяет тему только у ответов 200. Цена: в тёмной теме страница 404 светлая; исправление (`global-not-found`) отдельной задачей.

## Наблюдение (задача 3)

4. **Отметка фонового процесса в отдельной таблице `hdc_ops_heartbeats` (миграция 0087).** План назвал только `hdc_ops_backups`. Строка одна на процесс, пишет и читает только система. Адрес `/api/ready/worker` открыт без входа и читает отметку системным актором модуля `hdc` (как чтение настроек), одна строка без параметров запроса. Цена: ещё одна таблица в наборе изоляции.
5. **Отметка раз в минуту идёт задачей `ops.heartbeat` через pg-boss, а не таймером процесса.** Так 200 означает, что процесс берёт задачи из очереди, а не только жив. При запуске процесс отмечается сразу, чтобы после выкладки адрес не отвечал 503 до первой минуты. Цена: ещё одна очередь; новая версия процесса ждёт её создания миграцией, как остальные.
6. **Ответ `/api/ready/worker` повторяет форму `/api/ready`:** `{ status, checks: { worker: ok|fail } }`, без времени отметки. База не ответила за 2 секунды: 503.
7. **`backup_stale` без отметки срабатывает.** Нет ни одной отметки ночной копии: сигнал, как и при старой отметке. Базовая копия и журнал проверяются только при включённом архиве (`archive_mode` не `off`): без архива `base-backup.sh` отказывает, сигнал был бы ложным всегда. Цена: на новой установке сигнал `dump` приходит до первой ночной копии; в памятке инцидента сказано сделать её вручную.
8. **Сценарий копии завершается ошибкой, если отметка не записалась.** Копия к этому времени уже выгружена; ненулевой код виден в журнале cron, иначе дежурный получил бы `backup_stale` без причины в журнале сценария. Размер файла передаётся `--bytes`, имени файла и адреса бакета в базе нет.
9. **Отметка копии пишется в журнал аудита** действием `ops.backup_marked` от системы: это изменение данных эксплуатации, которое читает администратор. Строки `hdc_ops_backups` не меняются и не удаляются; за год их около 420.
10. **Проверка `scripts/checks/alerts-runbook.mjs`:** каждый код из `OPS_ALERT_CODES` записан в разделе 6 `docs/runbooks/incident.md` в виде (`код`), и лишних кодов там нет. Раздел дополнен тремя сигналами M8, которых в нём не было (`automation_dropped`, `automation_lag`, `builtin_rule_inactive`), и правилами внешней проверки и хостинга.
