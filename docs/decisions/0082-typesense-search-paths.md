## Решения, которых нет в плане

1. **Проверка после у клиента различает законное и чужое.** Typesense отдаёт клиенту идентификатор, которого RLS не отдал. Личное обращение коллеги отбрасывается законно, поэтому событие `search.isolation_drop` и сигнал `search_isolation` считаются только по обращениям другой организации (системная проверка `org_id`). У решений сигнал только по внутреннему решению, по которому строка очереди индекса не ждёт: решение, ставшее внутренним секунды назад, сигналом не считается.
2. **Переписка у сотрудника весит 0.8, свёрнутый список 0.7** против 1 у прямого (RRF). Вес 0.7 из плана; на наборе 15.4 (8 решений, 9 запросов) путь Typesense и путь SQL дали одинаково: правильное в первых трёх 100% на ru, uz, en, ложных показов 0 из 3. Набор мал, подбирать вес на нём нечего: вес оставлен по плану до набора побольше.
3. **Идеи у сотрудника ищутся двумя путями сразу** (Typesense и `containsText` через "или"): на вкладке "Все" есть идеи на модерации и отклонённые, которых в индексе нет по решению 1.
4. **Стоп-слова одним набором `hub_stopwords` с locale ru**, список в коде (`collections.ts`). Проверено на 30.2: набор без locale на поле с locale ru не действует, список наборов через запятую не принимается (404), набор с locale ru действует и на поля uz, en и `*_fold`. Без стоп-слов запрос "пожалуйста помогите накладная не печатается срочно" ничего не находил: слова отбрасываются только справа.
5. **Настройки поиска в тексте построчно**, как разрешённые домены решений: синонимы `склад, ombor, warehouse` и `накладная => yuk xati, invoice`, словарь `слово = основа`, курирование `запрос | номер решения | место`. Неверная строка называется номером, ничего не сохраняется. Аудит пишет код и число записей: набор целиком больше предела записи журнала (4000 знаков). Курирование всегда `contains`.
6. **Пустые подсказки: строка на сессию формы.** Последний запрос сессии без результата; если в той же сессии решение нашлось, строка удаляется. Текст после маски `findInText` (телефон, адрес, ИНН, ПИНФЛ, сервер) и чисел от 5 цифр, без пользователя и организации, 90 дней (ночная очистка). Аналитика Typesense (`--enable-search-analytics`) не включалась: хранение 90 дней и маску проще держать в PostgreSQL под RLS, и сводка работает и при `SEARCH_PROVIDER=postgres`. Видят администратор и роли публикации решений (agent_l2, care, admin).
7. **Курирование действует только на пути Typesense:** при `SEARCH_PROVIDER=postgres` правила хранятся, но подсказку не меняют.
