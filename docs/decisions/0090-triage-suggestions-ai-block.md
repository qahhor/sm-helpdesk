# 0090. Предложения разбора и блок AI у сотрудника

Дата: 26.11.2026. План M5b, задача 7, решения 6 и 18; FR-TRI-01..06, FR-AI-13, UX-A-12, экран 8.12. Принято исполнителем по общему поручению владельца. Статус: принято исполнителем.

## Что решено

1. **Источник предложений.** Разбор пишется из того же вызова первой линии (FR-TRI-05). Если помощник не отвечает (выключен администратором, обращение создал сотрудник) или передал обращение кодом до вызова модели (просьба о человеке, обязательная тема, P1 без точного совпадения), ставится отдельное задание `ai.triage` на быстрой модели. Неопознанное письмо разбора не получает. Предложения пишутся один раз на поле и обращение: повторный ответ помощника нового предложения не даёт, второе задание `ai.triage` модель не вызывает.
2. **Проверка кодом до записи** (`src/modules/hda/triage-text.ts`, `first-line/triage.ts`): заголовок только простым текстом до 80 знаков, без адресов сайтов и почты, телефонов, чисел длиннее четырёх знаков и угловых скобок, иначе строки нет; модуль только из действующего справочника по коду, который назвала модель (справочник в модель не уходит: его нет в перечне 14.3); тип из закрытого списка; совпадающее с обращением не предлагается; приоритет не предлагается, только пометка "проверьте приоритет" (`priority_hint`, значение `check`).
3. **Таблица `hda_triage_suggestions`** (миграция 0093): пишет система, принимают сотрудники, которые ведут обращения (`product` только читает), читают сотрудники, клиент ни одной политики. Принятие (`acceptTriage` модуля `hdt`) блокирует строку обращения, меняет модуль, тип или заголовок, отмечает предложения принятыми, пишет внутреннее событие `triage_accepted` и запись журнала `ticket.triage_accepted` одной транзакцией; "Принять всё" одной транзакцией. Резюме и пометка приоритета ничего не меняют: принятие только отмечает, что сотрудник их видел.
4. **Найденные решения** хранятся в новой колонке `hda_runs.found` (до трёх объектов: идентификатор, номер, оценка ранжирования). Текста там нет; заголовки блок берёт из `hdk_published` на языке обращения.
5. **Ночная задача `ai.triage_review`** (03:45 по Ташкенту, FR-TRI-04): доля принятых по полю за текущий календарный месяц; решённым считается принятое, отклонённое и ждущее дольше 7 дней (сотрудник прошёл мимо). Доля ниже 70% при не менее чем 30 решениях: строка в `hda_triage_field_offs`, поле больше не предлагается. Администратор видит отметку в настройках AI и включает поле обратно (свежий вход, журнал аудита); в этом месяце ночь поле снова не отключает. Отдельная таблица нужна потому, что система не пишет `hdc_settings`, а ослаблять её политику нельзя.
6. **Блок AI** в правой колонке страницы обращения: состояние и причина передачи, число ответов, резюме с пометкой "AI, не проверено" и под ним исходный текст обращения, найденные решения с оценкой, предложения с "Принять" у модуля, типа и заголовка и "Принять всё", пометка "Проверьте приоритет". Кнопки "Отклонить" нет (экран 8.12): непринятое за 7 дней считается непринятым.

## Цена

Без кнопки "Отклонить" доля принятых узнаёт о несогласии сотрудника только через 7 дней. Модуль почти не предлагается, пока модель не знает кодов справочника; если это мешает, справочник кодов можно добавить в системный текст отдельным решением с правкой перечня 14.3.

Тесты: `tests/unit/hda-triage-text.test.ts`, `tests/integration/hda-triage.test.ts`, `tests/e2e/ai-first-line.spec.ts` (блок AI).
