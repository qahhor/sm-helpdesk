# 0100. Известная проблема у клиента

Дата: 27.11.2026. План M5c, задача 4; FR-KP-05, 08, 09, 14.5, раздел 8.3. Принято исполнителем по общему поручению владельца. Статус: принято исполнителем.

## Что решено

1. **Только представление.** `src/modules/hdp/api/client.ts` читает проблему от имени клиента только из `hdp_problems_public`. Какая активная проблема у сигнатуры, находит система (клиенту таблица сигнатур закрыта), показ всё равно идёт через представление от имени клиента. Карточка клиента: номер, статус, публичные название и описание, момент исправления, обходной путь (номер, адрес и заголовок опубликованного для клиентов решения из `hdk_published`). Язык: язык клиента, затем запасные языки портала, затем любой показанный.
2. **Баннер** (решение 13): ответ `/api/suggest` дополняется полем `knownProblem`; обработчик маршрута собирает его, вызывая модуль знаний (`handleWidgetSuggest` с параметром `extra`) и модуль проблем (`problemForSuggest`) по отдельности. Серверное действие формы портала возвращает `{ items, knownProblem }`. Баннер только у активной показанной проблемы; исправленная остаётся на странице проблем, но баннера не даёт.
3. **Виджет**: баннер вместо формы, "У меня другая проблема" открывает обычную форму, обходной путь открывается в панели. **Портал**: баннер над полем описания, форма остаётся ниже; "Меня это тоже затронуло" отправляет ту же форму другим действием, описание из поля уходит в обращение.
4. **"Меня это тоже затронуло"** (решение 14): обращение тип `bug`, влияние `major`, тема из публичного названия, описание из текста клиента, иначе из кода и текста ошибки контекста, иначе название. Создаётся обычной операцией создания (пределы, сроки, сигнатура, помощник); не привязалось по сигнатуре: явная привязка `via: affected`. Своё обращение клиента по этой проблеме уже есть: возвращается его номер, нового нет. Одновременные нажатия отсекает предел одно нажатие на пару "пользователь, проблема" за 10 секунд. Коллега из той же организации получает своё обращение: номер чужого ему не отдаётся.
5. **Блок в обращении** (решение 15) и **страница `/problems`** (решение 16, ссылка с главной): тот же баннер без кнопок. Состояние Теза "Внимание": `TezMark` получил параметр `pose` и позу `virazh` из `docs/brand/tez/pose-virazh.svg` (копия в `public/brand/tez` без изменений, сверку держит `tests/unit/tez-assets.test.ts`).

## Цена

У позы "Вираж" в пакете бренда один файл на оба фона: в тёмной теме показывается он же. Портал ищет проблему по сигнатуре только из текста описания: подсказки режима B (код и текст ошибки) уходят в обращение и дают привязку по сигнатуре после создания, но баннер на форме по ним не строится.
