# 0104. Задача разработки у известной проблемы

Дата: 27.11.2026. План M5c, задача 8; FR-KP-11, FR-DEV-06. Принято исполнителем по общему поручению владельца. Статус: принято исполнителем.

## Что решено

1. **Привязка** строкой той же таблицы `hdw_dev_task_links` (миграция `0105_hdw_dev_task_problem_links.sql`, номер сдвинут на два от плана): колонка `known_problem_id` с внешним ключом и частичным уникальным индексом (у проблемы одна задача), проверка `c1` "ровно одно из обращения, идеи, проблемы". Привязку ставят и снимают те, кто ведёт проблемы (`app.hdp_can_write()`), отдельными политиками; политики обращений и идей не тронуты.
2. **Точки входа** в `hdw` (`linkDevTaskToProblem`, `unlinkDevTaskFromProblem`, `readDevTaskForProblem`): те же роли (agent_l2, care, admin), тот же ручной режим и режим API, что у передачи обращения; существующая задача по номеру переиспользуется. В режиме API в таск-менеджер уходит только внутреннее название проблемы и ссылка на карточку. Каждая привязка и отвязка пишет журнал аудита с объектом `known_problem`.
3. **Смена статуса или версии задачи** (вручную, вебхуком, опросом) даёт владельцу проблемы уведомление `problem_dev_task` и письмо `staff_problem_dev_task` в той же транзакции. Тот, кто сам сменил статус, о своём действии не уведомляется. Клиентам ничего не уходит, статус проблемы не меняется. Переход из колокольчика ведёт на карточку проблемы.
4. **Итог закрытия**: рассылка `closing` берёт версию задачи разработки проблемы и закрывает обращения итогом `fixed_in_version` с этой версией; версии нет, итог `solved`. Модуль `hdw` стоит над `hdp` (берёт у него привязку обращений для правил), поэтому версию `hdp` получает через источник, который регистрирует `src/wiring.ts` (`registerProblemDevTaskVersion`), как обработчик закрытия задачи идеи.
5. **Интерфейс** на карточке проблемы: тот же блок `DevTaskBlock` и окно `DevTaskDialog`, что у обращения, со своими действиями и подписями `agent.problems.devTask`. Интерфейс `DevTracker` (11.11) не менялся, контрактные тесты не трогались.

## Цена

Владелец проблемы, который ушёл из второй линии, продолжает получать уведомления, пока проблему не передадут другому. Проблема без владельца уведомлений не даёт.

Тесты: `tests/integration/dev-tasks.test.ts` (три новых случая), `tests/unit/hdn-mail-render.test.ts`.
