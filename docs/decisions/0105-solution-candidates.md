# 0105. Кандидаты в решения: черновик и склейка

Дата: 27.11.2026. План M5c, задача 9; FR-CAND-01, 02, 03, 05, 07, 09, 14.3. Принято исполнителем по общему поручению владельца. Статус: принято исполнителем.

## Что решено

1. **Таблицы** (миграция `0106_hda_candidates.sql`, номер сдвинут на два от плана): `hda_solution_candidates` (заголовок, проблема, шаги, находки для подсветки, вектор BGE-M3, статус, число источников и организаций, причина отклонения) и `hda_candidate_sources` (обращение-источник, уникальное: одно обращение даёт одного кандидата). FORCE RLS: читают и решают сотрудники с `app.kb_can_write()` (все, кроме product), создаёт и склеивает система, клиент не видит ни одной строки. Колонка `hdk_articles.staff_useful_count`, цель `candidate`, решение `skipped`.
2. **Обход** `ai.candidates_sweep` раз в 15 минут: обращения, решённые за 7 суток с итогом `solved` или `workaround`, без `solution_id`, не объединённые, без источника решения, у организации с AI-обработкой, без прошлого вызова цели `candidate` с ответом (`ok`, `invalid_response`) и без источника кандидата. Сбой сети (`failed`) обход повторит.
3. **Задание** `ai.candidate`: тот же вход и схема, что у черновика решения (`assembleDraftData`, `draftSchema`), модель уровня `fast`. Дневной предел `candidates.daily_limit` (50) по вызовам цели за сутки по Ташкенту, сверх общего месячного предела расходов. `confident: false`: кандидата нет, решение `skipped` в журнале. Ссылки вне разрешённых доменов вырезаются до записи; телефоны, почта и другие находки остаются в тексте и подсвечиваются (`findings`).
4. **Склейка** чистой функцией `candidateMergeDecision`: сходство с опубликованным решением любой аудитории не ниже `candidates.published_similarity` (0,88) даёт "пригодилось сотрудникам" без кандидата; иначе сходство с кандидатом `new` или `rejected` не ниже `candidates.merge_similarity` (0,85) добавляет источник; иначе новый кандидат. Отклонённый возвращается в `new` на пятом новом источнике с записью журнала `candidate.returned`.
5. **Векторы недоступны**: вектор запрашивается до трёх раз внутри задания, затем кандидат создаётся без вектора. Повторять всё задание нельзя: ответ модели уже получен и оплачен, повтор вызвал бы модель второй раз. Ночная задача `ai.candidates_embed` досчитывает векторы и склеивает: источники переходят к похожему кандидату, опустевший нерешённый кандидат удаляет система (отдельная политика удаления только для системы и только у нерешённого).
6. **Настройки** `candidates.*` на странице `/agent/settings/ai`: только администратор со свежим входом, журнал аудита на каждое значение.
7. **Кандидат не в поиске**: его нет в `hdk_search_documents` и Typesense, подсказка и помощник его не находят (проверка в задаче 10).

## Цена

Пороги 0,88 и 0,85 начальные: подстройка на настоящих векторах заблокирована (нет доступа к huggingface.co). Кандидат из обращения, решённого и снова открытого, остаётся. Вопрос о склейке с решением решает сотрудник, а не ночная задача: похожий на опубликованное решение кандидат без вектора остаётся кандидатом.
