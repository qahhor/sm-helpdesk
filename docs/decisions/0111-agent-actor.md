# 0111. Актор agent, таблицы токенов, журнала вызовов и сводок

Дата: 27.11.2026. Веха M8b, задача 1; ТЗ 7.21 (FR-AGT-02, 09), 10.2, 10.4, 10.5; решения 1, 5, 10, 14, 15, 23, 31 плана M8b. Принято исполнителем по общему поручению владельца от 26.11.2026. Статус: принято исполнителем.

## Что решено

1. **Тип актора.** `AgentActor = { type: 'agent'; tokenId; userId; tools; ticketId; ip? }`. В наброске 10.2 у актора нет пользователя, а 10.5 связывает токен с учётной записью `agent_bot`: `userId` нужен, чтобы база записала автора в служебные колонки и журнал аудита. `ticketId` задан только у токена запуска по обращению (FR-AGT-12).
2. **Переменные транзакции.** `withActor` ставит для агента `app.user_id`, новые `app.agent_token_id` и `app.agent_ticket_id`, адрес `app.client_ip` и `statement_timeout = 5s` (решение 31). У остальных акторов обе новые переменные пусты, предел времени не меняется.
3. **Функции базы.** `app.agent_token_id()` и `app.agent_ticket_id()` отдают значения только при `app.actor_type() = 'agent'`. `app.agent_token_active()` (`SECURITY DEFINER`, владелец `hub_owner`) истинна, если токен не отозван, не истёк, принадлежит учётной записи из `app.user_id` с ролью `agent_bot` в состоянии `active`, обращение совпадает с `app.agent_ticket_id`, а у токена запуска действует и родитель. Каждая политика актора `agent` включает эту функцию, поэтому отзыв закрывает данные со следующего оператора, даже внутри начатого запроса.
4. **Таблицы** (имена по `docs/naming.md`): `hda_agent_tokens` (значение не хранится: SHA-256 и последние 4 знака; перечень из каталога проверяет база; адреса обязательны; срок не больше 365 суток от выпуска или продления проверяет триггер; учётная запись только `agent_bot`; отзыв не снимается; токен запуска только с `get_ticket` и `add_internal_note` и пределом заметок), `hda_agent_tool_calls` (без аргументов и ответов, только пополняется, ночная очистка старше 365 суток), `hda_agent_reports` (пишет агент основным токеном, читают сотрудники, меняется только отметка "просмотрено" от имени отметившего).
5. **Справочники видны агенту.** Модули, рабочие календари и сроки SLA читает любой актор (политика `*_actor_select` с вехи M0-M3); агент тоже читает их целиком. Данных клиентов в них нет, а модуль агенту нужен для фильтров и черновика решения. В наборе изоляции это вид `agent: 'reference'`; изменить их агент не может.
6. **Чтение после записи.** У агента нет политик чтения своих сводок и строк журнала, поэтому запись агента идёт без `returning`: идентификатор строки код задаёт сам или не читает вовсе.
7. **Токен запуска и журнал.** Внешний ключ журнала вызовов на токен без каскада: ночная очистка удаляет истёкшие токены запуска, только когда у них не осталось строк журнала (365 суток).

## Цена

Агент видит справочник модулей, календарей и сроков SLA. Токены запуска лежат в таблице, пока живут их строки журнала. Без пользователя `agent_bot` токен не выпускается: учётная запись создаётся при выпуске (задача 3).

Тесты: `tests/integration/hda-agent-access.test.ts`, `tests/integration/isolation/registry.test.ts` ("агент с действующим токеном не читает ни одной строки, кроме своих представлений, и ничего не меняет и не удаляет"), `tests/unit/with-actor.test.ts`.
