# 0116. Инструменты записи сервера MCP и пометка записей AI-сотрудника

Дата: 27.11.2026. Веха M8b, задача 6; ТЗ 7.21 (FR-AGT-04, 05, 07, 10, 12), 14.3; решения 18-24 плана M8b. Принято исполнителем по общему поручению владельца от 26.11.2026.

## Что решено

1. **Инструменты записи:** `add_internal_note` (виды `note` и `handoff_memo`), `draft_solution`, `draft_known_problem`, `create_report`. Каждый пишет журнал аудита `agent.tool_called` той же транзакцией с номерами объектов.
2. **Очистка текста агента:** невидимые знаки и знаки направления письма, разметка HTML (скрипты и стили вместе с содержимым), ссылки вне разрешённых доменов решений (`kb.allowed_domains`) вырезаются; пустой после очистки текст и длинный ввод отклоняются схемой. Пределы: заметка 4000 знаков (токен запуска 2000), заголовок 200, текст решения и сводки 20000.
3. **Заметка и записка** строкой `hdt_ticket_messages` (`author_type = 'agent'`, внутренняя, автор учётная запись `agent_bot`, вид `agent_note_kind`). Политика вставки актора `agent` пускает только в обращение, видное агенту; триггер `t_hdt_ticket_messages_agent_guard` не даёт другим акторам писать от имени агента и считает заметки токена запуска до `note_limit`. Обращение, сроки SLA, "клиент ждёт с", исполнитель, уведомления, события и правила не трогаются: у таблицы сообщений нет триггеров на это, а кода сотрудника инструмент не вызывает (`tests/integration/hda-agent-write-tools.test.ts` сверяет строку обращения и очереди до и после).
4. **Записка второй линии** показывается в окне передачи как "Черновик записки AI-сотрудника" с пометкой; поля передачи она не заполняет.
5. **Черновик решения:** статья с `is_agent_draft` и `is_untrusted`, аудитория `internal`, первая версия-черновик из абзацев текста (только текстовые узлы), источники только из видимых агенту обращений. Правка опубликованного решения: новый черновик со ссылкой `revises_article_id`, исходное решение не меняется. Публикация обычным порядком с отметкой находок недоверенного текста.
6. **Черновик проблемы** (решение 20): статус `draft` (не активный; признак показа запрещён проверкой базы `hdp_problems_c7`), сигнатура неактивна, обращения в `hdp_problem_proposals`, описание агента в `hdp_problems.internal_description`. К черновику обращения не привязываются (`problem_draft`). Сотрудник с правом ведения проблем: "Принять черновик" (статус `investigating`; сигнатура, уже занятая другой активной проблемой, снимается с черновика), "Привязать предложенные" (общая функция привязки, итог по каждому обращению), "Отклонить черновик" (статус `closed` без рассылки и без момента исправления). Записи аудита `problem.draft_accepted`, `problem.proposals_linked`, `problem.draft_rejected`. Системная функция черновика (для всплеска, задача 8) работает так же.
7. **Сводка:** строка `hda_agent_reports` непроверенной; поля для чата команды только числами по ключам `new_tickets`, `ai_resolved`, `handed_off`, `sla_risk` и до 20 номеров обращений, номера вне видимости агента отбрасываются.
8. **Пометка** "AI-сотрудник, не проверено" (`AgentMark`) в ленте обращения, окне передачи, карточке черновика проблемы, списке и редакторе решений. Текст агента выводится обычным текстом (`whitespace-pre-wrap`), без Markdown и активных ссылок.
9. Записи агента идут без `returning`: читать свои записи актору `agent` не дано, идентификаторы и номера берутся заранее (`nextval`).

## Цена

Агент видит черновики проблем в `list_known_problems` (статус `draft`): так он не создаёт повторов, но и видит черновики, которые сотрудник ещё не принял. Отклонённый черновик остаётся закрытой проблемой в списке.
