# 0118. Всплеск сигнатуры

Дата: 27.11.2026. Веха M8b, задача 8; ТЗ 7.21 (FR-AGT-11), 10.5; решение 25 плана M8b. Принято исполнителем по общему поручению владельца от 26.11.2026.

## Что решено

1. **Правило** (чистая функция `spikeDecision`): число разных организаций с сигнатурой за окно не меньше порога, нет активной проблемы или черновика с этой сигнатурой, не было всплеска этой сигнатуры за последние 24 часа. Ровно 24 часа спустя всплеск снова возможен.
2. **Задача `agent.spikes`** раз в 5 минут считает сигнатуры обращений за окно по всем организациям клиентов (это счётчик, данных не выдаёт), без служебной организации "Неопознанные" и объединённых обращений. Найденный всплеск: строка `hda_signature_spikes` (сигнатура, число организаций и обращений, окно, момент). Событие агенту по всплеску ставит задача 9.
3. **Настройки** `agent.spike_org_count` (по умолчанию 3, от 2 до 100) и `agent.spike_window_minutes` (по умолчанию 60, от 5 до 1440) на экране "AI-помощник" настроек, только администратор со свежим входом, журнал аудита `settings.changed`.
4. **Блок "Всплески сигнатур"** на `/agent/problems` за 7 суток для всех сотрудников. "Создать известную проблему" работает без агента: роль ведения проблем, внутреннее название (по умолчанию "Всплеск ошибки <сигнатура>"), активная проблема с сигнатурой, обращения окна привязываются общей функцией привязки, всплеск ссылается на проблему.
5. **Агент** читает всплески инструментом `signature_spikes` из представления `hda_agent_spikes`: сигнатура, числа, номер проблемы и до 50 номеров обращений окна, видимых агенту. Организаций нет.

## Цена

Ссылка всплеска на проблему ставится отдельной транзакцией после создания проблемы: при сбое между ними проблема есть, а кнопка у всплеска остаётся (вторая попытка получит `signature_taken`). Обращения окна привязываются сразу: это действие сотрудника, не агента.
