# 0125. Адрес запроса сервера MCP и доверенный прокси

Дата: 27.11.2026. Веха M8b, независимая проверка, находки I6 и M10; ТЗ 7.21 (FR-AGT-02), 13 (`MCP_ALLOWED_IPS`), 14.2 (T27); решение 11 плана M8b, решение 0020. Принято исполнителем по общему поручению владельца от 26.11.2026.

## Что решено

1. Списки адресов сервера MCP (`MCP_ALLOWED_IPS` и список токена) проверяют адрес из заголовка `CLIENT_IP_HEADER` доверенного прокси. Это единственное решение о доступе по этому заголовку в портале. Условие запуска: порт портала принимает соединения только от доверенного прокси (Cloudflare или свой nginx), прокси перезаписывает заголовок своим значением. Записано в `docs/runbooks/launch.md` (переменная `MCP_ALLOWED_IPS`) и `docs/guides/agents.ru.md`; комментарий `clientIp` в `src/modules/hdc/util.ts` исправлен.
2. Главная защита сервера MCP остаётся токеном (256 бит, хеш в базе, срок, отзыв); список адресов второй рубеж.
3. Предел 30 неудачных проверок за 10 минут с адреса действует только на неверные токены (находка M10): действующий токен с того же адреса принимается, чужие попытки не закрывают вход агенту.

## Цена

Если источник портала открыт в обход прокси, список адресов обходится подменой заголовка; токен по-прежнему нужен. С адреса, исчерпавшего предел, перебор продолжает получать 429, но действующий токен узнаёт по ответу 200; перебор токена длиной 256 бит этим не облегчается.

Тесты: `tests/integration/hda-mcp-server.test.ts` (тест "находка M10").
