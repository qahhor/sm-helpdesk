# 0128. Приём отчёта о сканировании инструментом сервера MCP

Дата: 27.11.2026. Веха M8c, задача 3; ТЗ 7.22 (FR-CODE-01, 03, 05, 12, 13, 14), 7.21 (FR-AGT-04), 8.12 (перечень инструментов токена); решения 3, 10, 11, 14, 15, 26 плана M8c. Принято исполнителем по общему распоряжению владельца от 26.11.2026.

## Что решено

1. **Путь отчёта.** Hermes Agent передаёт отчёт инструментом `code_catalog_upsert` сервера MCP (имя из экрана 8.12) одним вызовом. Новой точки входа и новой сетевой зависимости нет: вход, адреса, пределы, журнал вызовов и аудит `agent.tool_called` общие с остальными инструментами записи. Токен запуска инструмента не получает (проверка `hda_agent_tokens_c7`).
2. **Предел тела.** Вход сервера MCP теперь проверяет токен по заголовкам до чтения тела. Токен с `code_catalog_upsert` в перечне получает предел 2 МБ, остальные прежние 64 КБ. Большое тело без действующего токена не читается вовсе.
3. **Отклонение.** Нарушение правил решения 0127 оставляет строку `hda_code_scans` со статусом `rejected` и причинами (правило и путь поля), записи аудита `code.scan_rejected`; записей, шаблонов и заметок о модулях нет. Ответ агенту `status: rejected` с причинами. Неверный по схеме вызов (например, поле `pattern`) даёт `invalid_arguments` и не пишет ничего, кроме строки журнала вызовов.
4. **Изменения.** Портал считает их сам по отпечатку содержимого от агента: новая запись черновиком (`new`), изменившаяся снова черновиком без утвердившего (`changed`), неизменная остаётся с прежним статусом и правками сотрудника (`same`), отсутствующая в отчёте того же репозитория становится `removed`, вернувшаяся снова черновиком `new`. Карта модулей теми же правилами. Поле `changes` отчёта только проверяется схемой. Журнал аудита `code.scan_accepted` с числами и ключами сменивших статус записей (до 100).
5. **Повтор.** Принятый отчёт того же репозитория с тем же `scanId` ничего не меняет и возвращает прежние числа с `duplicate: true`.
6. **Сводка в чат команды** (FR-CODE-14): задача `agent.team_chat` M8b отправляет по каждому принятому за сутки сканированию сообщение из чисел и ссылки на очередь (шаблон `agent.teamChat.codeScan`), отметка `chat_sent_on`; без настройки чата ничего не уходит. Выводов агента в сообщении нет.

## Цена

Изменённая утверждённая запись перестаёт давать точную сигнатуру до повторного утверждения. Запрос с телом до 2 МБ держит соединение дольше: такой предел только у токена с инструментом сканирования. Проверка `MCP-тело больше 64 КБ` теперь отвечает 401 раньше 413 для запроса без токена.
