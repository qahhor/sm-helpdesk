# 0130. Точные сигнатуры по утверждённым шаблонам

Дата: 27.11.2026. Веха M8c, задача 5; ТЗ 7.22 (FR-CODE-04, 05), 11.5; решения 7, 8 плана M8c; сценарий 20 раздела 15.3. Принято исполнителем по общему распоряжению владельца от 26.11.2026.

## Что решено

1. **Одна функция сигнатуры** `resolveErrorSignature` (`src/modules/hdk/api/signature-text.ts`) для всех мест, где считается сигнатура: запись сигнатуры нового обращения во всех каналах (портал, почта, виджет, сотрудник, "Неопознанные") и ночная починка, подсказка на портале и в виджете, баннер известной проблемы. Привязка сотрудником в редакторе: `resolveStaffSignature`. Сначала утверждённые шаблоны знаний из кода, затем прежний способ 11.5.
2. **Строки для шаблонов** (`templateCandidateLines`): текст ошибки контекста, текст строки ошибки 11.5, он же без хвоста стека на той же строке, затем до 30 непустых строк описания без кода и подписи "Ошибка:" в начале. Код ошибки берётся из контекста или строки ошибки.
3. **Сопоставление в базе** функцией `app.hda_code_signature` (решение 0126): только утверждённые записи; код записи пуст или совпадает с кодом ошибки; первая подходящая строка, затем самый длинный шаблон. Шаблоны не хранятся в памяти процесса.
4. **Сигнатура записи** (первые 32 знака sha256 от `code-key|<ключ>`) пишется в обращение и в `hdk_error_signatures` как любая другая: число организаций, решения, известные проблемы, всплески и правила работают с ней без изменений.

## Цена

Решения и проблемы, привязанные к прежней сигнатуре 11.5 той же ошибки, перестают совпадать с новыми обращениями после утверждения записи: новое обращение получает сигнатуру записи. Сотрудник перепривязывает решение (или создаёт решение из записи, задача 6). Каждая сигнатура обращения, подсказки и баннера теперь стоит одного короткого запроса к базе.

Тесты: `tests/integration/hdk-code-signature.test.ts`, `tests/unit/hdk-signature.test.ts`.
