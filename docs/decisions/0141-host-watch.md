# 0141. Ресурсы сервера без агента хостинга

Дата: 27.11.2026. План: `docs/plans/M9.md`, задача 9, решение 17; ТЗ 13.8. Миграция `drizzle/0126_hdc_ops_host_marks.sql`. Статус: принято исполнителем по общему поручению владельца от 26.11.2026.

1. **Замер на сервере, сигнал в портале.** Таймер systemd раз в 5 минут запускает `scripts/ops/host-watch.sh`: наибольшая доля занятого места томов базы и копий (`df -P`), память без кеша (`MemTotal - MemAvailable`), нагрузка за минуту на одно ядро (`/proc/loadavg`, не больше 100). Сценарий только читает и вызывает `hub ops:host-mark --host <имя> --disk --mem --cpu`. Имя сервера берёт сам сценарий: внутри контейнера `web` имя машины было бы именем контейнера.
2. **Таблица `hdc_ops_host_marks`**: одна строка на сервер, новая отметка заменяет прежнюю; FORCE RLS, пишет и читает только система; клиент, сотрудник и агент не видят (строка набора изоляции). Журнала аудита у отметки нет: это замер, а не изменение статуса или прав.
3. **Сигналы `ops.watch`.** `host_pressure`: свежая отметка (не старше 15 минут) с долей 80% и выше по любому показателю; в тексте только показатель и число (`disk 85%`), без имени сервера и путей томов. `host_mark_stale`: последняя отметка старше 15 минут. Отметок нет совсем: сигнала нет, чтобы не будить дежурных до установки таймера; о гибели всего сервера говорит внешняя проверка доступности (решение 4 плана). Оба сигнала не чаще раза в час, как остальные.
4. **Номер миграции.** План назвал `0126` для этой таблицы и `0127` для срока бездействия; срок бездействия сделан раньше, поэтому файл `0127` создан до `0126`. Ни одна база с этими миграциями до коммита вехи не запускалась, порядок применения по имени файла сохраняется.

Цена ошибки: таймер ставится руками по памятке запуска (раздел 12); пока его нет, сигналов о ресурсах нет совсем.
