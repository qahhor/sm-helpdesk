# 0147. Отметка согласия на AI-обработку ставится при каждом включении

Дата: 27.11.2026. Независимая проверка части A вехи M9, находка M5. Уточняет решение 10 плана M9 и миграцию 0124.

1. **База.** Миграция 0129 заменяет функцию триггера `app.hdu_organizations_ai_consent_guard()`: включить AI-обработку выключенной организации можно, только если дата или основание согласия изменились в этом же UPDATE. Прежняя отметка, оставшаяся после выключения, больше не открывает обработку одним признаком `is_ai_enabled = true` в обход кода.
2. **Код.** `setOrgAiProcessingTx` (hdu, `core/orgs.ts`) при включении выключенной организации сначала снимает прежнюю отметку, затем одним UPDATE ставит признак, дату и основание. Поэтому повторное включение по тому же письму (та же дата и основание) проходит и пишет `org.ai_consent_recorded`, как раньше. Обе записи в одной транзакции с журналом.
3. **Тесты.** Тесты и браузерные тесты, включающие обработку в обход кода, ставят основание с меткой времени (`'Тестовое согласие ' || clock_timestamp()::text`): на постоянной базе браузерных тестов повтор того же основания теперь отклоняется.
4. Цена ошибки: сценарий или ручной запрос, включающий обработку без новой отметки, получает ошибку 23514. Это и есть цель: включение без отметки согласия должно проходить только через форму care или администратора.
