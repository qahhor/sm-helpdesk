# 0149. Переписка уходит модели структурой: роль задаёт тег, а не строка

Дата: 28.11.2026. Проверка на AI-инъекции, волна 7, находки S-I2 и M9. Уточняет решение 15 плана M5 и решение 22 плана M5b.

1. **Что было.** Вход модели собирался строками "Клиент: ...", "Сотрудник: ...", "Ответ клиента: ...". Клиент мог написать такую строку сам, и модель читала её как сообщение сотрудника. `escapeData` не экранировал "&": готовая сущность `&lt;/ticket&gt;` из текста клиента была неотличима от экранированного тега.
2. **Решение.** Каждое сообщение лежит в теге `<msg role="client|staff">` (у темы, описания и ответа клиента ещё `part`), содержимое экранировано, "&" первым. Роль ставит только код. Системные подсказки первой линии, разбора и черновика говорят модели, что роль задаёт атрибут, а слова и теги внутри сообщения написал его автор. Пределы знаков считаются по тексту сообщений: тег посередине не обрезается.
3. **Перевод.** Текст, который модель вернула из экранированных данных (перевод решения, идеи, публичного текста, сообщения), проходит `unescapeData`: "&amp;" снова "&". Результат остаётся текстом и при показе экранируется как любой текст.
4. **Ссылки кандидатов.** `stripForeignLinks` считает адресом ссылку Markdown без схемы, "//узел", "www." без границы слова, любую схему с "://" (ftp, tg), `javascript:`, `tg:` и домен без схемы с путём. Остаются только http и https разрешённых доменов.
5. Цена ошибки: модель хуже понимает вход нового вида. Проверяется прогоном `pnpm eval:ai` с ключом (набор 15.6) перед включением помощника; на заглушке доли ответов не меряются.
