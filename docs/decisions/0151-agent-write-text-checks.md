# 0151. Записи агента: проверка на исходный код и очистка до неподвижной точки

Дата: 28.11.2026. Проверка на AI-инъекции, волна 7, находки S-I4 и S-M1. Уточняет решение 18 плана M8b и решение 0134.

1. **Исходный код (S-I4).** Инструменты `add_internal_note`, `draft_solution`, `draft_known_problem` и `create_report` отклоняют текст с признаками исходного кода ошибкой `invalid_arguments` и ничего не записывают. Признаки те же, что у отчёта о сканировании (`looksLikeCode`: присваивание PL/SQL, блок begin ... end;, запрос select ... from ... where, три точки с запятой в строке, знак длиннее 80 без пробелов, вставка base64), и строка длиннее 300 знаков. Адреса ссылок перед проверкой убираются: длинная разрешённая ссылка не код.
2. **Чего нет.** Правило "не больше 10 строк" отчёта о коде к заметкам, черновикам и сводкам не применяется: они по природе длиннее. Остаток риска тот же, что в решении 0134: фрагмент кода обычными словами без этих признаков эвристика пропустит; запись агента всегда помечена "не проверено" и клиенту не видна.
3. **Очистка (S-M1).** `cleanAgentText` повторяет вырезание разметки, невидимых знаков и чужих ссылок, пока текст меняется (не больше 50 проходов): вырезанный тег не собирает из соседних кусков новый. Оставшиеся одиночные "<" и ">" заменяются типографскими "‹" и "›": убрать их совсем значило бы исказить текст вида "остаток < 0". Ссылкой считается адрес без границы слова, "www.", "//узел" и любая схема: общий код с кандидатами (`src/modules/hda/links.ts`).
4. Цена ошибки: честная заметка с присваиванием ":=" или тремя точками с запятой в строке отклонена, агент получает `invalid_arguments` и пишет словами.
