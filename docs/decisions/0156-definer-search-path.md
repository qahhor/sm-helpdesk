# 0156. search_path функций SECURITY DEFINER оканчивается на pg_temp

Дата: 28.11.2026. Проверка на инъекции, волна 7, находка S-A2.

1. **Что было.** Пятнадцать функций SECURITY DEFINER заданы с `search_path = pg_catalog, public`. Без `pg_temp` в списке PostgreSQL ищет таблицы и типы сначала во временной схеме вызывающего: временная таблица с именем таблицы портала подменила бы её внутри функции с правами владельца.
2. **Решение.** Миграция 0131 дописывает `pg_temp` в конец пути каждой такой функции командой `ALTER FUNCTION ... SET search_path` (применённые миграции не правятся). Функции счётчиков идей принадлежат роли `hub_hdi_counter`: владелец миграций переключается на неё на время команды.
3. **Вторая линия.** Права TEMP у `hub_app`, `hub_auth` и PUBLIC нет с начальной настройки (`REVOKE ALL ON DATABASE ... FROM PUBLIC`): это теперь проверяет тест.
4. **Тест.** `tests/integration/db-roles.test.ts`: у каждой функции `prosecdef` вне расширений путь задан и оканчивается на `pg_temp`; роли приложения не создают временных таблиц. Новая функция SECURITY DEFINER без `pg_temp` роняет тест.
