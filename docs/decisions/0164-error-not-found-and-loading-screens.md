# 0164. Экраны ошибки, "не найдено" и ожидания: где есть оболочка и где её нет

Дата: 28.11.2026. Проверка интерфейса, волна 7b, находки U6 и U7.

1. **Экран ошибки (`error.tsx`).** Граница ошибок Next.js работает в браузере и не получает параметров от сервера, а тексты портала переводятся на сервере и в браузер файлы сообщений не уходят. Раскладка языка и раскладка рабочего места кладут готовые строки раздела `common.error` в контекст (`ErrorTextsProvider`), экран ошибки берёт их оттуда. Файл `error.tsx` стоит в каждой группе маршрутов рядом с её раскладкой: оболочка остаётся, меняется только содержимое. Причина ошибки на экран не выводится.
2. **Ошибка корневой раскладки (`global-error.tsx`).** Раскладки и её контекста уже нет. Язык берётся из адреса, тексты того же раздела `common.error` подгружаются отдельным файлом только на этом экране. Пока файл не пришёл, на экране один Тез. Строк в коде компонента нет. Цена ошибки: если сервер не отвечает совсем, текст не появится; человек видит Теза без подписи.
3. **"Не найдено" в кабинете и рабочем месте.** Страница, вызвавшая `notFound()` внутри группы `(portal)` или каталога `agent`, показывает экран внутри своей оболочки. Неизвестный адрес рабочего места ловит страница `agent/[...rest]`: гость с неё уходит на вход, как с любой страницы рабочего места.
4. **Неизвестный адрес вне рабочего места** (`/ru/что-угодно`) показывает общий экран в оболочке страниц без входа, без меню кабинета. Ловить такие адреса страницей внутри `(portal)` нельзя: раскладка кабинета требует входа, и гость вместо ответа 404 получал бы перенаправление на вход по любому несуществующему адресу. Сессию общий экран не читает. Цена ошибки: клиент, ошибшийся в адресе первого уровня, видит экран без меню кабинета и возвращается кнопкой "На главную".
5. **Заготовки на время загрузки.** У очередей файл `loading.tsx`. У показателей заготовка стоит внутри страницы (`Suspense` после проверки права): файл `loading.tsx` действовал бы и на вложенную страницу пилота, а ответ "не найдено" после начала потока теряет код 404. По той же причине у страницы обращения сотрудника и у карточки организации файла `loading.tsx` нет: обе отвечают 404 на несуществующий номер, и этот код проверяют тесты политики содержимого. Чтобы дать им заготовки, нужно разделить загрузку на быструю проверку существования и медленную часть; это вопрос владельцу (нужны ли заготовки ценой переделки загрузчиков).
6. **Проверочная страница `/dev/error`** бросает ошибку с параметром `fail=1`, чтобы браузерный тест видел экран ошибки. Открыта только при `HUB_SHOWCASE=1`, как витрина (решение 0008).
