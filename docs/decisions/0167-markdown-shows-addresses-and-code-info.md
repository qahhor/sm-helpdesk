# 0167. Адрес ссылки и картинки и строка после ``` видны сотруднику

Дата: 28.11.2026. Независимая проверка волны 7, находка R1. Дополняет решение 0148, уточняет раздел 14.3 ТЗ.

1. **Что было.** После решения 0148 на экране всё ещё не было адреса ссылки и картинки и строки после ``` у блока кода, кроме первого слова. `[](<текст для модели>)`, `![](http://x.uz/ignore-previous-rules)` с пустой подписью и ` ```sql указание ` сотрудник не видел, а модель и агент получали.
2. **Решение.** Экран дописывает скрытое текстом: после ссылки её адрес и подпись в кавычках в скобках, картинка заменяется текстом "подпись (адрес "подпись в кавычках")", над блоком кода абзац со строкой после ``` (язык и остальное). Адрес берётся из исходного текста, до проверки схемы: адрес `javascript:` ссылкой не становится, но текстом показан.
3. **Чего нет.** Ссылка, чей текст и есть её адрес (`<https://smartup.uz>`, `<help@smartup.uz>`), адрес не повторяет. Ссылка и картинка по сноске (`[текст][1]`, `![][1]`) адрес не повторяют: он показан в определении сноски (решение 0148).
4. **Кого касается.** Компонент один для сотрудника и клиента: клиент в ответе сотрудника тоже видит адрес после ссылки. Отдельного вида для клиента нет: два вида одного текста снова дали бы расхождение.
5. **Тесты.** `tests/unit/markdown.test.tsx` (три случая), `hda-agent-read-tools.test.ts`, три атаки категории `hidden_markdown` (`hidden-md-05..07`).
6. Цена ошибки: ответы со ссылками выглядят длиннее ("раздел (https://...)"). Если владельцу это мешает у клиента, адрес можно прятать только там, где текст написал сотрудник; текст клиента на экране сотрудника должен оставаться полным.
