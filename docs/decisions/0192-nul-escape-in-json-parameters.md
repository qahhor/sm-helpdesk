# 0192. Запись \u0000 в параметре JSON убирается на границе базы

Дата: 28.11.2026. Независимая проверка волны 7, находка R8. Дополняет решение 0157.

1. **Что проверено.** Значение колонки jsonb drizzle отдаёт драйверу уже строкой JSON, нулевой байт в ней записан шестью знаками `\u0000`. Очистка из решения 0157 такую строку не меняла, база отвечала 22P05. Воспроизведено на настоящей базе записью в `hdc_audit_log.diff` через `withActor`. Три проверенных входа с текстом пользователя в jsonb (контекст обращения из виджета, шаблон ответа, объявление) ошибки не давали: их схемы убирают знак раньше (`cleanUserText`). Остальные записи в jsonb (журнал аудита, очередь уведомлений, заголовки входящих писем, записи агента) по одной не проверялись: правка закрывает путь целиком.
2. **Решение.** На той же границе (`src/db/no-nul.ts`): из строкового параметра, который разбирается как JSON, убирается запись `\u0000` с чётным числом обратных косых черт перед ней. `\\u0000` в JSON (шесть обычных знаков в тексте) не трогается: база это хранит. Строка, которая не JSON, не меняется.
3. **Почему не свой тип колонки.** Колонок jsonb сорок; замена типа в каждой и правило "новая колонка только через него" надёжнее не станут, чем одна граница.
4. **Тесты.** `tests/unit/db-no-nul.test.ts` (запись знака, текст с косой чертой, не JSON), `tests/integration/sql-injection.test.ts` ("нулевой байт в тексте, который уходит в колонку jsonb").
5. Цена ошибки: тип параметра на границе неизвестен. Если пользователь вставил в текстовое поле целиком правильный JSON с записью `\u0000` (например, ответ сервера в описании ошибки), эти шесть знаков из его текста пропадут. Остальной текст не меняется.
