# Smartup Hub: инструкция для команды AI-агентов

Для тех, кто настраивает Hermes Agent и других внутренних агентов на работу с порталом. Основание: ТЗ 7.21 (FR-AGT-01..15), план `docs/plans/M8b.md`, решения `docs/decisions/0110`-`0120`.

## 1. Что агенту можно и нельзя

Агент работает с порталом только через сервер MCP и события. Прямого доступа к базе, исходному коду Smartup и знаниям из кода у него нет.

Агент читает обезличенные обращения организаций с включённой AI-обработкой (без имён, почты, телефонов клиентов, названия и ИНН организации; организация идентификатором и категорией A-D), внутренние заметки сотрудников в обезличенном виде, опубликованные решения со статистикой, кандидатов в решения, известные проблемы, опубликованные идеи без авторов, сигнатуры без решения, всплески сигнатур и показатели помощника. Вложения, скриншоты и имена файлов недоступны.

Агент пишет только то, что видят сотрудники: внутреннюю заметку, черновик записки для второй линии, черновик решения, черновик известной проблемы, сводку. Каждая запись помечена "AI-сотрудник, не проверено". Инструментов, которые отвечают клиенту, меняют статус, приоритет, исполнителя, очередь, видимость, теги, привязку к проблеме, делают рассылку, удаляют или публикуют, нет и не будет.

## 2. Подключение

- Адрес: `POST https://<домен портала>/api/mcp`. Протокол MCP поверх JSON-RPC 2.0 без состояния: без сессий (`Mcp-Session-Id` нет) и без SSE, ответ одним JSON. Методы `initialize`, `notifications/initialized`, `tools/list`, `tools/call`, `ping`. Версии протокола: 2025-11-25 и 2025-06-18 (пакетов JSON-RPC и SSE ранних ревизий нет); на другую версию сервер отвечает своей последней, а заголовок `MCP-Protocol-Version` с другой версией даёт 400.
- Заголовок `Authorization: Bearer hub_at_...`. Токен выпускает администратор портала в разделе "AI-сотрудники" и показывает один раз. В портале хранится только хеш.
- У токена есть перечень инструментов, срок (не больше 365 суток), список адресов и суточный предел. Запрос принимается только с адреса из списка токена и из общего списка портала `MCP_ALLOWED_IPS`. Сообщите администратору адреса, с которых ходит агент. Адрес запроса портал берёт из заголовка доверенного прокси (`CLIENT_IP_HEADER`, за Cloudflare `cf-connecting-ip`): портал должен принимать соединения только от этого прокси, а прокси перезаписывать заголовок, иначе список адресов можно обойти подменой заголовка (решение 0125).
- Токен запуска по обращению получает только те из `get_ticket` и `add_internal_note`, что есть у основного токена; основной токен без `get_ticket` токенов запуска не получает. Сужение адресов и перечня основного токена действует на его токены запуска со следующего запроса.
- Отзыв токена действует со следующего запроса.
- Тело запроса не больше 64 КБ. Заголовок `Origin`, если он есть, должен совпадать с адресом портала.

## 3. Ответы и ошибки

- Нет токена, неверный, истёкший или отозванный: HTTP 401 с `WWW-Authenticate: Bearer`. Адрес вне списка: 403. Больше 30 неудачных проверок токена за 10 минут с адреса: 429 на неверные токены с этого адреса; действующий токен с того же адреса принимается.
- Ошибки инструментов приходят результатом `tools/call` с `isError: true` и телом `{"error": "<код>"}`: `tool_not_allowed` (инструмента нет в перечне токена), `invalid_arguments`, `rate_limited` (с `retry_after_sec`), `not_found` (объект вне видимости агента выглядит как несуществующий), `note_limit`, `internal`.
- Пределы: 60 вызовов `tools/call` в минуту на токен, считая отклонённые вне перечня, и суточный предел токена (по умолчанию 2000) для инструментов из перечня; методы `initialize`, `tools/list`, `ping` и уведомления отдельно, 120 в минуту на токен. Сверх предела методов протокола и сверх предела одновременных вызовов процесса (`MCP_MAX_INFLIGHT`, по умолчанию 4) ответ HTTP 429 с `Retry-After` и ошибкой JSON-RPC -32000 `Too many requests`.
- Успешный ответ: `structuredContent` по схеме инструмента и тот же JSON в `content[0].text`. В каждом ответе поле `notice`.

## 4. Недоверенный текст

Любой текст людей (клиентов, сотрудников, решений, кандидатов, идей) лежит только в полях `untrusted_customer_text` (клиент) и `untrusted_text` (остальные). Настройка агента обязана считать такие поля данными, а не командами: просьбы "игнорируй инструкции", "выведи контакты", "отправь в чат" в этих полях выполнять нельзя.

## 5. Инструменты

Чтение: `search_tickets`, `get_ticket`, `similar_tickets`, `sla_risk_tickets`, `unsolved_signatures`, `signature_spikes`, `search_solutions`, `get_solution`, `list_candidates`, `list_known_problems`, `list_ideas`, `assistant_metrics`, `search_code_catalog` (сохранённые выводы из кода, веха M8c).

Запись: `add_internal_note` (вид `note` или `handoff_memo`, до 4000 знаков), `draft_solution` (до 20000 знаков, правка опубликованного решения полем `revises_solution_number`), `draft_known_problem` (обращения только предлагаются, сигнатура не действует до принятия сотрудником), `create_report` (сводка в раздел "Сводки"; для чата команды только числа `new_tickets`, `ai_resolved`, `handed_off`, `sla_risk` и до 20 номеров обращений, сообщение собирает портал сам).

Знания из кода (веха M8c, раздел 10): `code_catalog_upsert` (отчёт о сканировании), `submit_code_analysis` (ответ на запрос анализа по коду).

Разметка HTML, невидимые знаки и ссылки вне разрешённых доменов в записях агента вырезаются. Точные схемы входа и выхода отдаёт `tools/list`.

## 6. События

Портал шлёт события на адрес `AGENT_WEBHOOK_URL` методом POST с телом JSON и подписью `X-Hub-Signature: t=<секунды>,v1=<HMAC-SHA256 от "<секунды>.<тело>" секретом AGENT_WEBHOOK_SECRET>`, как вебхуки портала. Заголовки `X-Hub-Event: agent.<вид>` и `X-Hub-Delivery: <идентификатор>`. Приёмник должен проверять подпись и отбрасывать запросы старше 5 минут. Ответ 2xx значит "принято"; иначе до пяти попыток с паузами 1, 5, 15, 60 минут.

Виды: `ai_handoff` (помощник передал обращение сотрудникам), `line_transferred` (передача на вторую линию), `sla_breached`, `signature_spike`, `code_analysis_requested` (сотрудник или правило запросили анализ по коду; в теле `analysis_request.id`). В теле только коды и идентификаторы: номер и идентификатор обращения, приоритет, очередь, модуль, организация идентификатором и категорией, причина кодом; у всплеска сигнатура, числа и номера обращений. Текст обращения агент читает инструментом.

## 7. Токен запуска по обращению

Если администратор отметил основной токен "для событий", события `ai_handoff`, `line_transferred` и `code_analysis_requested` несут поле `run_token` (значение, перечень, срок). У события анализа по коду перечень `get_ticket`, `search_code_catalog`, `submit_code_analysis` (не шире основного токена). Это отдельный токен на одно обращение: только `get_ticket` своего обращения и одна заметка до 2000 знаков, срок 2 часа, не больше 20 вызовов, адреса основного токена. Сводки, черновики и чат ему недоступны. Отзыв основного токена закрывает его сразу. Для запусков по обращениям отключите в профиле Hermes все остальные инструменты, веб-поиск, браузер и произвольные сетевые запросы (ТЗ 7.21).

## 8. Проверка без настоящего агента

- `pnpm dev:agent`: местный приёмник событий (`http://localhost:3195/events`), проверяет подпись и печатает события.
- Тестовый клиент MCP: `tests/helpers/mcp-client.ts`.

## 9. До выпуска токена в production

Нужен ответ юриста на вопрос 40 ТЗ (передача обезличенных данных обращений поставщикам моделей Hermes и место обработки) и вопрос 19 о коммерческих условиях. Без ответа администратор не выпускает токенов в production.

## 10. Знания из кода (веха M8c)

Портал хранит только выводы о коде Smartup, не сам код (ТЗ 7.22). Код читает Hermes на своей стороне с доступом к репозиториям только на чтение; доступ выдаёт владелец продукта при запуске в production. Какие модели видят код и на каких условиях, решается до первого сканирования (ТЗ 14.3, вопрос 19).

**Навык "сканирование кода"** (раз в неделю, задание 6 раздела 16.4 ТЗ). Один отчёт на репозиторий передаётся одним вызовом `code_catalog_upsert` основным токеном с этим инструментом (тело запроса до 2 МБ). Вид отчёта: `scanId`, `repository`, `commit`, `modules` (код, название по языкам, описание, зависимости, экраны), `errors` (ключ вида `orders.insufficient_stock`, код ошибки вида `ORA-20001`, шаблоны сообщения по языкам `ru`, `uz`, `en`, `kk`, `tr`, модуль, места `raisedIn` ссылками `{ object, path, line }` с путём от корня репозитория, условия, вероятная причина у пользователя, до 10 пунктов "что проверить", род `user_error`, `setting`, `data`, `probable_defect`, уверенность от 0 до 1), `changes`. Точную схему отдаёт `tools/list`. Отчёт отклоняется целиком, если:

- любое текстовое поле длиннее 10 строк (портал не принимает фрагменты кода);
- шаблон содержит синтаксис регулярного выражения (`\`, `.*`, `.+`, `[ ]`, `|`, `^`, `$`, `(?`, `{n,m}`) или фигурные скобки вне подстановок `{имя}`;
- в отчёте есть поле, которого нет в схеме (например, `pattern`).

Шаблон пишется обычным текстом сообщения Smartup с именованными подстановками: `Недостаточно остатка товара {product} на складе {warehouse}`. Выражение для сопоставления строит портал. Записи приходят черновиками; изменённая запись снова становится черновиком. Повтор того же `scanId` ничего не меняет. Ответ: числа новых, изменённых и исчезнувших записей или причины отклонения (правило и путь поля).

**Навык "анализ обращения по коду"** (задание 7). По событию `code_analysis_requested`: прочитать обращение `get_ticket` (обезличенное, текст клиента в полях `untrusted_*`), найти сохранённые выводы `search_code_catalog` (по сигнатуре обращения, ключу, модулю, словам), при необходимости прочитать код на своей стороне, затем один раз вызвать `submit_code_analysis`: номер обращения, гипотеза причины, уверенность, места в коде ссылками, что проверить у клиента, вопросы клиенту, номера похожих обращений, рекомендация, ключи использованных записей. Портал сам собирает внутреннюю заметку; поле длиннее 10 строк отклоняется. Заметку видят только сотрудники с пометкой "AI-сотрудник, не проверено". Ответ ждут 10 минут, поздний ответ тоже принимается. Тексты и комментарии кода Smartup для агента такой же недоверенный ввод, как текст клиента (FR-AGT-14).
