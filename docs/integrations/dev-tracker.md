## Режимы

| `DEV_TRACKER` | Поведение |
|---|---|
| `manual` (по умолчанию) | Сотрудник вводит номер, ссылку и название задачи, статус задачи меняет сам. Портал никуда не обращается |
| `smartup` | Портал создаёт задачу через API, статус получает вебхуком и опросом раз в 15 минут |

Переменные режима `smartup` (обязательны все три, проверяет `src/env.ts`):

| Переменная | Что это |
|---|---|
| `DEV_TRACKER_URL` | Адрес API без косой черты в конце, например `https://tasks.smartup.example/api/v1`. Только https; http только для localhost, когда сам портал работает на localhost |
| `DEV_TRACKER_TOKEN` | Токен портала в таск-менеджере. Уходит заголовком `Authorization: Bearer` |
| `DEV_TRACKER_WEBHOOK_SECRET` | Общий секрет подписи вебхука, не короче 32 знаков |

## Запросы портала к таск-менеджеру

Все запросы идут через защищённый сетевой слой `src/security/outbound.ts`: только https, только внешние адреса (имя узла проверяется при соединении), переадресации не выполняются, на ответ 10 секунд.

### Создать задачу

```
POST {DEV_TRACKER_URL}/tasks
Authorization: Bearer {DEV_TRACKER_TOKEN}
Content-Type: application/json

{
  "title": "Не проводится накладная",
  "descriptionMd": "Текст описания обращения\n\nОбращение в портале: https://hub.smartup24.com/ru/agent/tickets/SUP-1047",
  "kind": "bug",
  "priority": "p1",
  "moduleCode": "wms",
  "sourceUrl": "https://hub.smartup24.com/ru/agent/tickets/SUP-1047"
}
```

Ответ `200` или `201`: `{ "ref": "DEV-1204", "url": "https://tasks.smartup.example/tasks/DEV-1204" }`.

| Поле | Откуда |
|---|---|
| `title` | Тема обращения |
| `descriptionMd` | Описание обращения и ссылка на обращение в портале. Вложений и переписки нет |
| `kind` | `bug` для обращения типа "ошибка", иначе `feature` |
| `priority` | Приоритет обращения: `p1`..`p4` |
| `moduleCode` | Код модуля продукта из справочника портала, если модуль указан |
| `sourceUrl` | Адрес обращения в рабочем месте сотрудника |

В таск-менеджер уходит текст клиента (тема и описание). Это внутренняя система Smartup, и ТЗ этого требует (FR-DEV-03).

### Прочитать задачу

```
GET {DEV_TRACKER_URL}/tasks/{ref}
Authorization: Bearer {DEV_TRACKER_TOKEN}
```

Ответ `200`: `{ "ref": "DEV-1204", "url": "...", "status": "in_progress", "version": "5.14.2" }`. `404`: задачи нет.

### Статусы

| Статус таск-менеджера | Статус в портале |
|---|---|
| `todo`, `open`, `new`, `backlog` | `todo` |
| `in_progress`, `doing`, `review`, `testing` | `in_progress` |
| `done`, `closed`, `released`, `resolved` | `done` |
| `cancelled`, `canceled`, `rejected`, `wont_fix` | `cancelled` |

Незнакомый статус ничего не меняет и пишется в журнал событием `devtask.unknown_status`. Сравнение без учёта регистра; пробел и дефис читаются как подчёркивание.

## Вебхук таск-менеджера порталу

```
POST {HUB_URL}/api/webhooks/tracker
Content-Type: application/json
X-Tracker-Timestamp: 1795000000
X-Tracker-Signature: sha256=<hex>

{ "event": "task.status_changed", "ref": "DEV-1204", "status": "done", "version": "5.14.2" }
```

Подпись: HMAC-SHA256 общим секретом от строки `<X-Tracker-Timestamp>.<тело запроса как пришло>`, шестнадцатеричная запись. Время в секундах Unix. Запрос старше или новее пяти минут отклоняется.

| Ответ | Когда |
|---|---|
| `200` | Принято. Тот же ответ, если задачи с таким номером портал не знает или статус незнаком: существование задач наружу не раскрывается |
| `400` | Тело не JSON или не по схеме |
| `401` | Нет подписи, подпись неверна или время вне окна |
| `404` | Портал работает в ручном режиме |
| `413` | Тело больше 16 КБ |
| `429` | Больше 600 запросов в минуту с одного адреса |

Повтор того же события ничего не меняет. Когда задача стала `done` или `cancelled`, исполнители привязанных обращений "В разработке" получают напоминание один раз; статус обращений не меняется (FR-DEV-05).

## Опрос

Задание `devtasks.sync` раз в 15 минут (только в режиме `smartup`) читает открытые задачи (`todo`, `in_progress`), которые не сверялись 15 минут, пачками до 200 за запуск. Сбой чтения одной задачи остальным не мешает; пять сбоев подряд останавливают запуск до следующего раза.

## Недоступный таск-менеджер

Передача в разработку завершается отказом "таск-менеджер не ответил", обращение не меняется, сотрудник повторяет действие позже. Порядок: сначала создаётся задача в таск-менеджере, затем одной транзакцией привязка и статус обращения. Если транзакция не прошла после создания задачи, номер "осиротевшей" задачи пишется в журнал событием `devtask.orphan`.

## Что подтвердить у разработчиков Smartup

1. Адреса и методы: создание задачи и чтение по номеру. Есть ли поиск задачи по ссылке на обращение (тогда повтор после сбоя не создаст вторую задачу).
2. Способ входа: постоянный токен `Bearer` или иной (OAuth, подпись запроса). Как токен отзывается и заменяется.
3. Поля создания: названия, обязательность, допустимые значения типа и приоритета, справочник кодов модулей (совпадает ли с кодами портала).
4. Что возвращает создание: номер и адрес задачи для человека.
5. Перечень статусов задачи и как узнать версию с исправлением.
6. Вебхук: есть ли он, какие события, заголовки и формула подписи, входит ли время в подпись, повторяет ли таск-менеджер доставку при ошибке.
7. Ограничения частоты запросов и допустимый размер описания.
8. С каких адресов приходит вебхук и доступен ли API из сети портала.

## Локальная проверка

```
pnpm dev:tracker
```

Ложный сервер слушает `http://localhost:3194`. В `.env`: `DEV_TRACKER=smartup`, `DEV_TRACKER_URL=http://localhost:3194`, `DEV_TRACKER_TOKEN` и `DEV_TRACKER_WEBHOOK_SECRET` со значениями, с которыми запущен ложный сервер (по умолчанию названы в начале `scripts/mock-tracker.mjs`). Сменить статус задачи и послать вебхук порталу:

```
curl -X POST http://localhost:3194/__tasks/DEV-1001/status -H 'content-type: application/json' -d '{"status":"done","version":"5.14.2","notify":true}'
```

Браузерные тесты идут в ручном режиме.
