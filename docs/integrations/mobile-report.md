# Пункт "Сообщить о проблеме" в мобильном приложении Smartup

Памятка для разработчиков мобильного приложения Smartup (ТЗ 11.9, FR-WG-08; раздел 17, задача 7; план M6, задача 7). Страница портала готова, от приложения нужны пункт меню и выпуск токена контекста.

## Что сделать в приложении

1. Пункт "Сообщить о проблеме" (или "Помощь") в меню.
2. По нажатию приложение просит у своего сервера Smartup токен контекста текущего пользователя: тот же JWT, что для виджета в Smartup Web (ТЗ 11.4), с полем `platform` = `android` или `ios`. Токен действует не больше 5 минут и одноразовый: на каждое открытие нужен новый.
3. Приложение открывает во встроенном браузере адрес

   ```
   https://<адрес портала>/<язык>/m/report#ctx=<токен контекста>
   ```

   `<язык>`: `ru`, `uz` или `en`, язык интерфейса приложения. Токен стоит после `#`: эта часть адреса не уходит на сервер и не попадает в журналы.
4. Закрывает страницу кнопкой самого приложения: своей кнопки "Закрыть" у страницы нет.

## Что делает страница

- Сразу, до первого запроса, убирает `#ctx=...` из адреса и истории, меняет токен контекста на токен виджета на 15 минут и держит его только в памяти. Кук нет, вход в портал не нужен.
- Показывает "Сообщить об ошибке": описание, модуль, скриншот из галереи или камеры, затем "Мои обращения" и страницу обращения с перепиской и ответом.
- Обращение получает источник "мобильное приложение" (`widget_mobile`) по полю `platform` токена.
- Отвечает без заголовка `Referer` и не открывается внутри чужой страницы.

## Ограничения

- После перезагрузки страницы, через 15 минут и при отклонённом токене страница просит открыть её заново из приложения: продлить токен ей некому. Приложению достаточно снова выполнить шаги 2 и 3.
- Тот же токен второй раз не принимается.
- Ссылка "Открыть в портале" на странице обращения открывает портал с обычным входом: встроенный браузер может открыть её во внешнем браузере.
- Встроенному браузеру нужны JavaScript и доступ к адресу портала. Куки третьих сторон не нужны.
