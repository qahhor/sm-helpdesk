# Smartup Hub: соглашение об именах

Статус: принято. Владелец продукта подтвердил 11 префиксов модулей 20.11.2026. Вносится в версию 1.1 ТЗ.
Образец: Biruni, `ai-context/standards/` (01 архитектура модулей, 02 база данных, 03 стиль кода) и исходники `main/oracle/module/`.

В тексте ТЗ таблицы названы логическими именами (`tickets`, `kb_articles`). Правило записано в разделе 10.1 ТЗ версии 1.1 (решение 91). Физическое имя в базе строится по этому соглашению. Соответствие для каждой вехи записывается в её плане.

## 1. Префикс модуля

Имя таблицы: `{префикс модуля}_{название во множественном числе}`. Префикс: буквы проекта `hd` и одна буква модуля, как в Biruni (буква проекта плюс мнемоника, всего 2-4 знака).

| Префикс | Модуль | Каталог кода | Что в нём | Примеры |
|---|---|---|---|---|
| `hdc` | core, ядро | `src/modules/hdc` | настройки, журнал аудита, события, ограничения частоты | `hdc_settings`, `hdc_audit_log`, `hdc_domain_events` |
| `hdu` | users, идентичность | `src/modules/hdu` | серверы Smartup, организации, членство, сотрудники, приглашения, привязки каналов | `hdu_servers`, `hdu_organizations`, `hdu_memberships`, `hdu_staff` |
| `hdr` | references, справочники | `src/modules/hdr` | модули продукта, SLA, календари, шаблоны ответов, памятки, теги | `hdr_product_modules`, `hdr_sla_policies` |
| `hdt` | tickets, обращения | `src/modules/hdt` | обращения, сообщения, события, вложения, передачи между линиями | `hdt_tickets`, `hdt_messages`, `hdt_attachments` |
| `hdk` | knowledge, знания | `src/modules/hdk` | статьи и решения, версии, переводы, сигнатуры ошибок, поисковый индекс | `hdk_articles`, `hdk_published`, `hdk_error_signatures` |
| `hdi` | ideas, идеи | `src/modules/hdi` | идеи, голоса, комментарии, отбор месяца | `hdi_ideas`, `hdi_votes`, `hdi_cycles` |
| `hdn` | notifications, уведомления | `src/modules/hdn` | уведомления, очередь исходящих, входящая почта | `hdn_notifications`, `hdn_outbox`, `hdn_email_inbound` |
| `hdp` | problems, известные проблемы | `src/modules/hdp` | известные проблемы, рассылки, объявления | `hdp_problems`, `hdp_broadcasts`, `hdp_announcements` |
| `hda` | AI | `src/modules/hda` | вызовы модели, разбор, кандидаты, токены AI-сотрудников, знания из кода | `hda_runs`, `hda_triage_suggestions`, `hda_agent_tokens` |
| `hdw` | workflow, автоматизация | `src/modules/hdw` | правила, макросы, вебхуки, задачи разработки | `hdw_rules`, `hdw_macros`, `hdw_dev_tasks` |
| `hdh` | channels, каналы (этап 3) | `src/modules/hdh` | аккаунты каналов, диалоги, звонки | `hdh_accounts`, `hdh_threads`, `hdh_calls` |

Таблицы библиотеки аутентификации Better Auth лежат в отдельной схеме `auth` под именами библиотеки.

## 2. Таблицы

- Строчные буквы, `snake_case`, английский язык, множественное число.
- Связующая таблица: `{префикс}_{родитель}_{потомки}`, например `hdt_ticket_watchers`, `hdt_ticket_tags`.
- Подчинённая таблица: `{родитель}_{детали}`, например `hdk_article_versions`.
- История: окончание `_history`. Настройки: окончание `_settings`. Справочник видов: `_types` или `_kinds`.
- У каждой таблицы и колонки есть комментарий `COMMENT ON`.

## 3. Колонки

- Первичный ключ: `{сущность}_id` (`ticket_id`, `article_id`), тип `uuid`, значение `uuidv7()`. Внешний ключ носит то же имя, что и ключ цели, либо имя роли (`assignee_id`, `parent_id`).
- Порядок колонок: `org_id`, первичный ключ, внешние ключи, данные, `state`, `code`, `pcode`, служебные.
- Арендатор: `org_id` первой колонкой во всех таблицах с данными клиента.
- `state`: активна или отключена запись. `status`: шаг процесса (статус обращения). Вид записи: `{что}_kind`.
- Логические колонки: тип `boolean`, имя с `is_` (`is_internal`, `is_active`).
- Служебные: `created_by`, `created_on`, `modified_by`, `modified_on`. Момент времени оканчивается на `_on` (`closed_on`, `first_response_due_on`), тип `timestamptz`.
- Порядок: `order_no`. Код и название: `code`, `name`. Запись, поставленная с системой и не удаляемая: `pcode`.

## 4. Ограничения, индексы, последовательности, триггеры

| Объект | Имя | Пример |
|---|---|---|
| Первичный ключ | `{таблица}_pk` | `hdt_tickets_pk` |
| Внешний ключ | `{таблица}_f1`, `_f2` | `hdt_messages_f1` |
| Уникальность | `{таблица}_u1`, `_u2` | `hdr_product_modules_u1` |
| Проверка | `{таблица}_c1`, `_c2` | `hdt_tickets_c1` |
| Индекс | `{таблица}_i1`, `_i2` | `hdt_tickets_i1` |
| Последовательность | `{таблица}_sq` | `hdt_tickets_sq` |
| Триггер | `t_{таблица}_{назначение}` | `t_hdi_votes_count` |
| Политика RLS | `{таблица}_{актор}_{действие}` | `hdt_tickets_client_select` |

Каждая колонка внешнего ключа получает индекс.

## 5. Код модуля

Слои как в Biruni: вызовы идут сверху вниз, `util` не меняет данные.

| Файл | Роль | В Biruni |
|---|---|---|
| `api.ts` | Точки входа модуля: проверка актора, прав и данных | `{prefix}_api` |
| `core.ts` | Операции с данными внутри `withActor` | `{prefix}_core` |
| `util.ts` | Чистые функции без обращения к базе | `{prefix}_util` |
| `pref.ts` | Константы и коды | `{prefix}_pref` |
| `error.ts` | Ошибки модуля | `{prefix}_error` |
| `schema.ts` | Описание таблиц Drizzle | `setup/{prefix}_table.sql` |

Миграции: `drizzle/NNNN_{префикс}_{что}.sql`, например `0002_hdr_hdc_tables.sql`.

## 6. Что из Biruni не переносится и почему

| Правило Biruni | В портале | Причина |
|---|---|---|
| Числовой ключ `number(20)` и последовательности | `uuid` и `uuidv7()` | Решение ТЗ, раздел 10.2. Последовательности остаются только для номеров `SUP-1042` |
| Однобуквенные коды `'A'/'P'`, `'Y'/'N'` | Слова (`active`, `in_progress`) и тип `boolean` | В PostgreSQL и TypeScript читаемые значения проверяются типами |
| Запрет `DEFAULT` в колонках | `DEFAULT` разрешён | Значения `uuidv7()` и `now()` задаёт база |
| Таблицы аудита `X_` и триггеры `Y_` | Одна таблица `hdc_audit_log` | Решение ТЗ, раздел 14.3 |
| Изоляция фильтром `company_id` в каждом запросе | Политики RLS по `org_id` | Решение ТЗ, раздел 10.3 |

## 7. Что остаётся под именем hub

Название продукта, адрес `hub.smartup24.com`, переменные окружения `HUB_*` и роли базы `hub_owner`, `hub_app`, `hub_auth` не меняются: это имена развёртывания, а не объекты предметной области.
