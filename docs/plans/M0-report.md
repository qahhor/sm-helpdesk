### Критерии готовности

1. Запуск одной командой: `pnpm install && pnpm dev:up`. `/api/ready` отвечает `{"status":"ready","checks":{"db":"ok"}}`, адреса `/ru`, `/uz`, `/en` отвечают 200. Выполнено.
2. Полная цепочка проверок проходит. Выполнено.
3. Пробный четвёртый язык (казахский). Изменены два файла: `src/i18n/locales.ts` и новый `messages/kk.json`. Проверки и сборка прошли, `/kk` открылась, браузер с казахским языком перенаправлен на `/kk`. Изменения отменены. Выполнено.
4. Пробная замена палитры: правка двух значений слоя 1 меняет кнопку и шапку без правки экранов (тест `tests/e2e/acceptance.spec.ts`). Выполнено.

## Итоговая независимая проверка ветки

Ветку целиком проверил независимый ревьюер. Критичных дефектов нет. Важные замечания исправлены одним проходом, каждое сначала воспроизведено тестом.

| Замечание | Исправление |
|---|---|
| Параметр в адресе базы (`?user=postgres`) обходил проверку роли | Параметры адреса разрешены только по списку. Готовность отказывает, если приложение подключено не под `hub_app` или роль обходит RLS |
| Меню и нижний лист в кабинете клиента были 40 px и с текстом 14 px | Размеры зоны клиента действуют и на меню, и на нижний лист |
| Сломанная строка перевода показала бы имя ключа | Такая строка заменяется текстом запасного языка. Проверка ловит и лишние подстановки |
| Имя раздела вроде `/my-tickets` или `/sms` принималось за язык | Языком считается только правильно записанный код. Тест сверяет правило со всеми разделами портала |
| Проверка оформления пропускала стандартные цвета, тени и размеры Tailwind | Стандартные цвета, тени и скругления отключены, правило расширено, три места исправлены |
| Кнопка под указателем теряла контраст (4,03) | Кнопка темнеет, пара добавлена в проверку. Проверка падает, если не нашла тёмную тему |
| Проверка готовности при зависшей базе отнимала соединения у приложения | Не ответившее соединение закрывается |
| Портал можно было встроить в чужую страницу | Запрет встраивания действует сразу, не только в отчётах |
| Адрес с точкой шёл мимо прокси | Мимо прокси идут только `/api/`, `/_next/` и файлы интерфейса |
| Файл миграции с неверным именем молча пропускался | Запуск миграций останавливается |
| Вход действия "выбор языка" проверялся без Zod | Проверка через Zod, с пределом длины |

### Отложенные мелкие замечания

- Граница доступа к базе в линтере обходится динамическим импортом (данные защищает RLS).
- Проверка запрета кеша не видит настройку `fetch`, разбитую на несколько строк.
- Правила слов для клиента не применяются к новым пространствам сообщений автоматически.
- Тире в виде кода символа и тире в сообщениях коммитов не проверяются.
- При первом открытии меню фокус на мгновение теряется. Нет своей страницы ошибки (`error.tsx`).
- Английский сентябрь пишется "Sept".
- Окружение принимает пароль-заглушку `change-me-*` в production.
- `pnpm start` наследует переменную `HOSTNAME`. `pnpm dev:up` даёт невнятную ошибку, если том базы остался от другого `.env`.
- Политика чтения справочника принимает любой вид актора, кроме пустого. Служебные колонки пусты для фоновых задач и AI-сотрудника.
- Несколько тестов слабее своих названий. Тесты RLS лежат не в `tests/integration/isolation`, как сказано в `CLAUDE.md`.
- Витрина: подписи разделов на русском без перевода, значки 20 px вместо 24 px, вложенный `main`. У всех страниц один заголовок вкладки.
- Образы в `Dockerfile` и CI указаны по тегу, а не по хешу.

1. Подтвердить префиксы модулей из `docs/naming.md` (`hdc`, `hdu`, `hdr`, `hdt`, `hdk`, `hdi`, `hdn`, `hdp`, `hda`, `hdw`, `hdh`). Сейчас в базе две таблицы, переименование до M1 ничего не стоит.
