# Веха M0 "Каркас": план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** пустой, но боевой каркас портала: проект поднимается одной командой, CI зелёный, главная открывается на трёх языках, `/api/ready` проверяет базу (ТЗ, раздел 16.2, строка M0).

**Архитектура:** одно приложение Next.js (App Router, все страницы динамические, кеш компонентов выключен) и одна база PostgreSQL 18 с тремя ролями и принудительным RLS. Оформление задаётся токенами в три слоя из поставки Smartup Web. Две оболочки, кабинет клиента "сначала телефон" и рабочее место `/agent`, собираются из общих компонентов. Каждое правило ТЗ, которое может проверить машина, проверяет `pnpm check`.

**Стек:** Node.js 24, pnpm 12, Next.js 16.4.6, React 19.3, TypeScript 5.9 (strict), Tailwind CSS 4, shadcn/ui, next-intl 4.15, Zod 4, Drizzle ORM 0.45 с драйвером `pg`, PostgreSQL 18 с pgvector 0.8.7, Vitest 5, Playwright 1.63, Testcontainers 12, Docker Compose, GitHub Actions.

**ТЗ:** `docs/TZ.md` версии 1.0 от 20.11.2026. Разделы для этой вехи: 0-4, 7.11, 8.1, 8.2, 8.9, 8.11, 8.13, 9, 10.3, 10.5 (таблицы с вехой M0), 13.3, 13.5, 13.6, 14.4, 16. Бренд: `docs/brand/BRAND-GUIDE.md`. Образец оформления: `docs/design/` (токены из пакета для разработки, снимки поставки Smartup Web "Главная и навигация" от 14.11.2026).

## Предусловия

1. **Репозиторий.** Он закрыт, либо владелец подтвердил, что открыт намеренно. До этого коммиты остаются локальными: ТЗ, файлы бренда и код наружу не отправляются.
2. **Материалы.** Вне репозитория распакованы пакет для разработки `smartup-hub-handoff` версии 1.0 и поставка `smartup-web-home-handoff`.
3. **Среда.** Node.js 24.22.x и Docker. В облачной сессии сборки: служба Docker запускается командой `dockerd`, образы берутся с зеркала (`PG_IMAGE=mirror.gcr.io/pgvector/pgvector:pg18`), для Testcontainers задаётся `TESTCONTAINERS_RYUK_DISABLED=true`, Playwright использует уже установленный Chromium и браузеры не доустанавливает.

## Общие ограничения

Каждая задача неявно включает этот список. Значения взяты из ТЗ дословно.

- Next.js 16.4.x, не ниже 16.4.5. Берём 16.4.6. Node.js 24 LTS. TypeScript в строгом режиме.
- PostgreSQL 18, pgvector не ниже 0.8.7, pg_trgm. Drizzle ORM 0.45.x, ветку 1.0-rc не берём.
- `use cache` и `unstable_cache` не используются вообще. Все страницы портала динамические (раздел 9.4, правило 6).
- Прямой импорт клиента базы вне `src/db` и `src/modules` запрещён линтером (раздел 9.4, правило 2).
- Модули с секретами начинаются с `import 'server-only'` (раздел 9.4, правило 5).
- Все строки интерфейса лежат в `messages/*.json`. Строк в коде компонентов нет (FR-I18N-02).
- Языки при запуске: русский, узбекский (латиница), английский. Язык по умолчанию русский. Формат строк ICU MessageFormat.
- В компонентах нет цветов, размеров и радиусов числом, только токены (UX-S-01). Вёрстка использует логические свойства CSS (FR-I18N-09).
- Размеры рабочего места: шапка 52 px, строка таблицы 48 px, кнопка 40 px, поле 46 px. В кабинете клиента кнопки и поля не ниже 44 px, основной текст 16 px (UX-S-02).
- Точки перестройки раскладки: 600, 1024, 1200, 1280, 1440 px (UX-S-11).
- Контраст текста не ниже 4,5:1. Область нажатия в кабинете клиента не меньше 44×44 px. Цвет не единственный носитель смысла.
- Шрифт Montserrat с насыщенностью 400, 500, 600, 700 берётся из файлов пакета бренда и раздаётся самим порталом, а не внешним сервером (UX-S-16, UX-B-11).
- Теза и логотип нельзя рисовать и менять. Только файлы из `docs/brand/` через компоненты `TezMark` и `Logo`. Теза нельзя зеркалить, перекрашивать и поворачивать. Меньше 16 px он не ставится. Вокруг него охранное поле в 1/6 размера.
- Символы U+2014 и U+2013 запрещены в документах, комментариях, сообщениях коммитов и текстах интерфейса. `pnpm check` падает, если находит их.
- Запрещённые слова: "dala" и "дала" в узбекских строках, "Smartup ERP", "точно" и "гарантированно" в обещаниях (UX-B-06). Словарь интерфейса из раздела 8.11.
- Бюджеты: скрипты первого экрана клиента не больше 170 КБ в сжатом виде, Lighthouse по скорости не ниже 85 и по доступности не ниже 95, ноль серьёзных замечаний axe (раздел 8.9).
- Каждая таблица предметной области имеет `ENABLE` и `FORCE ROW LEVEL SECURITY` и строку в тестах (раздел 10.3).
- Роли базы: `hub_owner` только для миграций, `hub_app` без права обходить RLS, `hub_auth` для аутентификации.
- Секреты и файлы `.env` не коммитятся. `.env.example` содержит все имена без значений.
- Перед использованием API сторонней библиотеки сверка с документацией установленной версии. Для Next.js это `node_modules/next/dist/docs/`.

## На что смотреть при проверке

Пять случаев, которые ТЗ подразумевает, но прямо не описывает. Для каждого тест стоит в задаче, которая владеет кодом.

1. Неизвестный или искажённый язык в адресе и в заголовке браузера (`/de`, `/RU`, `Accept-Language: *`): пользователь попадает на язык по умолчанию или ближайший, а не на ошибку. Задача 6.
2. Длинные узбекские и английские строки на ширине 320-360 px: нет горизонтальной прокрутки, подписи не обрезаны. Задача 9.
3. База недоступна при старте или пропала позже: `/api/ready` отвечает 503 не дольше чем за 3 секунды, `/api/health` продолжает отвечать 200. Задача 5.
4. Переменная окружения задана, но неверна (адрес без схемы, подключение под суперпользователем, витрина включена в production): приложение не стартует, сообщение называет переменную и не печатает её значение. Задача 3.
5. Ключ перевода есть в русском, но отсутствует или сломан в узбекском: пользователь видит текст запасного языка, а не имя ключа, и CI падает. Задача 6.
