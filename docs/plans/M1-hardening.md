# Доработка после проверки main (вехи M0 и M1)

Дата: 21.11.2026. Основание: две независимые проверки `main` на коммите `82b1346` (безопасность; качество и контекст) и отложенные мелкие замечания итоговой проверки M1 (`M1-report.md`). Решение владельца 21.11.2026: исправить всё найденное. Работа идёт в ветке `claude/smartup-customer-portal-iszbit`, слияние в `main` по команде владельца.

Правило для каждого пункта, который меняет поведение: сначала тест, который падает, затем исправление, затем полный прогон.

## 1. Безопасность

| № | Что | Как |
|---|---|---|
| S1 | Сессия одного пароля даёт подбирать код второго фактора без ограничения | Шаг кода не принимается от сессии без отметки второго фактора у сотрудника с подключённым вторым фактором; после подключения остальные сессии завершаются; свой счётчик попыток кода; запись входа только при новой сессии |
| S2 | Подтверждение email не привязано к тому, кто его запросил | Подтверждает только вошедший владелец ссылки; страница называет учётную запись |
| S3 | Приглашение на существующую учётную запись работает как вход на 7 дней | Существующая учётная запись принимает приглашение только после обычного входа |
| S4 | Отключённый сервер Smartup не закрывает доступ его пользователям | Одно общее условие "кто входит как клиент", с состоянием сервера |
| S5 | В журнале аудита нет адреса у действий администратора, неудачные входы сотрудников не пишутся | Адрес запроса в контексте транзакции, база ставит его в журнал; запись неудачных входов |
| S6 | Адреса IPv6 в счётчиках целиком; общий офис упирается в предел начала входа | Группировка IPv6 по /64, предел начала входа пересмотрен |
| S7 | Кука сессии с приставкой `__Secure-`, а не `__Host-` | `__Host-`, если библиотека позволяет; иначе запись ограничения |
| S8 | Имя из Smartup без фильтра попадает в письмо приглашения | Длина, без ссылок и управляющих знаков, без имени в теме |
| S9 | У CSP в режиме отчётов нет адреса для отчётов | Обработчик отчётов и `report-uri` |
| S10 | Образ Docker: база по метке, файлы принадлежат пользователю процесса | Файлы принадлежат root, закрепление по digest, если доступно |
| S11 | Отложенные мелочи M1: повтор кода TOTP, счётчик адреса после предела IP, `constructor` в соответствии ролей, приглашённый гость, возврат отозванного приглашения, диапазоны IPv6 в защите от SSRF | По пунктам отчёта M1 |
