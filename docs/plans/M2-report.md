## Итоговая независимая проверка ветки

Проверяющий на самой сильной модели прочитал всю ветку (15 коммитов) против плана, ТЗ, `CLAUDE.md` и решений исполнителя. Вывод: "готово с исправлениями".

Исправлено, каждый пункт тестом, который сначала падал:

1. **Критичное: подмена файла во время проверки.** Ссылка на загрузку живёт 300 секунд, а файл читался дважды (для типа и для антивируса) и переносился без сверки версии. Загрузивший мог положить по той же ссылке другой файл того же размера, пока антивирус читал первый, и подменённый файл становился "чистым". Теперь тип, антивирус и хеш берутся из одного чтения, перенос идёт только с меткой этого чтения (ETag). Подменённый файл не переносится, задача проверяет его заново.
2. **Черновик стирался в момент отправки.** При обрыве сети, ошибке сервера или истёкшей сессии текст пропадал. Теперь черновик удаляется только после успеха, а отметка успеха убирается из адреса.
3. **Подписки коллег оставались на личном обращении**, хотя решение 17 плана требует их снимать. Возвращено правило плана: подписки коллег снимает фоновая роль сразу после смены видимости, политики не менялись.
4. **Законные файлы отклонялись и выглядели как "вирус":** журналы в UTF-16, файлы Office с паролем, PNG с расширением `.jpg`. Теперь они принимаются, а "не прошёл проверку на вирусы" и "не принят, приложите файл заново" подписаны по-разному.
5. **Проверка, которая никогда не проходит, повторялась бесконечно.** Проверяющий отнёс это к мелким, я повысил до важного: файл навсегда "проверялся", а обход каждую минуту гонял его через антивирус. Теперь через сутки файл получает `rejected` с отметкой `scan_failed`, а оператор видит строку в журнале.

Не исправлялось: миграция `0013`, её согласовал владелец (ниже).

Сырые невидимые знаки в исходниках и тестах заменены записью `\u....`: так их видно при чтении кода.

Не исправлялось, с причиной:
- **Подписка администратора клиента на ставшее личным обращение снимается**, как у коллеги. Проверяющий предлагал её оставлять, но это решение 17 утверждённого плана; владелец подтвердил его.
- **Совпадение MD5 в метке ETag.** Подменить файл так, чтобы MD5 совпал, а размер и тип прошли, на практике нельзя; сверка размера и типа остаётся.
- **Справочник модулей в браузерных тестах общий для всех прогонов.** Тесты от этого не падают; разделение отложено.
- **Очередь проверки файлов без справедливости по пользователям**: один клиент с 30 файлами в час не задерживает остальных заметно. Вернусь, если увидим очередь на staging.
- **Оценка из письма (веха M4)** должна учесть, что оценивает только автор.

- Письма по подпискам и фильтр "письмо только тому, кто видит обращение": M4.
- Ссылки без угловых скобок в Markdown: нужен пакет `remark-gfm`, он не согласован.

## Решения владельца

Получены 21.11.2026.

1. **Миграция `0013_attachment_sweep.sql`: согласована.** Неприкреплённые загрузки удаляются через сутки. Право есть только у системы и только для неприкреплённых строк старше суток (ограничивающая политика; тесты подтверждают, что клиент и сотрудник не удаляют ничего). Записано в решении 0028, пункт 7.
2. **Файлы с паролем: не принимаются.** Клиент видит "файл защищён паролем, приложите его без пароля". Решение 0027, пункт 20.
3. **Действия с обращением организации: подтверждено.** Подтверждают решение автор и администратор клиента, открыть снова может любой, кто видит обращение, оценивает только автор. Решение 0026, пункт 21.
4. **Подписка администратора клиента на ставшее личным обращение: снимается**, как у коллеги, по решению 17 плана. Решение 0026, пункт 25.

## Решения исполнителя по ходу работы

Каждое отступление от плана записано в журнале выполнения с ценой ошибки. Коротко:

- **Задача 1.** У дочерних таблиц `org_id` с составным внешним ключом вместо нового вида строки набора изоляции. В фикстуру добавлено личное обращение `aMine`. `docs/naming.md` не менялся. Последовательность номеров принадлежит колонке.
- **Задача 2.** Проверка модуля идёт через новый `hdr/api.ts`. Добавлены вид объекта аудита `ticket` и подписи действий.
- **Задача 3.** Курсор листания хранит время изменения текстом базы (микросекунды). Имена людей берутся из `hdu`, срок повторного открытия из настройки `hdc`.
- **Задача 4.** Решение оставить подписки на личном обращении отменено по итоговой проверке: теперь они снимаются, как в плане.
- **Задача 5.**
  - Отклонение загрузки идёт от системы и только для своей строки загрузившего.
  - Привычные браузеру варианты типа принимаются, в строку пишется тип по расширению.
  - Добавлена переменная `FILE_STORAGE_DIR`, ключ подписи локальной заглушки выводится из секрета сессий.
  - Обработчики принимают только JSON со страницы портала.
  - Отклонённые и заражённые файлы нельзя прикрепить.
- **Задача 6.**
  - Заражённые файлы пишутся в журнал аудита.
  - Чистым считается только файл, прочитанный целиком, в строку пишется SHA-256.
  - После любого обрыва повтор доводит проверку до итога.
  - Пропавшая строка для фонового процесса считается выполненной задачей.
- **Задача 7.**
  - Ошибка постановки задачи пишется в журнал и не роняет запрос.
  - Схема `pgboss` и права создаются миграцией 0012 и повторяются после установки pg-boss.
  - Миграция 0013 даёт право удалять неприкреплённые загрузки (согласовано владельцем 21.11.2026).
  - Обход ставит проверку снова только при наличии файла или через час.
  - Задачи вложений проверяют актора `system`.
  - Фоновый процесс берёт узкие файлы слоя api, иначе в сборку попадает Next.js.
  - ClamAV 1.5.5 закреплён по digest. С настоящим clamd клиент не проверялся.
- **Задача 8.** Ответ обработчика вынесен в чистую функцию ради тестов. Скачать можно только чистый, не внутренний и уже перенесённый файл, имя очищается от пути.
- **Задача 9.**
  - Подсказки в миграции `0014`.
  - Формы на `useActionState`, остальные действия обычными формами.
  - Подпись "Тема обращения", чтобы не совпадать с кнопкой темы оформления.
  - Черновик подставляется после гидратации.
  - Тема считается одной функцией на сервере и в браузере.
  - `blob:` в `img-src` для миниатюр.
  - Ссылки без скобок не становятся ссылками.
  - Тестовые настройки фонового процесса и хранилища для браузерных тестов.
  - На главной три последних своих обращения.
- **Задача 10.** Политики справочника не ослаблялись: команда работает от имени указанного администратора. Номер ошибки дан и записью, и строкой файла. Вид объекта аудита `module`.
- **Задача 11.** Миграция права очистки получила номер 0015. Политики ограничивающие, иначе система могла бы удалять и непросроченные строки. Итог очистки печатает и ссылки с кодами.
- **Задача 12.** Lighthouse только для страницы входа, страницу нового обращения покрывают замер скриптов и axe. Поле "Модуль" получило поиск по названию и недавние значения позже, при разборе отложенных замечаний.
