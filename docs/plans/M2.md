# Веха M2 "Обращения клиента": план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** клиент сообщает о проблеме на портале и ведёт своё обращение: создаёт его с файлами, видит список и переписку, отвечает, подтверждает решение, открывает заново, ставит оценку, выбирает, кто видит обращение. Чужое обращение и непроверенный файл не отдаются даже при ошибке в коде (ТЗ, раздел 16.2, строка M2: "Сценарий S2 проходит. Строки набора изоляции по обращениям, сообщениям и вложениям зелёные. Файл EICAR не скачивается").

**Архитектура:** новый модуль `hdt` (обращения) по образцу `hdu`: `api/` проверяет актора и данные, `core/` работает с базой внутри `withActor` под ролью `hub_app`, политики RLS повторяют правила сервиса. Файлы идут из браузера прямо в хранилище по подписанной ссылке, в папку карантина. Появляется фоновый процесс `worker` на pg-boss: он проверяет файл антивирусом и настоящий тип файла, только после этого файл можно скачать по ссылке на 60 секунд. Хранилище и антивирус сделаны интерфейсами с настоящей реализацией и заглушкой: локально проект по-прежнему запускается без внешних ключей.

**Стек:** как в M1 (Next.js 16.4.6, React 19.3.1, Drizzle ORM 0.45.4, `pg` 8.23.1, PostgreSQL 18, Zod 4.6.7, next-intl 4.15.1, Vitest, Playwright 1.63.0). Новые пакеты, требуют согласия (раздел "Что подтвердить"): `pg-boss` 12.38.2 (фоновые задачи, раздел 9.2 ТЗ), `react-markdown` 10.1.0 (вывод текста как Markdown без HTML, раздел 14.3), `aws4fetch` 1.0.20 (подпись запросов к R2 по SigV4, без зависимостей). Антивирус ClamAV подключается по его протоколу `INSTREAM` через `node:net`, без пакета.

**ТЗ:** `docs/TZ.md` версии 1.1 с правками от 21.11.2026. Разделы: 6 (S2), 7.2 (FR-TK-01..17), 8.3 (главная, новое обращение, страница обращения), 8.6 (UX-C-01..16), 9.1, 9.2, 10.1, 10.2 (`tickets`, `ticket_messages`), 10.3, 10.5 (`ticket_events`, `ticket_watchers`, `attachments`), 11.11 (`Storage`, `AntivirusScanner`), 12.1, 12.2 (`/api/uploads/*`, `/api/attachments/{id}`), 13.3, 13.5, 14.2 (T6), 14.3 (раздел "Файлы"), 14.5, 15.2, 15.3 (сценарий 1), 16.2. Имена объектов: `docs/naming.md`.

## Общие ограничения

Каждая задача неявно включает этот список. Значения взяты из ТЗ.

- Актор только из проверенной сессии. Организация обращения берётся из актора, поле организации во входных данных отбрасывается (раздел 11.1, CLAUDE.md).
- К базе только через `withActor` под `hub_app`. Модуль `hdt` берёт у других модулей только `api` и `pref` (правило линтера).
- Каждая точка входа: проверка сессии, прав и данных схемой Zod. Каждое изменение статуса и видимости: запись в `hdc_audit_log` в той же транзакции.
- Каждая новая таблица: `ENABLE` и `FORCE ROW LEVEL SECURITY`, политики руками, комментарий к таблице и каждой колонке, строка в `tests/integration/isolation/tables.ts`. Дочерние таблицы наследуют видимость через `EXISTS` по `hdt_tickets` (раздел 10.3).
- Клиент меняет обращение только именованными операциями: ответ, `confirmResolution`, `reopen`, `rate`, `setVisibility`, подписка. Каждая меняет фиксированный набор колонок. Приоритет, исполнителя, очередь и организацию клиент не меняет никогда (раздел 10.3).
- Внутренние заметки (`is_internal`) клиенту не видны никогда: ни в странице, ни в списке, ни в событиях, ни во вложениях (FR-TK-07).
- Типы: "Ошибка", "Вопрос", "Запрос на обслуживание" (`bug`, `question`, `service_request`). Влияние: "Работа остановлена", "Серьёзно мешает", "Неудобство", "Вопрос" (`blocker`, `major`, `minor`, `question`), из него приоритет `p1`..`p4` (FR-TK-01, FR-TK-03).
- Видимость: "Моя организация" (`org`, по умолчанию) или "Только я" (`private`). Личное обращение видят автор и администратор клиента (FR-TK-04, раздел 10.3).
- Номер вида `SUP-1042` (FR-TK-05).
- Статусы и переходы ровно по таблице раздела 7.2. Любой другой переход сервис отклоняет.
- Повторное открытие закрытого обращения в течение 14 дней, срок в настройке (FR-TK-12).
- Вложения: до 25 МБ на файл, MP4 до 50 МБ, до 10 файлов на сообщение (FR-TK-13). Загрузка по подписанной ссылке в карантин, ссылка 5 минут и фиксирует тип и размер. Имя файла в хранилище задаёт портал. Скачивание только после статуса "чист", ссылка 60 секунд с `Content-Disposition: attachment`. SVG и HTML никогда не показываются в браузере (раздел 14.3).
- Пределы: создание обращения 10 в час на пользователя, запрос ссылки на загрузку 30 в час на пользователя (раздел 14.5).
- Текст пользователя выводится как Markdown без HTML, ссылки с `rel="noopener noreferrer nofollow"`, картинок в тексте нет. Ответы с данными клиента: `Cache-Control: private, no-store`. `use cache` и `unstable_cache` запрещены.
- В текстах для клиента нет слов "тикет", "SLA", "эскалация", "очередь" (UX-C-13, проверка `pnpm check`). Строки только в `messages/*.json` на трёх языках. Цвета, размеры, радиусы только токенами.
- Новые пакеты: точная версия, опубликована не менее 7 дней назад, без сценариев установки (решение 98). Перед использованием API сверка с документацией установленной версии.
- Символы U+2014 и U+2013 запрещены везде.

## На что смотреть при проверке

Пять случаев, которые ТЗ подразумевает, но прямо не описывает. Тест каждого стоит в задаче, которая владеет кодом.

1. **Файл не тот, за кого себя выдаёт:** `report.pdf`, внутри которого HTML или исполняемый файл; картинка с подменённым типом; загрузка больше заявленного размера или после истечения ссылки. Файл не становится "чистым" и не скачивается. Задачи 5 и 6.
2. **Загрузка оборвалась или проверка не завершилась:** браузер закрыли после ссылки, но до "загрузка завершена"; фоновый процесс упал посреди проверки; ClamAV не отвечает. Файл остаётся "на проверке", не скачивается, через сутки неприкреплённая загрузка удаляется, а зависшая проверка повторяется. Задачи 6 и 7.
3. **Два действия над одним обращением одновременно:** клиент нажал "Решение подошло" в двух вкладках, или ответил, пока в другой вкладке открывал заново. Переход применяется один раз, второй получает понятный отказ, история не дублируется. Задача 4.
4. **Видимость меняется под ногами:** автор сделал обращение личным, пока коллега читал его или был подписан; участника отключили. Коллега теряет доступ на следующем запросе, подписка коллеги снимается. Задачи 3 и 4.
5. **Ссылка на обращение у коллеги или у чужого:** ссылку на номер открывает участник своей организации, участник другой организации, вышедший из системы человек. Своему открывается, чужому "не найдено" без подсказки, что номер существует, вышедшему вход и возврат на ту же страницу (UX-C-06, UX-C-11). Задачи 3 и 9.
