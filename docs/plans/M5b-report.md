# Отчёт по вехе M5b "AI первой линии и разбор"

Дата: 26.11.2026. Ветка `claude/smartup-customer-portal-iszbit`. План `docs/plans/M5b.md` подтверждён общим поручением владельца 26.11.2026. Решения вехи: `docs/decisions/0084`-`0095`. Журнал исполнителя: `.superpowers/sdd/M5b/progress.md`.

## Итог

Тез отвечает первым на обращения с портала, из виджета и из писем опознанных клиентов: опубликованным решением, одним уточняющим вопросом или передачей сотруднику со сроком ответа. Своего текста клиенту модель не пишет: вступления и вопросы выбираются по идентификаторам из `messages/*.json`, шаги берутся из `hdk_published`. Сотрудник видит "После AI" с причиной, блок AI с резюме рядом с исходным текстом и предложения разбора, отмечает неверные ответы, переводит сообщения клиента. Есть показатели помощника и проверочный набор с набором атак (`pnpm eval:ai`).

Всё сделано на заглушке модели с настоящей реализацией Anthropic за интерфейсом. С настоящим ключом ничего не проверено: ключа нет.

## Решения 1-24 плана для владельца

Все приняты по рекомендованному варианту; отклонения записаны в журнале (`Ruling:`) и в решениях 0084-0094. Главные отклонения:

1. Помощник включается отдельной системной транзакцией сразу после создания (триггер клиента не даёт иначе).
2. Передачи кодом (человек, тема, P1, язык, без текста) идут до модели; разбор для них отдельным вызовом `ai.triage`.
3. Найденные решения и комментарий к отметке хранятся в новых колонках `hda_runs.found` и `flag_comment`, отключение полей разбора в новой таблице `hda_triage_field_offs`.
4. Кнопки "Отклонить" у предложений нет; непринятое за 7 дней считается непринятым в доле FR-TRI-04.
5. `ai.min_score` остаётся 0: на синтетическом наборе ложных ответов нет уже при 0.
6. Прочая кириллица определяется как русский, просьба о человеке и обязательная тема проверяются до языка (найдено набором).
7. Перевод и уточнение благодарности требуют только AI-обработки организации; сообщения не меняются, список "Не открыли обращение" исключает сообщение по событию.
