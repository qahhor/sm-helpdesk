# Отчёт по вехе M8c "Знания из кода"

Дата: 27.11.2026. Ветка `claude/smartup-customer-portal-iszbit`. План `docs/plans/M8c.md` подтверждён общим распоряжением владельца 26.11.2026. Решения вехи: `docs/decisions/0126`-`0133`. Журнал исполнителя: `.superpowers/sdd/M8c/progress.md`.

## Итог

Hermes Agent передаёт порталу отчёт о сканировании кода Smartup инструментом сервера MCP `code_catalog_upsert`: карту модулей и экранов и каталог ошибок. Портал хранит только выводы: отчёт с полем длиннее 10 строк, с регулярным выражением в шаблоне или с лишним полем (например, `pattern`) отклоняется целиком, в истории остаётся строка с причинами без значений. Выражение для сопоставления строит база из текста шаблона с подстановками. Записи приходят черновиками в очередь "Знания из кода", новые и изменённые выделены; вторая линия, Customer Care и администратор утверждают, правят и отклоняют, заметки о модулях применяет к справочнику администратор. Утверждённый шаблон даёт точную сигнатуру: сигнатурой обращения становится ключ записи, во всех местах, где считается сигнатура (обращение, подсказка, виджет, баннер, привязка в редакторе). В обращении блок "Что известно по коду": у второй линии условия, что проверить, место в коде ссылкой, "Создать решение из записи" и "Разобрать по коду"; у первой линии только "Что проверить" утверждённых записей. Анализ идёт событием агенту с токеном запуска; ответ агента портал собирает во внутреннюю заметку с пометкой "AI-сотрудник, не проверено"; без ответа за 10 минут "анализ не выполнен". Анализ можно запускать правилом автоматизации. Клиент, AI-помощник и подсказка знаний из кода не видят: у клиента нет политик, система читает только функцию сигнатуры.

Всё проверено отчётом-примером и тестовым клиентом MCP. С настоящим Hermes Agent и настоящими репозиториями ничего не проверено.

## Независимая проверка

Проверка нашла 2 критические, 7 важных и 8 мелких находок. Исправлены все, кроме отложенных M6 и M8; M3 оставлено решением. Миграции `0122_hda_code_matching.sql`, `0123_hda_code_access.sql` (0118-0121 не менялись), решение `docs/decisions/0134-m8c-review-fixes.md`. Тест каждой находки написан до исправления и падал; исключения в журнале (строки `Ruling`).

**Критические.**
- **C1. Сопоставление с шаблонами не масштабировалось** (2000 шаблонов на 31 строку: 24 с, 10000: дольше предела запроса, без предела запросов у подсказки и баннера). Исправление: одна функция базы `app.hda_code_matches()` для сигнатуры и блока обращения; сначала статус и код, затем все буквальные слова шаблона (колонка `literals`), только потом выражение, каждый шаблон компилируется один раз; не больше 500 проверок и 300 мс, иначе сигнатура по 11.5; неверное выражение пропускается. Предел запросов подсказки в виджете и баннера проблемы проверяется до сигнатуры. Тесты: `hda-code-review` "C1: сигнатура по 10000 шаблонам (5000 утверждённых)..." (было 35,9 с, стало около 140 мс), `hdk-code-signature-limits` (два теста).
- **C2. Управляющий знак становился подстановкой.** Выражение строится разбиением по подстановкам, без знака-заместителя; управляющие, форматирующие знаки и разделители строк отклоняются в отчёте, правке и ответе анализа (`control_char`) и проверками базы `hda_code_error_templates_c3`, `hda_code_error_entries_c9`, `hda_code_module_notes_c6` (NOT VALID с подтверждением по прежним строкам); триггер компилирует выражение при записи шаблона. Тесты: `hda-code-review` "C2: управляющий знак не становится подстановкой...", `hda-code-report` "C2: ..." (два).

**Важные и мелкие (исправлены).**
- I1 правило 10 строк: любые переводы строки, строка до 300 знаков, эвристика `code_like`, очистка `stripInvisible` перед записью. Тесты `hda-code-report` "I1: ..." (три), `hda-code-review` "I1: база считает строки только по \n...".

- I3 токены запуска отзывали друг друга: колонка `purpose`. Тест "I3: ...".
- I4 истёкший запрос держал новые: истечение той же транзакцией, шаги минутной задачи независимы (`runJobSteps`). Тесты "I4: ...", `log.test` "runJobSteps" (два).
- I5 набор изоляции: общие проверки агента вернулись, явная таблица `CODE_AGENT` для каталога; таблицу запросов агент не читает, ответ функцией `app.hda_code_analysis_answer()` без `requested_by` и `org_id`. Тесты `registry`, `hda-agent-access`, `hda-code-access`, "I5: ...".

- I7 утверждение невиденного: версия записи в форме, `conflict` и сообщение об устаревшей странице. Тест "I7: ...".

## Долги и что не проверено

- Страница обращения сотрудника по-прежнему шире окна на 360 px и без блока (находка M8b вне вехи): сценарий S11 проверяет ширину самого блока на трёх ширинах и страницу на 1280.
- С настоящим Hermes Agent ничего не проверено; браузерный сценарий отвечает на анализ тестовым клиентом MCP основным токеном, доставку события проверяют интеграционные тесты.
- Решения и проблемы, привязанные к прежней сигнатуре 11.5 ошибки, после утверждения записи не совпадают с новыми обращениями: сотрудник перепривязывает или создаёт решение из записи (решение 0130).
- Изменённая утверждённая запись не даёт точной сигнатуры до повторного утверждения (решение 0128).
- Имена записи для проверки перед публикацией читаются правами сотрудника: у первой линии остаются общие правила (решение 0131).
- Порядок "сначала увидеть падение" нарушен для части тестов (строки `Ruling` журнала): модульные `hda-code-report`, `agent-nav`, тест сводки о сканировании в `hda-team-chat`, модульный тест строк для шаблонов; браузерные тесты вехи написаны по задачам, запущены в задаче 9.
- Долги M8b (отложенные мелкие находки M1, M4, M5, M7, M9, M11-M14) остаются с прежними причинами.
