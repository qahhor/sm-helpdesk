# Волна 0 плана оптимизации "Готовность к staging": план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** закрыть находки аудита, без которых портал нельзя показывать первому клиенту: второй слой изоляции в чтениях клиента, свежий вход для всех настроек администратора, журнал и сигналы дежурным, настройка базы, доступ только через Cloudflare, шифрованные копии с инструкциями, боевой режим политики содержимого.

**Источник:** `docs/audit/2026-11-23-technical-audit.md`, раздел 9, волна 0. Владелец поручил начать разработку по плану аудита без остановок 23.11.2026; отдельного подтверждения этого плана по его поручению не ждём.

**ТЗ:** `docs/TZ.md`, разделы 9.4, 13.3-13.8, 14.3, 14.4, 14.7.

## Что в волну не входит и почему

- **S1, включение GitHub Actions.** Проверки выключены решением владельца 0011. Файл `ci.yml` готов, включение ждёт решения владельца (вопрос 10 в `docs/HANDOFF.md`).
- **O4, staging.** Нужны сервер, Cloudflare и DNS. Всё, что зависит от кода и конфигурации, делается здесь; шаги для сервера остаются в `docs/runbooks/launch.md`.
- **Внешний сервис сбора ошибок.** Правило проекта требует согласования. Сигналы дежурным делаются средствами портала: письмо и чат дежурных.

## Общие ограничения

Правила `CLAUDE.md` и общие ограничения плана `docs/plans/M4b.md`. Дополнительно: новых пакетов нет; секреты, токены и тексты клиентов в журнал не попадают; каждая новая таблица получает RLS и строку в наборе изоляции.

### Task 3 (Задача 3): Журнал и измерения

**Files:** `src/lib/log.ts` (новый), `src/db/with-actor.ts`, `src/worker/main.ts`, `src/modules/hdn/core/outbox.ts`, `src/modules/hdt/core/housekeeping.ts`, замена `console.*`.

**Interfaces:** `log.info|warn|error(event: string, fields?: Record<string, unknown>)`: одна строка JSON с временем, уровнем, событием; поля с именами секретов вырезаются. `SLOW_TX_MS` (по умолчанию 250): транзакция дольше порога пишет `db.slow_tx`. ### Task 4 (Задача 4): Сигналы дежурным

**Files:** `drizzle/0041_ops_alerts.sql`, `src/modules/hdc/ops-watch.ts`, `src/modules/hdn` (отправка дежурным), `src/worker/main.ts`, `messages/*.json`, набор изоляции.

**Interfaces:** таблица `hdc_ops_alerts(code, last_sent_on, ...)`, только система. Задача `ops.watch` раз в 5 минут проверяет: упавшие задачи очереди за час, сообщения исходящих со статусом ошибки и задержку больше 5 минут, письма без разбора старше 15 минут, 20 и больше неудачных входов сотрудников за 15 минут, заражённые файлы за час. Сигнал уходит дежурным письмом и в чат, не чаще раза в час на вид.

- [ ] Падающие тесты на каждый вид сигнала, на предел раз в час, на отсутствие личных данных в тексте.
- [ ] Реализация, коммит `feat(ops): alerts to the on-call`.
