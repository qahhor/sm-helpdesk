# Волна 1 плана оптимизации "Запас по нагрузке и защите": план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** портал выдерживает рост до сотен организаций и сотен тысяч обращений без замедления очередей и фоновой задачи, а оставшиеся находки безопасности среднего и низкого уровня закрыты.

**Источник:** `docs/audit/2026-11-23-technical-audit.md`, раздел 9, волна 1. Владелец поручил вести разработку по плану аудита без остановок 23.11.2026.

**ТЗ:** `docs/TZ.md`, разделы 7.3, 9.4, 11.10, 13.3, 14.3, 14.5.

## Общие ограничения

Правила `CLAUDE.md`. Новых пакетов нет. Политики RLS не ослабляются. Каждый новый индекс проверяется планом запроса на наборе в 200 тысяч обращений. Каждая новая таблица: RLS и строка в наборе изоляции.

### Task 1 (Задача 1): Нагрузочный набор и тесты планов

**Files:** `tests/integration/helpers/bulk.ts`, `tests/integration/query-plans.test.ts`.

**Interfaces:** `seedBulkTickets(count: number, orgs: number): Promise<{ orgId: string; userId: string }>` заливает обращения одной командой под суперпользователем; `planOf(actor, sql): Promise<string>` возвращает план запроса под ролью приложения с настройками актора.

- [ ] Падающие тесты на 50 тысячах обращений: список клиента идёт по индексу организации (уже так после волны 0, тест закрепляет); счётчики очередей и первая страница очереди не делают полного просмотра таблицы; запросы задачи раз в минуту идут по индексам.
- [ ] Реализация в задачах 2-4; здесь только набор и закрепляющий тест списка клиента. Коммит `test: bulk data set and query plan checks`.

### Task 2 (Задача 2): Очереди сотрудника

**Files:** `src/modules/hdt/core/agent-queues.ts`, `src/modules/hdt/api/agent.ts`, `src/app/[locale]/(agent)/agent/queues/page.tsx`, `drizzle/0043_queue_indexes.sql`.

- [ ] Счётчики считаются только по открытым обращениям и по "Моим"; у очереди "Все" счётчика нет.
- [ ] Листание по ключу сортировки вместо OFFSET; "Отправить и к следующему" берёт следующее обращение одним запросом по ключу.
- [ ] Индексы под три сортировки открытых обращений.
- [ ] Тесты планов и поведения, коммит `perf(hdt): queue counters and keyset pagination`.

### Task 3 (Задача 3): Индексы задачи раз в минуту

**Files:** `drizzle/0043_queue_indexes.sql` (тот же файл), `src/modules/hdt/core/sla.ts`.

- [ ] Частичные индексы: отложенные (`snoozed_until`), решённые (`resolved_on`), неразобранные письма; запрос обновления сроков разбит на три запроса по индексам.
- [ ] Тесты планов, коммит `perf(hdt): indexes for the minute job`.

### Task 4 (Задача 4): Очередь исходящих и сроки хранения

**Files:** `drizzle/0044_retention.sql`, `src/modules/hdn/core/outbox.ts`, `src/modules/hdn/api/maintenance.ts`, `src/worker/main.ts`.

- [ ] Частичный индекс по сообщению для отметки "не доставлено".
- [ ] Ночная очистка: отправленные и пропущенные строки очереди старше 30 суток (текст письма в них больше не нужен), разобранные входящие письма старше 90 суток. Журнал аудита не чистится: срок его хранения решает владелец с юристом.
- [ ] Тесты, коммит `perf(hdn): undelivered index and retention`.

### Task 5 (Задача 5): Уведомления без вложенных транзакций

**Files:** `src/modules/hdt/core/notify.ts`, `src/modules/hdu/api/recipients.ts`, `src/modules/hdn/core/notifications.ts`, `src/modules/hdt/core/lines.ts`.

- [ ] Роли получателей и действие Telegram читаются одним запросом на всех получателей; имя сотрудника для события берётся до транзакции.
- [ ] Тест: событие с 20 наблюдателями делает не больше заданного числа транзакций. Коммит `perf(hdt): batched recipient lookups`.

### Task 6 (Задача 6): Настройки один раз на запрос

**Files:** `src/modules/hdc/settings.ts`, загрузчики страниц рабочего места.

- [ ] Чтение настройки запоминается на время одного запроса (не данные клиентов); счётчик транзакций на страницу обращения сотрудника падает с 15 до заданного предела.
- [ ] Тест с счётчиком транзакций, коммит `perf: settings once per request`.

### Task 7 (Задача 7): Замена ключей

**Files:** `src/security/secret-box.ts`, `src/modules/hdn/inbound/reply-address.ts`, `src/env.ts`, `src/cli/commands.ts`, `docs/runbooks/incident.md`.
