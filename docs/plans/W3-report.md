## Итоговая независимая проверка ветки

Проверяющий с отдельным контекстом прочитал план, решение 0040, журнал исполнителя и весь diff (9 коммитов, 59 файлов). Вердикт: "готово после исправлений". Критичных замечаний нет. Новая точка входа без сессии (оценка по ссылке) подделку подписи, чужое обращение, повторную оценку и гонку двух нажатий держит.

Важные замечания, исправлены:

1. **Пометка возврата оставалась навсегда у закрытых обращений.** Отложенное и затем решённое обращение получало пометку, которую некому снять. Теперь решённым и закрытым она не ставится и у них не показывается.
2. **Ссылку оценки видел сотрудник, если клиент переслал письмо о закрытии в поддержку.** По ней оценка ставится за автора без входа. Ссылки оценки во входящих письмах теперь скрываются.
3. **Не было теста, что проверка файла ставит время проверки.** Без этого сигнал дежурным о заражённых файлах мог молча перестать работать. Тест добавлен, индекс под новый счёт построен.
4. **Действие со старой страницы было проверено только в сервисе.** Добавлен сценарий в браузере.

Мелкие замечания, исправлены: ошибка сервера на ключе листания с невозможной датой; комментарий к оценке из пробелов давал "ссылка не подходит"; письмо о повторном закрытии оценённого обращения несло ссылки; команда бота после скобки в теме сообщения Telegram; два недостающих теста.

### Решения, принятые при выполнении

Все записаны в `docs/decisions/0040-partial-requirements.md`. Главные, с ценой:

- **Оценка из письма двумя нажатиями, а не одним.** Иначе оценку ставил бы почтовый сканер. Расхождение с текстом ТЗ: вопрос 21.
- **Оценка без входа от имени автора по подписи ссылки.** Кто получил пересланное письмо, может поставить оценку за автора: один раз, с записью адреса в журнале. Вопрос 21.
- **Страница оценки в группе страниц без входа, а не в `(public)`:** в `(public)` запрещён любой актор, кроме `public`.
- **У действий нет кнопки "выполнить всё равно":** страница после отказа свежая, повтор это одно нажатие.
- **Листание по ключу только у сортировки по последнему изменению.** Далёкие страницы "Все" по сроку по-прежнему со смещением.
- **Сигнал о заражённых файлах по новой колонке, а не по журналу аудита:** журнал читает только администратор, давать чтение системе значит менять политику.
- **Предел скриптов рабочего места 212 КБ** поставлен по замеру, а не взят из ТЗ.
- **Часть тестов написана до кода, но отдельно красной не запускалась** (не компилировалась без кода): пометка возврата, действия со старой страницы, листание по ключу, срок "взять в работу", оценка из письма. Проверяющий оценил именно их: тест действий честный, два пробела закрыты.

### Мелкие замечания: отложены

| Замечание | Почему отложено |
|---|---|
| Автор с выключенной почтой и Telegram не получает ссылок оценки | Нужна кнопка оценки в сообщении Telegram: отдельная задача. Оценка остаётся на странице обращения |
| Гость, ставший пользователем, по старой ссылке оценку не поставит | Редкий случай; подпись сделана на прежнего автора |
| Проверка версии не видит чужую смену приоритета и линии; при отказе причина приоритета теряется | Меняет сводку "что изменилось" и у ответа, и у действий |
| Правило базы для вставки клиентом не называет `snooze_returned_on` | Сервис колонку не задаёт; правка правила базы отдельной миграцией |
