# Волна 3 "Требования ТЗ, выполненные частично, и удобство рабочего места": план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** закрыть то, что ТЗ требует от уже сделанных вех, но сделано частично, и снять оставшиеся ограничения рабочего места сотрудника до пилота.

**Источник:** поручение владельца 24.11.2026 "создать план улучшения и улучшать". Состав взят из трёх перечней: строки "выполнено частично" в `docs/TZ-1.2-changes.md`, отложенные замечания в `docs/plans/W2-report.md` и решении 0039 (пункты 16 и 18), ограничения роста из решения 0038 (пункт 3) и раздела 4.3 аудита.

**ТЗ:** `docs/TZ.md`, разделы 7.2 (FR-TK-11), 7.3 (FR-AG-12, FR-AG-13), 7.19 (FR-LINE-06), 8.6 (UX-C-07), 8.7 (UX-A-06, UX-A-11), 14.3.

## Как выбирались задачи

Показатели пилота (раздел 16.7 ТЗ) считаются по оценкам клиентов и по срокам ответа. Поэтому первой идёт оценка из письма: без неё оценок будет мало, и показатель удовлетворённости пилота не на чем считать. Дальше то, что сотрудник видит каждый день, затем то, что мешает росту, в конце мелкие долги.

## Что в волну не входит

- **Поиск по тексту под политиками RLS** (вопрос 19 в `docs/HANDOFF.md`): исправление меняет порядок применения политик, нужно согласие владельца.
- **Скрытый текст в письмах** (FR-EM-15): решением отложен до M5b.
- **Привязка к известной проблеме** в массовых действиях (FR-AG-20): известные проблемы появляются в M5c.
- **Срок хранения и выгрузка журнала аудита, пакет `undici`, GitHub Actions, staging:** решения владельца.
- **Миграция 0048:** применённый файл не правится.

## Общие ограничения

Правила `CLAUDE.md`. Новых пакетов и внешних сервисов нет. Политики RLS не ослабляются. Каждая новая таблица: RLS и строка в наборе изоляции. Строки интерфейса только в `messages/*.json` на трёх языках. Для каждой задачи сначала падающий тест. Решения, которых нет в ТЗ: `docs/decisions/0040-partial-requirements.md`.

### Task 1 (Задача 1): Оценка из письма

**Files:** `src/modules/hdt/csat-link.ts` (подпись ссылки), `src/modules/hdt/api.ts`, `src/modules/hdt/core/actions.ts`, `src/modules/hdn/mail-text.ts` и шаблон письма "закрыто", `src/app/[locale]/(public)/rate/page.tsx` и действие, `messages/*.json`, `tests/unit/csat-link.test.ts`, `tests/integration/csat-link.test.ts`, `tests/e2e/tickets.spec.ts`.

**Interfaces:** `csatToken(ticketId: string, userId: string, secret: string): string`; `parseCsatToken(token: string, secrets: string[]): { ticketId: string; userId: string } | null`; `rateByLink(input: { token: string; score: number }): Promise<{ ok: true; number: number; needsReason: boolean } | { ok: false; code: 'link_invalid' | 'already_rated' | 'not_closed' }>`.

- [ ] Письмо о закрытии обращения автору несёт пять ссылок с оценками 1-5. Ссылка подписана ключом подписи адресов ответа (и прежним ключом при замене), привязана к обращению и автору, срок не нужен: оценка ставится один раз.
- [ ] Переход по ссылке ничего не меняет (почтовые сканеры открывают ссылки): страница показывает выбранную оценку и кнопку "Поставить оценку". Меняет данные только нажатие кнопки. Вход не нужен.
- [ ] Оценка ставится один раз и только у закрытого обращения, только за автора; при 1-3 страница предлагает причину из списка (вторая форма, та же подпись). Запись в журнал аудита в той же транзакции. Предел частоты на подпись.
- [ ] Страница в группе `(public)`: сессию не читает, актор `public` не используется для записи: запись идёт системным актором от имени автора из подписи. Текст обращения страница не показывает, только номер.
- [ ] Коммит `feat(hdt): rating from the email with one press`.
