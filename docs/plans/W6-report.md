## Замер на наборе пилота (миллион обращений, 21 300 строк идей, 3000 строк решений; машина разработчика, 4 ядра, Typesense и PostgreSQL на той же машине)

Два прогона `tests/perf/pilot-p95.test.ts`; второй после исправления счётчика при открытом выключателе. p95, мс:

| Что | PostgreSQL, прогон 1 / 2 | Typesense, прогон 1 / 2 | Цель |
|---|---|---|---|
| "Все" с текстом | 65,9 / 68,7 | 36,2 / 28,6 | 50: держится только на Typesense |
| Поиск клиента | 179,3 / 133,8 | 148,1 / 156,0 | 300: держится обоими |
| Поиск организаций | 8,2 / н. д. | 8,6 / 5,6 | 400 |
| Похожие идеи | 551 / 481,9 | 480,5 / 512,4 | 150: **не держится** |
| Подсказка, 50 в секунду | 13 536 (33,7 в секунду) / 1268 (48,2 в секунду) | 2370 / 6958 | 500: **не держится**; во втором прогоне путь Typesense медленнее PostgreSQL |
| Откат при недоступном Typesense, "Все" с текстом | цель: PostgreSQL плюс 2 | 69,3 / 64,0 | прогон 1 не держался (запись счётчика на каждый откат, исправлено), прогон 2 держится |
| Откат, поиск клиента | цель: PostgreSQL плюс 2 | 125,4 / 141,3 | прогон 2 на 5,5 мс выше цели; разброс прогонов этой строки 45 мс |

- Полная переиндексация миллиона обращений и остальных коллекций: 400 и 466 секунд. Память Typesense после заливки: 600 МБ (план считал 1,8-2,7 ГБ на описаниях по 400 знаков; в наборе описания короче). `TYPESENSE_MEM_LIMIT` оставлен 2560m до замера на настоящих текстах. Переписки в наборе почти нет (40 сообщений): память коллекции `hub_ticket_texts` этим замером не оценена.
- Похожие идеи: Typesense заменил только список слов; медленная часть это смысловой список pgvector под RLS на 21 300 строках. По плану это условие переноса векторов в Typesense; в этой волне не сделано.
- Подсказка под нагрузкой: на машине с 4 ядрами Typesense, PostgreSQL, портал и генератор нагрузки делят процессор, и результат прыгает в разы между прогонами. Вывод о подсказке при 50 запросах в секунду этим замером не сделан: нужен замер на сервере 16 ГБ. До него на production `SEARCH_PROVIDER=postgres` (ответ владельца 0070).

## Что не сделано и почему

- Векторы в Typesense для похожих идей (цель 150 мс): решение плана "после замера"; нужен отдельный план.
- Подсказка при 50 запросах в секунду: машина разработчика не выдаёт 50 в секунду и на пути PostgreSQL; нужен замер на сервере 16 ГБ.
- Правки к `docs/TZ.md` не вносились (правило: ТЗ не трогать); перечень в `docs/TZ-1.2-changes.md`.
- GitHub Actions на ветке не проверялся: пуша не было. Тесты сами скачивают образ `typesense/typesense:30.2` по digest с Docker Hub.
- Узбекские примеры набора языков: черновик исполнителя, нужен носитель языка.
- Независимая проверка ветки другим исполнителем не проводилась; проверка по разделу "На что смотреть" сделана тестами (изоляция, ключи, состав индекса, откат, синхронизация, кеш и журналы).
