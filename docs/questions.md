## 1. Разработчикам Smartup

**Тема:** Smartup Hub - что нужно от команды Smartup для входа клиентов и виджета

Коллеги, мы строим Smartup Hub - портал клиентов на hub.smartup24.com. Он заменит Jira Service Desk. Клиенты будут входить в портал через свою учётную запись Smartup, а из Smartup Web и мобильного приложения откроется виджет "Сообщить о проблеме".

Нужны ответы на восемь вопросов. Первые три нужны раньше всего: без них не начнётся настоящий вход клиентов.

1. **Параметры OAuth (вопрос 3).**
   - адреса авторизации, токена и сведений о пользователе;
   - есть ли документ discovery (`/.well-known/openid-configuration`) и `id_token`;
   - поддерживается ли PKCE;
   - какие области доступа запрашивать.

   Портал нужно зарегистрировать как клиента OAuth на общем облаке и на одном выделенном сервере. Адрес возврата пришлём.
2. **Сведения о пользователе.** Что сервер отдаёт о вошедшем пользователе: постоянный идентификатор, имя, email, идентификатор и название компании, ИНН, роль, язык. Чего из этого нет?
3. **Компания и организация (вопрос 43).** В Smartup Web при входе есть выбор компании, а в шапке переключатель организаций (например, GWS Tashkent, Демо Самарканд, Демо Фергана). Что именно придёт в поле `company_id` при входе через OAuth и в токене виджета: компания или организация из переключателя? Должны ли сотрудники разных организаций одной компании видеть обращения друг друга? Если человек переключил организацию в Smartup, меняется ли `company_id` в следующем токене?
4. **Телефон пользователя.** У большинства пользователей нет email, поэтому уведомления портала пойдут в Telegram через отдельного бота портала. Отдаёт ли OAuth номер телефона пользователя?
5. **Токен виджета (вопрос 17).** Виджету нужен короткий подписанный токен с пользователем и компанией. Как вам удобнее подписывать:
   - закрытым ключом с публикацией открытых ключей (JWKS);
   - или общим секретом.
6. **Коды модулей и экранов (вопрос 9).** Есть ли у модулей и экранов Smartup стабильные коды? Можно ли выгрузить их справочник с названиями?
7. **Приложение (вопрос 44).** В переключателе есть приложения SFA, Биллинг, Аналитика, Финансы, Procurement, Verifix, WMS. Уникальны ли коды модулей и экранов между приложениями? Можете ли вы передавать код приложения в подсказках виджета рядом с кодом модуля?
8. **API таск-менеджера.** Описание методов:
   - создать задачу;
   - получить статус;
   - вебхук о смене статуса с подписью.

   Нужно к передаче обращений в разработку.

Полный список задач для команды Smartup - раздел 17 ТЗ, могу прислать.

**Дополнение после вехи M1: регистрация портала как клиента OAuth** (уточнено 21.11.2026 после проверки портала). Портал готов к настоящему входу. Для регистрации на общем облаке и на выделенном сервере:

- Адрес возврата: `https://hub.smartup24.com/api/auth/sso/callback/<код сервера>`. Код сервера мы назначаем сами и сообщим вместе с заявкой (например, `cloud` для общего облака). На staging адрес тот же с узлом staging.
- Поток: authorization code с PKCE, метод `S256`. Портал всегда отправляет `code_challenge`.
- Области доступа: `openid profile email`.
- **`id_token` обязателен.** Без него вход не состоится. Токен подписан ключом сервера, открытые ключи опубликованы в JWKS. Портал проверяет подпись, `iss` (адрес сервера входа), `aud` (наш идентификатор клиента) и срок.
- Сведения о пользователе портал берёт из `id_token`. Если у сервера есть адрес сведений о пользователе (userinfo), портал читает их оттуда, и `sub` там должен совпадать с `sub` в `id_token`. Адрес userinfo не обязателен.
- Поля сведений:

  | Поле | Тип | Обязательно | Для чего |
  |---|---|---|---|
  | `sub` | строка | да | Постоянный идентификатор пользователя на этом сервере. Не меняется при смене имени, email или компании |
  | `name` | строка | да | Имя в портале. Длиннее 200 знаков обрезается |
  | `company_id` | строка или число | да | Идентификатор компании (см. вопрос 3 выше). Без него человек входит, но организации в портале не получает |
  | `company_name` | строка | да | Название организации в портале. Длиннее 300 знаков обрезается |
  | `role` | строка | нет | Роль в Smartup: по ней портал назначает роль в портале (например, `director`) |
  | `inn` | строка или число | нет | ИНН компании |
  | `locale` | строка | нет | Язык пользователя: `ru`, `uz` или `en` (подходит и `uz-UZ`) |
  | `email` | строка | нет | Адрес пользователя. У большинства пользователей его нет, портал работает и без него. Адрес из Smartup не даёт входа по ссылке, пока человек не подтвердит его сам |

  Неверное необязательное поле портал отбрасывает и вход не ломает.
- Сообщите, пожалуйста, есть ли документ discovery (`/.well-known/openid-configuration`) с `code_challenge_methods_supported`, содержащим `S256`. Если документа нет, пришлите три адреса: авторизации, токена и ключей (JWKS), и, если есть, адрес сведений о пользователе.
- В ответ нам нужны идентификатор клиента и секрет клиента. Секрет передайте, пожалуйста, не письмом, а по защищённому каналу.

**Дополнение 26.11.2026: вход заново** (проверка подготовки M9, ASVS 7.5). Перед сменой адреса для входа и завершением сессий портал просит клиента войти заново и шлёт в запросе авторизации `prompt=login` и `max_age=0`. Вопросы:

- Выполняет ли сервер входа Smartup `prompt=login`: показывает ли форму входа, даже если человек уже вошёл в Smartup Web в этом браузере?
- Выполняет ли он `max_age=0`?
- Есть ли в `id_token` поле `auth_time` (время, когда человек ввёл пароль)? Без него портал не может проверить, что вход был заново, и пропускает такой вход, записав событие `auth.reauth_unverified` в журнал.

**Короткая версия для мессенджера** (подготовлена 23.11.2026, готова к вставке; остальные вопросы раздела отдельным письмом):

## 2. Юристу

**Тема:** Smartup Hub - пять вопросов по персональным данным и AI

Добрый день. Smartup запускает портал поддержки клиентов Smartup Hub. Клиенты (компании) и их сотрудники пишут в нём обращения, а AI-помощник отвечает первым. В договорах с клиентами есть согласие на полную обработку персональных данных.

Прошу оценить по законодательству Узбекистана:

1. **AI-помощник (вопрос 13).** Текст каждого обращения отправляется во внешний AI-сервис Anthropic (Claude, серверы вне Узбекистана), чтобы найти решение и ответить. Имена и контакты мы не отправляем, но в тексте обращения клиент может их написать сам. Покрывает ли это действующее согласие? Нужно ли дополнить договор или политику? Есть ли требование хранить такие данные на территории Узбекистана?
2. **Внутренний AI-сотрудник (вопрос 40).** Обезличенные обращения обрабатываются через Anthropic и OpenAI для внутренних сводок поддержки. Клиенты этих сводок не видят. Какие условия нужны?
3. **Сроки хранения (вопрос 39).** Предлагаем:
   - обращения и переписку хранить, пока действует договор, и 3 года после;
   - вложения хранить 1 год после закрытия обращения.

   Соответствует ли это закону о персональных данных и требованиям к хранению документов?
4. **Запись звонков (вопрос 32).** Можно ли записывать звонки в поддержку и расшифровывать их и голосовые сообщения из Telegram внешним сервисом? Нужно ли предупреждение в начале звонка, отдельное согласие? Считается ли голос биометрическими данными?
5. **Telegram-группы (вопрос 30).** Бот поддержки состоит в группах проектов с клиентами. Обычно он видит только команды и обращённые к нему сообщения. Можно ли включить режим, в котором бот читает все сообщения группы, чтобы предлагать создать обращение? Сохраняем только сообщения, ставшие обращениями. Достаточно ли закреплённого в группе уведомления?

Для пилота мы возьмём у пилотных клиентов письменное согласие на AI-обработку. Ответ по вопросу 1 нужен до перехода остальных клиентов на портал.

## 3. Поддержке OnlinePBX

**Тема:** Интеграция с порталом поддержки: два вопроса по API

Здравствуйте. Мы подключаем OnlinePBX к своему порталу поддержки через вебхуки: начался звонок, ответили, пропущенный, завершился. Уточните, пожалуйста:

1. Можно ли через API запустить звонок с внутреннего номера сотрудника на номер клиента, чтобы АТС сначала позвонила сотруднику, затем клиенту? Какой метод и параметры?
2. Ссылка на запись `download_url` в событии `call-end`:
   - сколько времени она действует;
   - нужна ли для неё авторизация;
   - можно ли получить свежую ссылку на запись по `uuid` звонка позже?

Дополнительно: подписываются ли запросы вебхуков, или защита только через секрет в адресе?

Спасибо.
