# Если что-то случилось: действия при инциденте безопасности

ТЗ 14.7. Короткая инструкция для дежурного и администратора. Один раз проигрывается на staging до первого клиента.

Ниже `hubc` означает `docker compose -f /opt/smartup-hub/compose.prod.yaml`, `hub` означает `hubc exec web node hub.mjs`.

## 1. Первые 15 минут

1. Записать время, что замечено и кем. Ничего не удалять: журналы и база нужны для разбора.
2. Сообщить владельцу продукта и техническому руководителю.
3. Остановить развитие инцидента подходящим действием из раздела 2.
4. Сохранить журналы: `hubc logs --since 24h > /root/incident-$(date +%F).log`, выгрузить журнал аудита из рабочего места ("Настройки", "Журнал аудита").

## 2. Как остановить

| Что нужно | Как |
|---|---|
| Закрыть портал для всех | `hubc stop web`. Письма и вебхуки при этом не теряются: почтовый сервис и Telegram повторят доставку |
| Отозвать все сессии (клиентов и сотрудников) | `hubc exec -T postgres psql -U postgres -d hub -c 'delete from auth."session"'`. Все входят заново |
| Отозвать сессии одного человека | Рабочее место: "Настройки", "Сотрудники", сброс доступа; или `hub staff:reset --email <адрес>` |
| Отключить вход через один сервер Smartup | Рабочее место: "Настройки", "Серверы Smartup", "Отключить"; или `hub server:disable --code <код>`. Клиенты этого сервера не входят, их данные остаются |
| Отключить вход из бота и уведомления в Telegram | Убрать `TELEGRAM_BOT_TOKEN` из `.env`, затем `hubc up -d web worker`. В @BotFather отозвать токен (`/revoke`) |
| Остановить приём писем | В кабинете Resend отключить вебхук приёма. Письма останутся у Resend |
| Заблокировать адрес или страну | Правило в Cloudflare WAF |

## 3. Смена секретов

Каждый секрет меняется в `.env` на сервере, затем `hubc up -d web worker`. Новое значение сохранить в менеджере паролей.

| Секрет | Что происходит при смене | Порядок |
|---|---|---|
| `BETTER_AUTH_SECRET` | Все сессии перестают действовать. Сотрудникам, возможно, придётся заново подключить второй фактор: проверить на staging | Новое значение `openssl rand -hex 32` |
| `ENCRYPTION_KEY` | Сохранённые секреты серверов Smartup и токен бота дежурных перестают расшифровываться: серверы пропускаются при входе | После смены заново ввести секрет клиента каждого сервера ("Настройки", "Серверы Smartup") и токен бота дежурных. Команда перешифрования появится в волне 1 плана аудита (находка S6) |
| `REPLY_HMAC_SECRET` | Ответы на уже отправленные письма перестают попадать в обращения по адресу ответа; работают цепочка писем и номер в теме | Новое значение, предупредить поддержку |
| Пароли ролей базы (`DATABASE_URL_*`) | Нет простоя, если менять по одному | `alter role <роль> password '<новый>'` под суперпользователем, затем адрес в `.env` или `.env.migrate`, перезапуск |
| `RESEND_API_KEY`, `RESEND_WEBHOOK_SECRET` | Письма не уходят и не принимаются до перезапуска с новым значением | Новые значения в кабинете Resend |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` | Бот молчит до перезапуска | `/revoke` в @BotFather, новый секрет вебхука `openssl rand -hex 32`, затем `hub telegram:set-webhook` |
| Ключи R2 | Загрузка и скачивание файлов не работают до перезапуска | Новый ключ в Cloudflare, старый удалить |
| `TURNSTILE_SECRET` | Проверка "не робот" недоступна до перезапуска, действуют пределы частоты | Новый ключ в Cloudflare |
| Секрет клиента OAuth сервера Smartup | Вход через этот сервер не работает до ввода нового | Запросить у разработчиков Smartup, ввести в "Серверы Smartup" |
| Ключ `age` резервных копий | Старые копии читаются старым ключом | Новая пара `age-keygen`, открытый ключ в `backup.env`; старый закрытый ключ хранить, пока живы старые копии |

## 4. Кого уведомить

| Кого | Срок | Кто уведомляет |
|---|---|---|
| Владелец продукта | сразу | дежурный |
| Клиенты, чьи данные затронуты | по решению владельца и юриста; срок по закону о персональных данных уточняет юрист (вопрос 39 раздела 20 ТЗ) | владелец |
| Разработчики Smartup | сразу, если затронут вход через Smartup или секрет клиента OAuth | технический руководитель |
| Resend, Cloudflare, Hetzner | если инцидент на их стороне или утёк их ключ | администратор |

## 5. После инцидента

- Разбор без поиска виноватых в течение 5 рабочих дней: что случилось, как заметили, что остановило, что меняем.
- Запись решения в `docs/decisions/`, тест на найденную ошибку, правка этой инструкции.
