# Staging после вехи M1: памятка

Что настроить и проверить, когда портал впервые разворачивается на staging. Решения: 0013, 0015, 0016, 0018, 0019.

## 1. Переменные окружения

Портал (служба `hub`):

| Переменная | Значение | Примечание |
|---|---|---|
| `NODE_ENV` | `production` | |
| `HUB_URL` | `https://<адрес staging>` | От него строятся ссылки в письмах, адрес возврата для Smartup и вебхук бота |
| `HUB_DOMAIN` | узел из `HUB_URL` | С ним сверяется проверка "не робот" |
| `DATABASE_URL_APP` | подключение роли `hub_app` | |
| `DATABASE_URL_AUTH` | подключение роли `hub_auth` | |
| `BETTER_AUTH_SECRET` | случайная строка от 32 знаков | Секрет |
| `ENCRYPTION_KEY` | ключ шифрования секретов серверов Smartup | Секрет. Смена ключа делает секреты серверов нечитаемыми: их задают заново |
| `MAIL_TRANSPORT` | `resend` | `console` и `file` только на localhost |
| `RESEND_API_KEY` | ключ Resend | Секрет |
| `MAIL_FROM` | `Smartup Hub <hub@домен>` | Домен проверен в Resend |
| `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET` | ключи Cloudflare Turnstile для домена staging | Задаются парой. Без них проверка "не робот" выключена |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` | токен бота от BotFather и случайная строка от 32 знаков | Задаются парой. Без них бот выключен |
| `TELEGRAM_API_URL` | не задавать | Другой адрес допускается только на localhost |
| `CLIENT_IP_HEADER` | `cf-connecting-ip` | Обязателен в production. Откуда брать адрес посетителя для счётчиков и журнала (решение 0020). Сетевой экран пропускает на 443 только адреса Cloudflare, иначе заголовок можно подделать |
| `LOG_LEVEL` | `info` | |

База (служба `postgres`): пароли ролей `hub_owner`, `hub_app`, `hub_auth`. Миграции: `pnpm db:migrate` от роли владельца.

## 2. Команды hub по порядку

1. Первый администратор: `hub staff:create --email <адрес> --name <имя> --role admin`. Ссылку из вывода передать лично: по ней задаётся пароль и подключается второй фактор.
2. Серверы Smartup. Секрет клиента OAuth передаётся переменной `HUB_OAUTH_CLIENT_SECRET` или вводится по запросу команды, в аргументах он не принимается:
   - общее облако: `hub server:add --code <код> --name <название> --base-url <адрес Smartup Web> --issuer <адрес сервера входа> --client-id <идентификатор> --default --role-map '{"director":"client_admin"}'`;
   - выделенный сервер: та же команда без `--default`.
   Команда печатает адрес возврата для регистрации портала в Smartup. Дальше серверы можно вести в рабочем месте: "Настройки", "Серверы Smartup".
3. Проверка связи с каждым сервером: `hub server:check --code <код>` (или кнопка "Проверить связь" на карточке сервера).
4. Вебхук бота: `hub telegram:set-webhook`, затем `hub telegram:info` (бот включён, имя бота).
5. Остальных сотрудников приглашает администратор в рабочем месте: "Настройки", "Сотрудники".

## 3. Как проверить каждый способ входа

| Способ | Как проверить |
|---|---|
| Через Smartup, общее облако | `/ru/login`, кнопка "Войти через Smartup", вход учётной записью Smartup. Первый вход ведёт на шаг с email; организация создаётся сама |
| Через Smartup, выделенный сервер | `/ru/login`, "У нас свой сервер Smartup", ввести адрес Smartup Web. Кнопка входа показывает узел сервера |
| По ссылке на email | В профиле указать и подтвердить адрес (письмо через Resend). Выйти, на `/ru/login` запросить ссылку, открыть письмо, нажать "Войти" |
| Из бота Telegram | В профиле "Привязать Telegram", в боте `/start`. Выйти, в боте `/login` или кнопка "Войти", открыть ссылку, нажать "Войти" |
| Сотрудник | `/ru/staff/login`: пароль, затем код из приложения. Действия администратора просят вход не старше 15 минут |
| Проверка "не робот" | На формах без входа виден виджет Turnstile; запрос без прохождения проверки не отправляет письмо |

Что смотреть после каждой проверки: запись в журнале аудита ("Настройки", "Журнал аудита"), отсутствие секретов и ссылок в журналах сервера.

## 4. Что известно заранее

- Документация Resend и Telegram из среды сборки была недоступна: поля запросов взяты из известного описания API (решение 0018). Первое письмо и первую привязку Telegram проверить вручную.
- Посетитель, у которого заблокирован `challenges.cloudflare.com`, не пройдёт проверку "не робот" (решение 0018).
- Политика обработки данных выключена, пока в `content/legal/` нет утверждённых текстов (решение 0017).
