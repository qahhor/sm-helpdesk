# Проверки ASVS для вех M0, M1, M2, M3 и M4

> Устарел. Полный чек-лист ASVS 5.0.0 уровня 2 по номерам требований: `docs/security/asvs.md` (подготовка M9, 26.11.2026). Этот файл остаётся как история вех M0-M4: в нём CSP ещё в режиме отчётов.

Дата: 22.11.2026. Основание: раздел 15 ТЗ (приёмка по OWASP ASVS 5.0, уровень 2) и пункт C8 плана `docs/plans/M1-hardening.md`. Полный чек-лист проходится в M9. Здесь то, что уже построено во входе и личности, по главам стандарта, с тестом или файлом, который это подтверждает. Номера отдельных требований сверяются с текстом стандарта при приёмке M9.

Состояние: "есть" значит сделано и проверяется тестом; "частично" значит сделана часть, остальное в названной вехе; "M9" значит ещё не начато.

## Известные отклонения

- Посетитель с заблокированным `challenges.cloudflare.com` не пройдёт проверку "не робот" на формах без входа (решение 0018).
- Строки с хешами одноразовых ссылок удаляет ночная задача M2 (решение 0023, дополнение M2).
- Тесты протокола ClamAV идут против ложного сервера; с настоящим ClamAV вложения проверяются на staging (памятка, шаг 5a).
- CSP до M9 работает в режиме отчётов (решение 0010).
- Ответы сотрудников не ограничены по частоте: сессия сотрудника со вторым фактором, пределы раздела 14.5 заданы для клиентов (решение 0031, пункт 8; журнал M3).
- Отправитель письма не опознаётся, пока на сервере не задан `INBOUND_AUTHSERV_ID`: все письма идут в "Неопознанные" (решение 0035, памятка запуска, шаг 11).
- Вложения писем от неопознанного отправителя, пришедшие ответом на чужое обращение, не скачиваются: такое письмо сохраняется заметкой "Письмо на проверке" только с текстом (решение 0035, пункт 5).
