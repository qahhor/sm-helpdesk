# Протокол проверки удобства на пяти людях

Основание: ТЗ 8.10 (проверка на людях), 15.5 (условия выхода в пилот), план `docs/plans/M9-prep.md`, задача 9, решение 12. Проверка идёт до подключения первого пилотного клиента; найденные проблемы исправляются до него.

## 1. Участники

| № | Кто | Устройство и язык | Задания |
|---|---|---|---|
| К1 | Сотрудник клиента, работает в Smartup каждый день | Ноутбук, русский | 1-4 |
| К2 | Бухгалтер или администратор клиента | Ноутбук, русский | 1-4 |
| К3 | Сотрудник клиента | Телефон, узбекский (латиница) | 1-4 |
| А1 | Агент первой линии | Ноутбук, русский | 5-6 |
| А2 | Агент второй линии или Customer Care | Ноутбук, русский | 5-6 |

Участники не видели портал раньше и не читали инструкций `docs/guides`. Агенты получают приглашение и подключают второй фактор до сессии: это не часть заданий.

## 2. Подготовка staging

Проверка идёт только на staging и только на тестовой организации (решение 12). Данных настоящих клиентов на staging нет.

- [ ] Staging развёрнут по `docs/runbooks/launch.md`, `/api/ready` и `/api/ready/worker` отвечают 200.
- [ ] Начальные данные: `hub seed:pilot` с файлом пилота (модули, шаблоны, памятки), хотя бы три опубликованных решения для клиентов, одно из них про ошибку из задания 1 (чтобы подсказка что-то нашла).
- [ ] Тестовая организация "Тест Пилот" на ложном или тестовом сервере Smartup; учётные записи К1-К3 в ней. У К1 два обращения прошлой недели: одно "Ждём вашего ответа", одно "Решено".
- [ ] На доске идей пять опубликованных идей, у одной уже есть голоса.
- [ ] Для агентов: в очереди "Новые" шесть обращений тестовой организации, у двух подходит шаблон ответа; одно обращение заранее в работе у А1, по нему есть решение, которое стоит опубликовать (задание 6).
- [ ] Снимок экрана для задания 1 лежит на рабочем столе ноутбука и в галерее телефона.
- [ ] Перед каждой сессией состояние сброшено: черновики браузера очищены (выход из портала), обращения и идеи прошлой сессии удалены или помечены.

## 3. Согласие на запись

Перед сессией участник читает и подписывает строку: "Я согласен(на), что наблюдатель записывает время и ход выполнения заданий. Запись экрана: да / нет". Запись экрана делается только с письменного согласия. В протокол пишутся время, остановки, ошибки и нажатия, без имён: участник обозначается кодом (К1-К3, А1-А2). Запись экрана хранится до разбора результатов, затем удаляется.

## 4. Как вести сессию

- Наблюдатель один, сидит сбоку и не подсказывает. На вопрос участника отвечает: "Как бы вы поступили сами?" Вопрос записывается как остановка.
- Задание читается вслух одной фразой из столбца "Что сказать" и выдаётся карточкой. Время идёт с конца фразы до признака конца задания.
- Если участник не справился за тройную цель по времени, задание останавливается и записывается как невыполненное.
- После каждого задания два вопроса (раздел 6), в конце сессии общие вопросы.
- Сессия клиента около 25 минут, агента около 30 минут.

## 5. Задания

| № | Кто | Что сказать | Начало | Конец | Цель (ТЗ 8.10) |
|---|---|---|---|---|---|
| 1 | Клиент | "При проведении документа Smartup показал ошибку. Сообщите о ней в поддержку и приложите снимок экрана." | Открыта главная кабинета, участник вошёл | На экране номер нового обращения, снимок приложен | Не дольше 60 секунд |
| 2 | Клиент | "Узнайте, что сейчас происходит с вашим обращением прошлой недели про склад." | Открыта главная кабинета | Участник вслух называет статус и чей ход | Не дольше 20 секунд |
| 3 | Клиент | "Опишите проблему с печатью. Если портал предложит решение и оно не поможет, передайте вопрос сотруднику." | Открыта форма нового обращения | Обращение отправлено после предложенного решения | С первой попытки |
| 4 | Клиент | "Предложите идею, как улучшить отчёт по продажам, и проголосуйте за чужую идею, которая вам нравится." | Открыта главная кабинета | Идея отправлена на проверку, голос стоит | Без вопросов наблюдателю |

| 6 | Агент | "Закройте обращение, по которому вы нашли решение, и опубликуйте решение для клиентов." | Открыто обращение в работе у участника | Обращение закрыто, решение опубликовано | Не дольше 5 минут |

Задание 3 до вехи M5b (AI первой линии) идёт на подсказке решений: "ответ AI" из ТЗ 8.10 заменён предложенным решением и кнопкой "Не помогло, отправить обращение". Когда AI-помощник появится, задание повторяется на нём, протокол меняется в той же ветке.

## 6. Вопросы

После каждого задания:

1. "Насколько легко было выполнить задание: от 1 (очень трудно) до 5 (очень легко)?"
2. "Было ли место, где вы не знали, что делать дальше? Где?"

В конце сессии:

1. "Что было самым непонятным?"
2. "Какое слово или кнопка показались странными?"
3. Клиентам: "Стали бы вы сообщать о проблеме здесь, а не по телефону? Почему?"
4. К3: "Всё ли понятно по-узбекски? Какие слова звучат неестественно?"
5. Агентам: "Чего не хватает, чтобы отвечать быстрее?"

## 7. Бланк наблюдателя

Один бланк на участника. Распечатать по числу участников.

Участник: ____ Устройство: ____ Язык: ____ Дата: __.__.____ Запись экрана: да / нет

| Задание | Время, с | Выполнено (да / нет / с помощью) | Остановки: где и сколько секунд | Ошибки: что нажал не то | Нажатия мышью (задание 5: на каждое обращение) | Оценка 1-5 | Что сказал |
|---|---|---|---|---|---|---|---|
| 1 | | | | | | | |
| 2 | | | | | | | |
| 3 | | | | | | | |
| 4 | | | | | | | |
| 5 | | | | | 1-е: __ 2-е: __ 3-е: __ | | |
| 6 | | | | | | | |

Остановка: участник больше 5 секунд не действует, ищет глазами, спрашивает или возвращается назад. Ошибка: нажатие, которое не ведёт к цели (не та кнопка, не тот раздел).

## 8. Что измеряется и когда задание пройдено

| Мера | Как | Пройдено |
|---|---|---|
| Время | Секундомер наблюдателя, от фразы до признака конца | Не больше цели задания |
| Успех | Задание выполнено без подсказки | У каждого участника своей группы |
| Остановки и ошибки | Бланк | Ни одной остановки дольше 15 секунд на одном месте у двух и больше участников |
| Нажатия мышью (задание 5) | Бланк, по каждому обращению | Не больше двух на обращение у обоих агентов |
| Вопросы наблюдателю (задание 4) | Бланк | Ноль |
| Оценка | Ответ на вопрос 1 | Не ниже 4 в среднем по заданию |

Проверка пройдена, когда все шесть заданий пройдены у каждого участника своей группы. Задание, не прошедшее у одного участника, разбирается: если причина в интерфейсе (а не в подготовке staging), это находка.

## 9. Как находка становится задачей

1. В тот же день наблюдатель переносит каждую остановку и ошибку в таблицу находок: задание, участник, где, что произошло, сколько участников столкнулись.
2. Находка, которая помешала выполнить задание или встретилась у двух и больше участников, становится задачей до пилота с меткой "удобство"; остальные идут в список этапа 2.
3. Исправление проверяется повтором того же задания на одном новом человеке.
4. Итог пишется в отчёт вехи M9: числа по заданиям, находки и что с ними сделано. Имён в отчёте нет.
