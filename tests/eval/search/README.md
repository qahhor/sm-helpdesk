# Проверочный набор поиска решений (ТЗ 15.4)

Набор для `pnpm eval:search` (план M5, задача 11). Команда поднимает базу в контейнере (testcontainers, как
интеграционные тесты), публикует решения из `solutions.json`, строит индекс, прогоняет каждый запрос из
`queries.json` настоящей функцией поиска подсказки (`searchSolutions`, от имени клиента, аудитория `clients`) и
печатает долю правильного решения в первых трёх по каждому языку и долю ложных показов рядом с порогами 15.4:
русский не ниже 80%, узбекский не ниже 65%, ложные показы не выше 10%. У английского порога в ТЗ нет, доля
печатается для сведения.

**Сейчас здесь 9 придуманных запросов и 8 придуманных решений** (по три запроса на язык, по одному без решения).
Они проверяют только, что команда работает от начала до конца. Настоящий набор (90 запросов, по 30 на русском,
узбекском и английском, и около 30 решений) присылает владелец; цифры замера считаются только на нём и с настоящими
векторами (TEI с BGE-M3). На заглушке векторов (`EMBEDDINGS=stub`, по умолчанию) смысловой поиск ненастоящий.

## Файлы

`solutions.json`: массив решений, по которым ищется.

| Поле | Что |
|---|---|
| `ref` | Короткое имя решения, на него ссылаются запросы. Уникально |
| `locale` | `ru`, `uz` или `en`: язык текста решения |
| `title` | Заголовок |
| `what` | Абзац "что видит пользователь" |
| `steps` | Шаги решения, массив строк (не меньше одного) |

`queries.json`: массив запросов.

| Поле | Что |
|---|---|
| `id` | Имя запроса для отчёта, уникально |
| `locale` | Язык запроса и языковая цепочка поиска (FR-SOL-10) |
| `query` | Текст, как его написал бы клиент в форме обращения |
| `expected` | `ref` правильного решения или `null`, если решения в наборе нет |

## Как считается

- **Правильное в первых трёх:** у запроса с `expected` решение с этим `ref` есть среди показанных (подсказка
  показывает не больше трёх). Доля по каждому языку.
- **Ложный показ:** у запроса с `expected: null` подсказка показала хоть одно решение. Доля среди всех запросов без
  решения.
- Запрос с `expected`, по которому показано только чужое решение, в отчёте помечен "чужое": это промах.

## Запуск

```
pnpm eval:search                      # этот каталог, векторы по EMBEDDINGS (по умолчанию заглушка)
EVAL_SEARCH_DIR=/путь/к/набору pnpm eval:search
EVAL_STRICT=1 pnpm eval:search        # код завершения 1, если порог 15.4 не пройден
EMBEDDINGS=tei EMBEDDINGS_URL=http://tei pnpm eval:search   # настоящие векторы
```

Нужен Docker (контейнер PostgreSQL с pgvector, образ из `PG_IMAGE`). Запрос и решения в журнал и в сеть не уходят.
